# Архитектура Flit

Документ описывает устройство этапа 1. Пользовательская сторона — в [README.md](README.md), подробные проектные записки — в [docs/design/external-open.md](docs/design/external-open.md) и [docs/design/wsl.md](docs/design/wsl.md), замеры — в [docs/metrics.md](docs/metrics.md).

Три принципа, из которых следует остальное:

1. **Ядро без ввода-вывода.** Вся логика интерфейса — состояние вкладок, выделение, навигация, раскладка, построение списка примитивов для GPU — живёт в `flit-core` и не делает системных вызовов. Ядро общается с внешним миром через очередь эффектов (`Effect`) и входящие события, поэтому целиком тестируется без окна и без диска.
2. **UI-поток не ждёт.** Чтение папок, слежение за изменениями, значки, названия типов, открытие файлов, файловые операции и фоновая сортировка выполняются в рабочих потоках; результаты приходят через каналы и будят цикл сообщений.
3. **Кадр только по изменению.** Пока ничего не меняется, процесс спит в `WaitMessage`; кадр строится, когда изменилось состояние или идёт анимация, и выводится с синхронизацией по кадровому ожиданию swap chain.

## Крейты и правило зависимостей

| Крейт | Назначение | Внутренние зависимости |
|---|---|---|
| `flit-core` | имена, пути, `Location`, листинги, сортировка, `Open` и маршрутизация, вкладки и `App`, раскладка, текстовый кэш, атлас, `DrawList` | — |
| `flit-proto` | транспорт (кадры, `Hello`), протоколы единственного экземпляра и агента-провайдера, общий `EntryBatch` | `flit-core` |
| `flit-search` | индекс тома (`VolumeIndex`), разбор запросов, движок поиска, сессия и протокол поиска, снимки индекса | `flit-core`, `flit-proto` |
| `flit-platform` | трейты платформы (`Platform`, `WindowSystem`, `Renderer`, `Fs`, `Watcher`, `Shell`, `FileOps`, `SingleInstance`, `IndexSource`, `Service`, `Duplex`), ОС-независимый `LocalProvider`, провайдер WSL `WslProvider` поверх агента и драйвер индекса `start_indexer` | `flit-core`, `flit-proto`, `flit-search` |
| `flit-platform-windows` | реализация трейтов на Win32, D3D11 + DirectComposition, DirectWrite, NT API, Shell COM, именованных каналах | `flit-core`, `flit-proto`, `flit-search`, `flit-platform` |
| `flit-platform-linux` | весь крейт под `#![cfg(target_os = "linux")]`: `LinuxFs` (`statx`, `getdents64`, размеры папок), `Inotify`, корзина freedesktop `Trash`, сервер агента `agent::serve` и бинарник `flit-wsl-agent` (фича `agent`); окно, отрисовка и шрифты — заглушки | `flit-core`, `flit-proto`, `flit-search`, `flit-platform` |
| `flit` | приложение: обработчик окон, рабочие потоки, клиент поиска с запасным индексом, сохранение состояния, сценарий метрик | `flit-core`, `flit-platform`, `flit-proto`, `flit-search`, платформа по `cfg` |
| `flit-indexd` | служба индексации: канал `\\.\pipe\flit-indexd`, консольный режим, служба Windows | `flit-core`, `flit-platform`, `flit-proto`, `flit-search`, платформа по `cfg` |
| `tools/flit-gen` | генератор тестовых папок | только `std` |

Слои сверху вниз: бинарники (`flit`, `flit-indexd`) → платформа (`flit-platform-windows` или `flit-platform-linux`) → `flit-platform` → `flit-core` / `flit-search` / `flit-proto`.

**Правило:** `flit-core`, `flit-proto`, `flit-search` и `flit-platform` никогда не зависят от крейтов `windows*` — ни напрямую, ни транзитивно. Код ОС есть только в `flit-platform-windows` (весь крейт под `#![cfg(windows)]`) и `flit-platform-linux` (под `#![cfg(target_os = "linux")]`). Бинарники выбирают платформу одной строкой (`type P = flit_platform_windows::Windows` или `flit_platform_linux::Linux`), весь остальной код обобщён по `P: Platform`. CI проверяет правило задачей `deps-isolation`: для каждого из четырёх крейтов строится `cargo tree -p <крейт> -e normal,build --target all`, и сборка падает, если в дереве есть пакет, имя которого начинается с `windows`. Кроме того, Linux-задача CI собирает весь workspace и гоняет тесты ОС-независимых крейтов.

| `flit-indexd-client`, `flit-indexd-session` | по паре на клиента службы, не больше 16 клиентов | чтение запросов клиента; выполнение запросов и запись ответов |
| `flit-indexd-report` | 1, только с `--console` | печать состояния томов |

Внутри дистрибутива у агента `flit-wsl-agent` свои потоки: главный читает запросы и сам отвечает на `Stat`; `flit-agent-out` пишет все ответы через буфер 1 МиБ; `flit-agent-list`, `flit-agent-sizes` и `flit-agent-op` создаются на каждый листинг, `DirSizes` и операцию (размеры считает ещё и пул `std::thread::scope` по числу ядер); `flit-inotify` ждёт события inotify и склеивает их за 50 мс.

UI-поток не выполняет блокирующих операций с файлами и COM в обработке ввода и кадра: `Effect` превращается либо в отправку в канал, либо в дешёвый вызов Win32 (заголовок, курсор, буфер обмена). Исключения: разрешение `shell:`-путей (`Platform::known_folder`, COM) при обработке входящей команды `Open`; ожидание устройства D3D11 перед первым кадром, если `flit-gpu` ещё не создал ни одного, и пересоздание аппаратного устройства после его потери; чтение `state.bin` до создания окна и его запись при закрытии последнего окна; меню оболочки (строится при раскрытии подменю «Show more options», а с Shift или флагом `shell_items_inline` — до показа меню) и окно свойств, объект данных и модальный цикл `SHDoDragDrop` при перетаскивании из Flit, вызовы `IDropTarget` и запись описания броска в объект данных при перетаскивании в него (см. «Файловые операции»). Собственные пункты контекстного меню Flit строятся без оболочки.

Пробуждение: рабочий поток кладёт результат в канал `crossbeam` и вызывает `Wake` (`Arc<dyn Fn()>`). На Windows это `Win32Waker`: он отправляет `WM_WAKE` скрытому окну-концентратору (`HWND_MESSAGE`), а флаг `AtomicBool` схлопывает повторные пробуждения в одно сообщение. Концентратор вызывает `WindowHandler::woken` для каждого окна, и обработчик разбирает каналы.

## Загрузка папки

1. **`Tab::load(gen)`.** Вкладка получает новое поколение `gen` (счётчик `App`), записывает его в свой `GenToken`, сбрасывает очередь изменений, ошибку, хлебные крошки и статистику и выпускает два эффекта: `Effect::Provider(Watch { path })`, затем `Effect::Provider(List { gen, path, view, case, out, cancel })`. Здесь `out` — слот снимков вкладки, `cancel` — её `GenToken`. Если провайдер сменился (локальный ↔ WSL), старому уходит `Watch { path: None }`.
2. **Маршрутизация.** `Handler::flush` передаёт запрос провайдеру: `ProviderId::Local` — прямо в `LocalProvider`, `ProviderId::Wsl` — через `via_unc` (см. ниже). `Watch { path }` провайдер только запоминает за вкладкой; `List` того же поколения забирает его с собой в пул `flit-fs-N`. Рабочий поток сначала просит `flit-watch-ctl` поставить слежение и ждёт подтверждения, что запрос `ReadDirectoryChangesExW` уже выдан, и только потом читает каталог: изменение, случившееся во время чтения, не теряется. `Watch { path: None }` уходит в `flit-watch-ctl` сразу.
3. **Чтение.** `NtFs::read_dir` открывает каталог через `CreateFileW` (`FILE_LIST_DIRECTORY`, `FILE_FLAG_BACKUP_SEMANTICS`, путь с префиксом `\\?\`, поэтому длинные пути работают) и читает его `NtQueryDirectoryFile` с классом `FileIdBothDirectoryInformation` в буфер 64 КБ. Каждый заполненный буфер — одна порция: имена из UTF-16 сразу пишутся в `ListingBuilder`, который одновременно растит листинг и ключи сортировки. Для «This PC» вместо чтения каталога перечисляются диски (`GetLogicalDrives`, объём несъёмных дисков через `GetDiskFreeSpaceExW`).
4. **Публикация.** После каждой порции проверяется `GenToken`: если вкладка ушла на другое поколение, чтение прекращается. Первая порция публикуется сразу, следующие — не раньше чем через 16 мс и не раньше чем через учетверённое время предыдущей публикации: рабочий поток копирует листинг и ключи, сортирует их и публикует `DirSnapshot` в `SnapshotSlot` вкладки. Поскольку цена публикации растёт с листингом, на огромной папке промежуточных снимков становится меньше, и на копирование уходит не больше пятой части времени чтения. Перед каждой публикацией поколение проверяется снова. Слот — `ArcSwapOption<DirSnapshot>` без блокировок: новый снимок заменяет непрочитанный, но снимок старшего поколения никогда не вытесняется младшим, даже если поток прежнего задания опубликовал его позже. Финальный снимок (`done = true`, ошибка, общее время) публикуется всегда, если поколение ещё актуально. После публикации — `Wake`.
5. **Приём.** При пробуждении и в начале каждого кадра `App::poll` забирает снимки из слотов всех вкладок. `Tab::on_snapshot` отбрасывает чужое поколение, запоминает время первого и последнего снимка (они видны в строке состояния), подменяет снимок в `DirView` (выделение сохраняется: индексы растущего листинга стабильны), применяет отложенное выделение (`/select`, выход в родительскую папку) и, если за время загрузки сменилась сортировка, заказывает пересортировку.
6. **Кадр** рисует только видимый диапазон строк текущей вкладки.

### Поколения и отмена

`gen` уникален в пределах окна и всегда идёт в паре с идентификатором вкладки. `GenToken` — `Arc<AtomicU64>`, общий для вкладки и её заданий: рабочий поток спрашивает `is_current(gen)` между порциями и перед публикацией, закрытие вкладки записывает `u64::MAX`. На стороне UI устаревшие результаты отбрасываются по тем же меткам: снимок — по `gen`, события провайдера — по паре (вкладка, `gen`), результат сортировки — по тройке (вкладка, `gen`, вид).

### Слежение за изменениями

`DirWatcher` держит на каждую вкладку один дескриптор каталога, привязанный к общему IOCP, и запрос `ReadDirectoryChangesExW` с `ReadDirectoryNotifyExtendedInformation` в буфер 64 КБ. Расширенная информация уже содержит размер, времена и атрибуты, поэтому дополнительный запрос метаданных не нужен. Уведомления превращаются в `DirChange` (`Added`, `Removed`, `Modified`; переименование — `Removed` старого имени плюс `Added` нового) и уходят событием `ProviderEvent::Changes { tab, gen }`. Переполнение буфера (завершение с нулевой длиной) или ошибка дают `Rescan`, и вкладка полностью перечитывает папку с новым поколением, сохраняя фокус. Записи уведомлений разбираются из байтов по смещениям полей с проверкой границ, без приведения буфера к структуре; обрезанная или неизвестная запись отбрасывается. Если имя похоже на короткое имя 8.3 (`LONGFI~1.TXT`), поток слежения разворачивает его через `GetLongPathNameW`; для удалённого файла это невозможно, и тогда вся пачка превращается в `Rescan`. `watch(Some)` открывает каталог вне замка, а под замком привязывает его к IOCP и выдаёт первый запрос до возврата; запросы одной вкладки упорядочены по (поколение, снятие), поэтому опоздавшая постановка не перекрывает более новую команду. Смена папки отменяет старый запрос через `CancelIoEx`, дескриптор закрывается по его завершении. Слот (дескриптор, буфер и `OVERLAPPED`) живёт, пока его пакет не извлечён из порта: `ReadDirectoryChangesExW` выполняется как ввод-вывод, не привязанный к потоку, и ядро копирует уведомления в буфер и пишет `OVERLAPPED` в момент, когда `GetQueuedCompletionStatus` забирает пакет. Раньше `stop` закрывал слот сразу, если `CancelIoEx` отказывал (запрос уже завершён, пакет стоит в очереди), и ядро потом писало в освобождённую память: отсюда `STATUS_HEAP_CORRUPTION` и зависания при параллельном прогоне тестов `flit-platform-windows`. Теперь `stop` только помечает слот `closing` и вызывает `CancelIoEx`, а закрывает слот поток `flit-watcher`, когда пакет приходит; у каждого слота в `slots` ровно один невыполненный запрос. Вкладка корзины держит по запросу на каждый корень `$Recycle.Bin\<SID>` (`by_tab: TabId → [ключи]`, `watch_all`), и любое завершение у такого слота (`rescan`) даёт `Rescan` без разбора имён.

На стороне UI изменения копятся в очереди вкладки. `App::frame` применяет изменения к текущей вкладке только после окончания загрузки и не дольше 4 мс за кадр (часы проверяются раз в 256 изменений); если очередь не опустела, сразу заказывается следующий кадр. Изменения применяются пачкой: `DirView::apply_all` обновляет листинг и карту имён по каждому изменению, а порядок строк перестраивает один раз на пачку. Запись, ставшая невидимой (удалена или скрыта), выходит из выделения и теряет фокус, поэтому удаление в корзину никогда не захватит то, чего нет на экране. Фоновые вкладки хранят очередь до активации; если в ней набирается больше 65 536 изменений, очередь выбрасывается и вкладка перечитывает папку, как при `Rescan`, поэтому шумная папка в фоне не растит память без предела. `DirView::apply` идемпотентен: `Added` или `Modified` для существующего имени обновляет метаданные и переставляет строку, `Added` для нового имени дописывает запись в конец листинга и вставляет строку двоичным поиском, `Removed` ставит надгробие, `Removed` для отсутствующего имени ничего не делает. Поскольку слежение поставлено до начала чтения, события, гонящиеся с чтением, ждут финального снимка, а повторное применение уже учтённого изменения безвредно. UNC-шары часто не дают живых уведомлений, поэтому после успешной файловой операции такая вкладка перечитывается. Папки WSL тоже: изменения в них присылает агент через inotify, но операции, кроме корзины, идут через `\\wsl.localhost`, а в упрощённом режиме уведомлений нет вовсе.

### Фоновая пересортировка

Щелчок по заголовку, команды сортировки и группировки, Ctrl+H, переключатели имён с точкой и защищённых системных файлов или устаревший вид в финальном снимке порождают `Effect::Resort { snap, view }` с `Arc` на текущий снимок; переключатель пересортировывает только те вкладки, чей `ViewSpec` от него изменился. Поток `flit-sort` сортирует его и возвращает порядок вместе с длиной листинга на момент сортировки. `App::on_resorted` сверяет вкладку, поколение и вид, после чего `DirView::merge_order` выбрасывает надгробия и скрытые записи, вставляет записи, добавленные после начала сортировки, и проверяет упорядоченность; если за это время изменения сдвинули метаданные и порядок нарушен, выполняется полная сортировка на месте. До прихода результата на экране остаётся прежний порядок.

### Размеры подпапок

Ctrl+Shift+S отправляет `DirSizes` со списком видимых подпапок (без ссылок и дисков). Задания выполняет отдельный поток `flit-sizes`, он вызывает `Fs::dir_sizes`. Реализация по умолчанию обходит каждое поддерево через `Fs::read_dir`, для HDD (`IOCTL_STORAGE_QUERY_PROPERTY`, `IncursSeekPenalty`) последовательно, иначе параллельно через `rayon`. `NtFs` её переопределяет: весь запрос — один `rayon::scope` в собственном пуле `flit-sizes-N` (по числу логических ядер, на HDD — один поток, то есть подпапки по очереди), каждый каталог — отдельная задача. Каталог читается `NtQueryDirectoryFile` с `FileFullDirectoryInformation` в буфер потока, подкаталоги открываются `NtOpenFile` относительно дескриптора родителя (`OBJECT_ATTRIBUTES.RootDirectory`), хранятся только их имена, без `ListingBuilder`; точки повторной обработки-ссылки (junction, symlink) не обходятся, ошибки доступа дают 0. У каждого элемента свой счётчик байт и незавершённых каталогов; поток, обнуливший счётчик, сразу отправляет `ProviderEvent::DirSize`, поэтому долгий элемент не задерживает результаты остальных. Результат появляется в колонке «Размер», если на экране всё ещё снимок того же поколения; отмена — через тот же `GenToken`, он проверяется перед открытием каждого каталога и перед каждым чтением. Замеры `bench_dir_sizes` (тёплый кэш): `C:\Windows` (45,9 ГБ) — 1,55 с вместо 7,6–8,7, `C:\Program Files` — 68 мс вместо 160; сетевые пути тоже быстрее (`\\wsl.localhost\…\usr` — 0,97 с вместо 3,06). Узкое место — каталоги с десятками тысяч соседних подкаталогов (`WinSxS\Temp\InFlight`): NTFS сериализует открытия внутри одного родителя.

Флаг `ViewPrefs::auto_sizes` (выключен) запускает тот же запрос сам: `App::on_loaded` вызывает `compute_dir_sizes`, когда финальный снимок пришёл в текущую вкладку, а включение флага сразу считает текущую папку. Цена — та же, что у Ctrl+Shift+S (`bench_dir_sizes`, тёплый кэш: 400 папок с 10 000 файлов — 4,5 мс, `C:\Program Files` — 71 мс, `C:\Windows` — 1,5 с, с холодного кэша — 4,2 с); на скорость открытия папки обход не влияет, потому что идёт в своём пуле после финального снимка, а уход из папки отменяет его через `GenToken`.

## Модель данных

**Имена — WTF-8.** Имена из ОС хранятся байтами: UTF-16 переводится без потерь, непарные суррогаты кодируются трёхбайтовыми последовательностями, и обратное преобразование (`name::to_utf16`) восстанавливает исходные единицы UTF-16 точно. Корректный UTF-16 даёт корректный UTF-8, поэтому показ обычно идёт без копирования; замена на U+FFFD (`name::display`) применяется только при отображении. Имена Linux и WSL — произвольные байты.

**Листинг — один буфер имён и записи по 40 байт.** `Listing { names: Vec<u8>, entries: Vec<Entry> }`. `Entry` (`repr(C)`, 40 байт): размер, время изменения и создания (тики FILETIME), смещение имени в буфере, атрибуты, длина имени, длина расширения. Биты атрибутов: каталог, скрытый, системный, только чтение, ссылка (точка повторной обработки), диск, «размер известен», удалён. На запись нет отдельных выделений памяти.

**Стабильные индексы.** Записи только дописываются. Удаление ставит бит «удалён» (надгробие) и убирает строку из порядка, поэтому индекс записи не меняется за всё время жизни снимка. Выделение — битовая карта по индексам (`Vec<u64>`), фокус и якорь — индексы; всё это переживает сортировку и изменения.

**Снимок и вид.** `DirSnapshot`: поколение, путь, листинг, ключи сортировки, порядок (`Vec<u32>` — отсортированные индексы видимых записей), вид (`ViewSpec`: сортировка `SortSpec` — поле, направление и место папок `Folders::{First, Last, Mixed}`; группировка `GroupSpec` — поле, направление групп и единица даты; показ скрытых, защищённых системных и имён с точкой; смещение UTC для групп по дате), признак завершения, ошибка, время. `DirView` держит `Arc<DirSnapshot>` (изменения применяются через `Arc::make_mut`, копия делается только если снимок ещё кем-то используется), выделение, фокус, якорь, лениво строящийся хеш имя → индекс и раскладку групп.

**`FsPath`.** Нормализованные байты, длина корня и вид пути: `Computer` (виртуальный «This PC»), `Drive` (`C:\...`), `Unc` (`\\server\share\...`), `Verbatim` (`\\?\Volume{...}\...`), `Unix` (`/...`). При разборе `/` заменяется на `\` для путей Windows, `.` и `..` разрешаются лексически, `\\?\C:\` и `\\?\UNC\` сворачиваются в `Drive` и `Unc`. Путь с байтом NUL отвергается при разборе: Win32 обрезал бы его по NUL и адресовал бы другой файл. Относительный путь не является `FsPath`: его разрешает команда `Open` по `cwd`. `to_wide(true)` добавляет `\\?\` или `\\?\UNC\` для путей длиннее `MAX_PATH`. Родитель корня диска — «This PC».

**`Location`.** `Local(FsPath)` или `Wsl { distro, path }` с путём вида `Unix`; `provider()` даёт `ProviderId::Local` или `ProviderId::Wsl(distro)`. Каноническая байтовая форма — байты пути или `wsl://дистрибутив/путь`; при десериализации она проверяется, подделанный относительный путь отвергается. `Location::from_local` распознаёт `\\wsl.localhost\D\...` и `\\wsl$\D\...` и возвращает запрещённые в Windows символы из частной области U+F001–U+F07F; `to_windows` делает обратное (для имён не в UTF-8 — невозможно).

**Ключи естественной сортировки.** `SortKeys` строятся в том же проходе, что и листинг: общий буфер ключей, смещения и для каждого имени `u64` из первых 8 байт ключа. Кодирование (`encode_key`):

- ASCII-знаки препинания и управляющие — байт `0x02 + ранг`, ранги идут блоками по возрастанию кода (`0x00–0x2F`, `:;<=>?@`, `` [\]^_` ``, `{|}~`), то есть знаки раньше цифр и букв;
- серия цифр — байт `0x48`, длина значащей части (без ведущих нулей) и сами цифры, поэтому число сравнивается по величине;
- ASCII-буквы — `0x50 + номер буквы` без учёта регистра или `0x50 + 2·номер + заглавная` с учётом;
- остальные символы — UTF-8 строчной формы кодовой точки (первый байт не меньше `0xC2`), то есть после всех ASCII-букв в порядке кодовых точек.

Сравнение ключей как байтовых строк и есть естественный порядок; равные ключи разрешаются исходными байтами имени, затем индексом, так что порядок полный и детерминированный. `sort::sort` отбирает видимые записи, строит компактные элементы (группа «папка/файл», первичный ключ поля — размер, время со сдвигом знака или 8 байт расширения в нижнем регистре, затем два слова ключа имени) и сортирует их по целым числам; к полному компаратору обращается только при равенстве префиксов. Обратный порядок инвертирует целые ключи, а группа «папка/файл» от него не зависит: папки сверху, снизу или вперемешку задаёт `Folders`. Дата создания сортируется так же, как дата изменения. `insert_pos` и `find_row` — двоичный поиск тем же компаратором для изменений по одному.

### Группировка

Группа — непрерывный отрезок отсортированного порядка, поэтому группировка — это ещё один, старший ключ той же сортировки, а не отдельный проход. `sort::group_key` даёт для записи пару «`u64`, точный ли он»: первая буква имени (знаки — 1, цифры — 2, буквы — `0x100 +` строчная кодовая точка), корзина размера по границам Проводника (папки без посчитанного размера, пустые, 16 КБ, 1 МБ, 128 МБ, 1 ГБ, 4 ГБ), номер года, месяца или дня в местном времени (`fmt::local_days` со смещением UTC вида и `civil_from_days`), первые 8 байт расширения в нижнем регистре плюс один (у папок — 0) или первые 8 байт исходной папки в корзине. Ключ считается в том же проходе `sort::sort`, что и ключи сортировки, и стоит в компактном элементе первым (`gkey`, инвертируется направлением групп отдельно от направления сортировки); точный ключ (всё, кроме расширения или исходной папки длиннее 8 байт) не требует сравнения байтов, неточный дорешается `group_tail_cmp` по полному расширению или пути без учёта регистра, и только между записями с равным `gkey`. Полный компаратор `sort::cmp` — это `group_cmp`, затем прежнее сравнение элементов, поэтому вставка по одному, проверка порядка в `merge_order` и фильтр работают с группами без изменений.

Раскладку строит `DirView::regroup` после каждого изменения строк (снимок, изменения слежения, пересортировка, фильтр) прямо в UI-потоке: идёт по видимым строкам и находит конец каждой группы двоичным поиском (`partition_point` по равенству ключа), так что цена пропорциональна числу групп, а не строк: на 100 000 записях — сотые доли миллисекунды. `Group { first, start, line, count, collapsed, id }`: первая запись, первая строка, номер строки экрана с заголовком, число элементов, свёрнута ли, идентификатор (хеш ключа и байтов). Экран — последовательность строк двух видов: `DirView::line(n)` двоичным поиском по `line` даёт `Line::Header(g)` или `Line::Row(r)`, `line_of_row` и `row_at_line` переводят номера строк списка в номера строк экрана и обратно; отрисовка, прокрутка, попадание мышью, рамка и перемещение фокуса работают с номерами строк экрана, а выделение, быстрый переход и подсчёт — со строками списка, поэтому виртуализация сохранилась. Без свёрнутых групп список строк — это `snap.order` или строки фильтра без копии; если что-то свёрнуто, `shown` хранит видимые строки без строк свёрнутых групп, а `prune` убирает их из выделения и фокуса. Свёрнутые группы запоминаются в `DirView` по идентификатору и переживают снимки и пересортировку той же загрузки.

Подписи групп («A», «#», «0-9», «Tiny (under 16 KB)», «March 2024», «2024-03-15», «Unknown date», название типа как в колонке «Тип», исходная папка или «Unknown location») и глифы строит `App::group_label` по первой записи группы и только для видимых заголовков; число элементов стоит после подписи, шеврон показывает, свёрнута ли группа. Результаты поиска приходят страницами от службы, поэтому их группировка по папке — сортировка службой по папке и пометка начала каждой серии при отрисовке, без заголовков и подсчёта.

## Окна и вкладки

Процесс — одна оконная система с любым числом окон. `Handler` (`crates/flit/src/app.rs`) хранит для каждого окна `App`, `Gfx` (текст и атлас), `Renderer` и диапазон видимых строк для отсева запросов значков.

`App` — состояние одного окна: вкладки и текущая вкладка, настройки вида окна (`ViewPrefs`), общее хранилище видов папок (`FolderViews`), редактор адресной строки, наведение и перетаскивание, кэши значков и названий типов, очередь эффектов, раскладка.

`Tab` — независимая вкладка: идентификатор, история (`History`: стеки «назад» и «вперёд» из `Location`), поколение, `GenToken`, `SnapshotSlot`, провайдер, за которым следит, `ViewSpec`, вид раскладки (`LayoutMode`, пока только `Details`), набор и ширины колонок (`Columns`), признак отложенной подгонки колонок, состояние загрузки, `DirView`, ошибка, очередь изменений, хлебные крошки, статистика, прокрутка и её цель, буфер быстрого перехода. Новая вкладка наследует вид текущей, пока загрузка папки не подставит вид этой папки.

### Вид папки

`FolderView { layout, sort, group, columns }` — то, что запоминается для папки: раскладка, `SortSpec`, `GroupSpec` и `Columns { hidden: u8, widths: [f32; 7] }` (битовая маска скрытых колонок и ширины по виду колонки, поэтому у корзины свои «Original location» и «Date deleted», а скрытая колонка сохраняет ширину). Показ скрытых, имён с точкой и системных файлов, расширения, строка состояния, флажки и прочие переключатели — не вид папки, а `ViewPrefs` окна.

`FolderViews` — `Arc<Mutex<…>>` с картой «ключ папки → (метка последнего обращения, `FolderView`)», один на процесс: новое окно получает клон `Arc` вместе с `Persisted`, поэтому вид, изменённый в одном окне, виден во всех. Ключ — `folder_key`: FxHash байтов пути, для локальных путей — в нижнем регистре ASCII (`C:\Users` и `c:\users` — одна папка), для WSL — канонической формы `Location` как есть; корзина и «This PC» — обычные ключи. Хранилище ограничено: больше 4096 папок — и записи с самыми старыми метками удаляются до 3072 (`select_nth_unstable` по меткам, одна операция на тысячу вставок), поэтому и память, и `state.bin` ограничены (около 50 байт на папку). Замок берётся только при загрузке папки и при смене вида, не в кадре.

`App::load_tab` перед каждой загрузкой (переход, история, F5) подставляет вкладке `view_for(loc)` — сохранённый вид папки или `ViewPrefs::defaults` — и синхронизирует с `ViewPrefs` поля `ViewSpec`, которые не принадлежат папке. Любая смена вида идёт через `change_view`: изменить вкладку, пересортировать, если `ViewSpec` изменился, и записать `FolderView` в хранилище (`remember_view`). При `ViewPrefs::same_for_all` вид вкладки при загрузке не подменяется и не запоминается, то есть все папки идут одним видом, пока флаг не снят. «Use this view for folders without their own» копирует вид текущей вкладки в `defaults`. Никаких `desktop.ini` и других файлов в папках пользователя: всё хранится в `state.bin` Flit (`desktop.ini` только читается для адаптивной раскладки и значков папок, пишет его лишь команда «Change the folder icon», см. «Раскладки»).

Подгонка колонок (`fit_columns`) выполняется в кадре, где есть текстовый бэкенд: команда или флаг `auto_fit` (после каждой загрузки и смены набора колонок) ставит вкладке `fit_pending`, и кадр меряет заголовок и видимые строки каждой колонки, кроме имени (оно занимает остаток), ограничивая ширину 40–600 пикселей при 100 %. Меню заголовка колонок, меню корзины и меню результатов поиска — тот же построитель меню Flit, что и контекстное меню, с `ShellMenu::shell = false`: платформа не запрашивает у оболочки пунктов и не добавляет «Show more options».

Таймер окна один (`timer_at`), его ставит `arm_timer` на ближайший срок из медленного второго щелчка и выделения наведением. Выделение наведением (`hover_pick`) ждёт 600 мс, пока курсор остаётся над той же строкой той же вкладки, в активном окне, без нажатых кнопок, Ctrl и Shift, перетаскивания, броска и переименования. Автопрокрутка средней кнопкой хранит точку щелчка; каждый кадр сдвигает список со скоростью (расстояние от точки щелчка − 12 пикселей мёртвой зоны) × 8 пикселей в секунду и заказывает следующий кадр, пока прокрутка не выключена; щелчок, который её выключает, дальше не передаётся.

Вкладка помнит отдельно папку, которую загружает, и папку, чей снимок сейчас на экране (`view_loc`, меняется только вместе с `DirView`). Пока новый листинг не пришёл, Enter, двойной щелчок, Delete, Ctrl+Shift+C и запросы значков работают с той папкой, которую видит пользователь, а не с той, куда вкладка уже переходит.

**Глобальные идентификаторы вкладок.** Каждое окно получает базу `k · 2^32`, его вкладки нумеруются `база + 1`, `база + 2`, и так далее. События провайдера несут только идентификатор вкладки, и `Handler::window_of_tab` находит окно по диапазону; слежение (одно на вкладку) тоже не путает вкладки разных окон.

Закрытие вкладки отменяет её задания (`u64::MAX` в `GenToken`) и снимает слежение; закрытие последней вкладки закрывает окно; при уничтожении окна `App::shutdown` отменяет задания всех его вкладок и снимает их слежение, а обработчик отправляет получившиеся запросы провайдерам; при завершении сеанса Windows (`WM_ENDSESSION`) окна уничтожаются тем же путём, и состояние сохраняется; после последнего окна сохраняется состояние и цикл сообщений завершается. Новое окно (`Effect::NewWindow`) создаётся так: обработчик готовит `App` и ставит его в очередь, `Window::open_window` отправляет концентратору `WM_OPEN_WINDOW`, а `WindowHandler::created` забирает подготовленный `App`.

### Раскладки

`ui/layouts.rs`, `ui/flow.rs`, `ui/columns.rs`. `LayoutMode` — `Details`, `List`, `Cards`, `Columns`, `Grid`, `Adaptive`. У вкладки два поля: `mode` — выбранная раскладка (может быть `Adaptive`), `look` — показываемая конкретная; `look` меняется только вместе с новым снимком (`settle_look` при свежем `DirView`), поэтому старая раскладка остаётся на экране, пока новая папка не пришла. `Sizes` — ступень размера для каждой раскладки (пять у «Подробно», «Списка» и «Колонок», четыре у «Карточек», двенадцать у «Сетки»); таблицы высот строк, ширин колонок «Списка», значков и ширин карточек и плиток лежат в `layouts.rs`. Раскладка и `Sizes` — часть `FolderView`.

Все раскладки, кроме колонок-родителей, стоят на одной геометрии `Flow { per, across, cell, head }`: строки `DirView` (заголовки групп и элементы) идут полосами по `per` ячеек, полоса — ряд у вертикальных раскладок и колонка у «Списка»; заголовок группы занимает всю полосу, а в «Списке» — одну ячейку. «Подробно» — частный случай с `per = 1` и ячейкой во всю ширину. `Flow` отвечает на вопросы раскладки за O(групп): прямоугольник строки, строка под точкой, видимый диапазон, шаг клавиш (соседняя ячейка или полоса с той же позицией, мимо заголовков). Поверх неё работают выделение, рамка, перетаскивание, переименование, контекстное меню, быстрый переход и виртуализация: кадр обходит только строки из `lines_in` видимой области.

«Колонки»: слева до четырёх колонок-родителей (`Pane`), каждая со своим листингом — `ProviderRequest::List` с вкладкой 0 и своим `SnapshotSlot`, а при уходе вглубь — `DirView`, который только что был на экране (`keep_as_pane`), без повторного чтения. Колонка-родитель прокручивается сама и центрирует папку, в которой стоит вкладка; щелчок по её элементу — `open_pane_row`.

«Адаптивная»: `adaptive_layout(kind, view)` — тип папки из `desktop.ini` (`Pictures`, `Videos` → `Grid`; `Documents`, `Music`, `Generic` → `Details`), иначе `Grid`, если картинок и видео больше 60 % элементов. Тип папки читает поток чтения папки, только если вкладка попросила (`SnapshotSlot::ask_kind`, поколение и вид упакованы в один `AtomicU64`), — `Fs::desktop_ini`, на Windows через `std::fs::read`. Решение по первой порции листинга держится до конца загрузки, решение по полному листингу — в `App::adaptive` (до 4096 папок) для следующего открытия. При `same_for_all` адаптивная раскладка отказывает с сообщением.

**Миниатюры.** При `ViewPrefs::thumbnails` кадр «Сетки» и «Карточек» для видимого файла с расширением из `has_thumbnail` ищет миниатюру в атласе по ключу `hash(путь, дата изменения, размер, класс)`, иначе рисует значок и выпускает `Effect::Thumbnail(IconRequest { kind: Thumbnail, gen, row })`; состояние запроса (`Pending`, `Failed`) лежит в `App::thumbs`, не больше 65 536 записей. `flit` отдаёт запрос пулу `flit-thumb-N` вместе с `Visible` окна: поток, взяв задание, проверяет, что строка ещё в видимом диапазоне с запасом 32 строки, иначе отвечает `Skipped`, и состояние сбрасывается, чтобы элемент попросил снова, когда вернётся на экран. Готовая миниатюра (`Done::Thumb`) кладётся в атлас в UI-потоке без декодирования: оболочка уже отдала RGBA.

Собственный кэш на диске (`crates/flit/src/thumbs.rs`, `ThumbCache` под `Mutex`, общий для потоков): `%LOCALAPPDATA%\Flit\thumbs\NNNNNNNN.thumbs`, записи `ключ u64, ширина u32, высота u32, RGBA` подряд. Индекс «ключ → сегмент, смещение» строится при первом обращении проходом по заголовкам (500 миниатюр — 1,7 мс); оборванная запись в конце сегмента отбрасывается, и следующая запись ложится на её место. Сегмент закрывается, когда дорастает до восьмой части предела (не меньше 1 МиБ); пока сумма больше `ViewPrefs::thumb_cache_mb` (100–5000, по умолчанию 500), удаляется самый старый сегмент. `Effect::ClearThumbnails` удаляет все сегменты. Без `LOCALAPPDATA` кэша нет, миниатюры каждый раз делает оболочка.

**Значки папок.** `icon_key` даёт папке с атрибутом `READONLY` или `SYSTEM` собственный ключ (`IconKind::CustomFolder`: путь, дата, атрибуты, `App::icon_epoch`); поток значков читает её `desktop.ini` и, если там есть `IconResource` или `IconFile`, берёт значок у `IShellItemImageFactory` с `SIIGBF_ICONONLY`, иначе общий значок папки. «Change the folder icon» открывает поле палитры `Pick::FolderIcon`, `icon_location` разбирает «путь[,номер]», а `FileOp::FolderIcon` выполняет быстрый путь `flit-shell-ops`: `SHGetSetFolderCustomSettings` с `FCSM_ICONFILE` и `FCS_FORCEWRITE` (оболочка пишет `desktop.ini` и ставит папке «только чтение»). Успех увеличивает `icon_epoch`, и значки таких папок запрашиваются заново; шага отмены у операции нет.

## Команда `Open` и единая точка маршрутизации

`Open { paths, select, target, cwd }` — одна сериализуемая структура для всех источников: её строит `parse_args` из командной строки, она же передаётся по каналу единственного экземпляра и её же собирает адресная строка. Пути остаются сырыми байтами WTF-8 и разрешаются в принимающем экземпляре вместе с `cwd` вызывающего процесса.

`parse_args` понимает синтаксис `explorer.exe`: путь, `/select,<путь>` (и `/select,` с путём в следующем аргументе, как его передают через пробел), `/e,`, `/root,<путь>`, `/n`, склейку ключей через запятую, игнорирует `/separate` и `/idlist`, а также `--new-tab`, `--new-window`, `--current-tab`. Пути Linux вида `/home/...` ключами не считаются.

`open::routes` превращает `Open` в маршруты `Route { folder: Location, select: Option<имя> }` и список ошибок. `resolve` по порядку: CLSID «Этого компьютера» → «This PC»; `shell:` и `::{` → `Platform::known_folder` (`SHCreateItemFromParsingName` и `SIGDN_FILESYSPATH`, поэтому годятся только папки с путём в файловой системе, иначе `UnknownShellLocation`); `file:///C:/…`, `file://localhost/C:/…` и `file://сервер/шара/…` (→ `\\сервер\шара\…`) с декодированием `%XX`; абсолютные, UNC и WSL-формы через `Location::parse`; формы Windows относительно `cwd`: `\x` и `/x` — от корня `cwd` (для `cwd` в WSL-шаре `/etc` даёт `wsl://D/etc`), `C:x` — от `cwd`, если он на том же диске, иначе от `C:\`; иначе путь присоединяется к `cwd`. Испорченный URL и голый `\\сервер` — ошибка `Invalid`, а не путь внутри `cwd`. Префиксы сравниваются по байтам, поэтому многобайтовые символы в начале пути не ломают разбор. `/select` даёт маршрут в родительскую папку с именем для выделения.

Одна команда открывает не больше 32 маршрутов, лишние отбрасываются с сообщением «Opened the first 32 of N locations». `App::open` подставляет вместо `OpenTarget::Default` значение `App::open_target` (пока всегда «новая вкладка», настроек в интерфейсе нет), вызывает `App::dispatch` и затем выводит первую ошибку разрешения в строку состояния той вкладки, которая оказалась текущей.

`App::dispatch(routes, target)` — единая точка, где маршрут становится вкладкой или окном:

- `NewWindow` → `Effect::NewWindow(routes)`;
- `CurrentTab` → первый маршрут в текущей вкладке (если вкладка уже в этой папке и нужное имя есть — только выделение, без перечитывания), остальные в новых вкладках;
- `NewTab` и `Default` → каждый маршрут в новой вкладке.

Через `dispatch` проходят входящие команды по каналу (`Handler::apply_opens` → `App::open`), адресная строка (`Effect::Open` с `CurrentTab` и `cwd` = текущая папка; обработчик вызывает `App::open` с тем же `Platform::known_folder`, поэтому `shell:`-пути работают и здесь) и внутренняя навигация: вход в папку, «вверх», хлебные крошки, новая вкладка, перетаскивание файлов. «Назад», «вперёд», обновление и `Rescan` не создают маршрутов и перечитывают папку через `Tab::load`. Командная строка самого первого процесса разрешается тем же `open::routes`, но маршруты открываются конструктором `App::new` — по вкладке на маршрут, а без маршрутов открывается сохранённая папка; ошибки разрешения показываются тем же `App::show_open_errors`.

## Провайдеры

Трейт `Provider { fn submit(&self, req: ProviderRequest) }` асинхронный: листинг возвращается через `SnapshotSlot`, всё остальное — событиями `ProviderEvent` в общий канал.

- Запросы: `List`, `Watch`, `DirSizes`, `Op { tab, id, op: FileOp, ctl: OpCtl }`, `Open { tab, path }`, `Launch { tab, launch: Launch }` (`Terminal { dirs, admin }` или `With { program, args }`).
- События: `Changes`, `Rescan`, `DirSize`, `OpDone { tab, id, error, report }`, `OpProgress { tab, id, progress }`, `OpConflict { tab, id, conflict }`, `Navigate { tab, path }` (ярлык оказался ссылкой на папку), `Status { tab, gen, text }` (пояснение вместо «Loading…» в строке состояния загружающейся вкладки: «Starting Ubuntu-22.04…»). Операции несут вкладку-источник, поэтому `Handler::window_of_tab` доставляет прогресс, вопрос о конфликте и ошибку в то окно и ту вкладку, откуда пришла команда.

`LocalProvider` лежит в `flit-platform` и не содержит кода ОС. `LocalProvider::new::<F, W, S>(fs, …)` обобщён по `Fs`, `Watcher` и `Shell + FileOps` и запускает потоки, которые владеют реализациями: пул чтения `flit-fs-N`, `flit-sizes`, `flit-watch-ctl`, `flit-shell-open` и `flit-shell-ops`, а тот — потоки операций `flit-op-N`, каждый со своим экземпляром `S`. Сама структура хранит только отправители каналов и ожидающие постановки слежения, поэтому она не обобщена, а медленная постановка слежения (недоступная сетевая папка) задерживает только поток слежения, но не UI-поток. `flit-platform-windows` даёт реализации `NtFs`, `DirWatcher`, `ShellCom`. Тесты гоняют тот же код на файловой системе в памяти.

`NtFs` помечает запись ссылкой, только если тег точки повторной обработки — суррогат имени (`tag & 0x20000000`: символические ссылки, точки соединения, ссылки WSL); заглушки OneDrive и дедупликации остаются обычными файлами и папками. Тег берётся из `EaSize` при чтении каталога и из `ReparsePointTag` в уведомлениях.

`ShellCom` передаёт диалогам оболочки окно-владелец (только если на переднем плане окно самого Flit), а `ShellExecuteExW` — папку файла как рабочую. Значки, которые оболочка отдаёт крупнее запрошенного, уменьшаются усредняющим фильтром по предумноженным пикселям (`fit`). `ShellCom::open` и `FileOps::file_op` отказываются работать с путём, в котором есть имя, оканчивающееся точкой или пробелом: оболочка нормализует такой путь по правилам Win32 и молча срезает точку, так что удалился бы `build` вместо `build.`. Пользователь видит ошибку, а не удаление чужого файла.

Трейт `Platform` связывает реализации в одну точку: ассоциированные типы `WindowSystem`, `Renderer`, `Text`, `Fs`, `Watcher`, `Shell`, `Instance`, `IndexSource`, `Service` и функции `text`, `fs`, `utc_offset_minutes`, `dark_mode`, `state_dir`, `home`, `known_folder`, а также с реализациями по умолчанию `templates` (шаблоны «Создать», по умолчанию пусто), `double_click_time` (500 мс), `elevated` (`false`), `watch_wsl` (ничего не делает) и `wsl_launcher` (`None`, то есть WSL только через `\\wsl.localhost`). У `Shell` по умолчанию `launch` отказывает, а `shortcut_folder` возвращает `None`, поэтому Linux-заглушка их не реализует; `Window::set_timer(ms)` — одноразовый таймер окна.

**`WslProvider`.** `Handler::submit` приводит имя дистрибутива к написанию из реестра и отправляет запросы `ProviderId::Wsl(distro)` в `WslProvider` этого дистрибутива из `Handler::wsl`, создавая его при первом запросе. Провайдер (`crates/flit-platform/src/wsl.rs`) — управляющий поток `flit-wsl-<distro>` с состояниями «нет агента», «запуск», «готов» и «упрощённый». Агента он получает от `Platform::wsl_launcher(distro, &AGENTS)`: трейт `AgentLauncher` умеет `launch` (процесс с stdin, stdout и функцией остановки) и `deliver`; реализация Windows — `WslLauncher`. Первый `List`, `DirSizes` или `Op::Trash` запускает агента, запросы ждут в очереди, загружающиеся вкладки получают `Status`. После `Hello` с тем же идентификатором сборки очередь уходит агенту; чужой `Hello`, EOF или мусор вызывают одну доставку и повторный запуск, отсутствие `Hello` за 15 с или неудачная доставка переводят дистрибутив в упрощённый режим до перезапуска Flit. Пачки `Entries` складываются в `Listing` и публикуются в `SnapshotSlot` раз в 16 мс, как у `LocalProvider`; устаревший листинг или `DirSizes` (по `GenToken`) отменяется запросом `Cancel`. Каждое событие агента проверяется `Event::validate(false)` в потоке чтения, и невалидное считается разрывом. После 5 минут без наблюдений и незавершённых запросов агент получает `Shutdown` и через секунду завершается. Разрыв завершает ожидающие листинги ошибкой `Unavailable`, операции — ошибкой, а вкладкам с наблюдением шлёт `OpDone { id: 0 }` с текстом о потере связи; перезапуск — только следующим запросом от действия пользователя, а три разрыва за 5 минут включают упрощённый режим.

**WSL в упрощённом режиме.** `WslProvider` в состоянии «упрощённый», а в любом состоянии — все запросы, кроме `List`, `Watch`, `DirSizes` и `Op::Trash`, отдаёт `LocalProvider`, переписав пути функцией `via_unc` в `\\wsl.localhost\<distro>\...`. Если путь нельзя выразить через шару (имя не в UTF-8), запрос дальше не уходит: `List` сразу получает снимок с ошибкой `Unavailable`, `Watch` снимает слежение, операция получает `OpDone` с ошибкой `UNMAPPABLE`, остальное отбрасывается с записью в лог. Подробности — в [docs/design/wsl.md](docs/design/wsl.md).

## Файловые операции

**Команды.** Каждая команда — отдельный публичный метод `App` в `crates/flit-core/src/ui/ops.rs`: `copy_selection`, `cut_selection`, `paste`, `paste_into_selection`, `rename_focused`, `new_folder`, `new_item_dialog`, `new_folder_with_selection`, `new_stream`, `create_shortcuts`, `open_terminal`, `trash_selection`, `delete_selection`, `flatten_selection`, `restore_selection`, `restore_all`, `empty_bin`, `undo`, `redo`, `properties`, `context_menu`; панель операций — `toggle_jobs` и `clear_completed` в `ui/jobs.rs`. Их сочетания зарегистрированы в реестре `ACTIONS` (`file.copy`, `file.cut`, `file.paste`, `file.paste_into`, `file.rename`, `file.new_folder`, `file.new_item`, `edit.undo`, `edit.redo`, `item.properties`, `item.context_menu`, `item.copy_quoted_path`, `app.terminal`, `app.terminal_admin`, Delete — `item.trash`, Shift+Delete — `item.delete`, без сочетаний — `bin.restore`, `bin.restore_all`, `bin.empty`, `file.new_folder_with_selection`, `file.new_stream`, `file.shortcut`, `file.flatten`, `ops.show`, `ops.clear`, а также `item.open_tab`, `item.open_window` и `item.pin` из `actions.rs` и `sidebar.rs`), поэтому те же команды есть в палитре, а многие — и в контекстном меню; `ops_key` перехватывает клавиши только пока открыт редактор переименования. Команды работают с выделением той папки, которая на экране (`view_loc`), и строят пути Windows (`Location::to_windows`): папка WSL адресуется через `\\wsl.localhost`, а запрос всегда уходит провайдеру `ProviderId::Local`. В «This PC» вставка, новая папка и переименование отказывают с сообщением в строке состояния.

**Протокол.** `ProviderRequest::Op { tab, id, op, ctl }` несёт `FileOp`: `Trash`, `Copy { items, dest }`, `Move { items, dest }`, `Link { items, dest }`, `Rename { item, name }`, `NewFolder { dir, name }`, `NewFile { dir, name, template }` (`Template::Empty`, `Copy(файл-шаблон)` или `Data(байты)`), `NewStream { item, name }`, `MoveTo(пары)`, `Restore(пары)`, `Paste { dest }`, `Delete(пути)` (навсегда, мимо корзины), `Purge(пары «$R… → исходный путь»)`, `EmptyBin` и `Flatten(папки)`; `id` — номер операции в окне. `OpCtl` — общий для UI и потока операции `Arc`: флаг отмены (`cancel`, `is_cancelled`) и ответ на конфликт под мьютексом с условной переменной. Поток операции зовёт `OpCtl::resolve(ask)`: если уже есть действие по умолчанию (`policy`: из флага `App::conflict_default` или после «для всех остальных»), оно возвращается сразу; иначе `ask` отправляет `OpConflict { conflict: Conflict { source, target, from, to } }` с `Meta` обеих сторон, и поток ждёт `OpCtl::answer(Resolve, all)` или отмену (`Resolve::KeepBoth`, `Replace`, `Skip`; отмена — `None`). Прогресс — `OpProgress { progress: OpProgress { stage, bytes, total_bytes, items, total_items } }`, где `Stage` — `Preparing` (подсчёт), `Queued` (ждёт очереди тома) или `Running`. Ответ — `ProviderEvent::OpDone { tab, id, error, report }`, где `OpReport { op, items }` — фактически выполненная операция и пары «откуда → куда» для каждого обработанного элемента верхнего уровня: итоговое имя после переименования при конфликте, путь `$R…` в корзине. Частичный успех даёт и ошибку, и отчёт. `FileOp::map_paths` переписывает все пути операции, через него `via_unc` пропускает операции WSL.

**Выполнение.** Трейт `FileOps`: `file_op(&FileOp, &Job) -> OpOutcome`, `clipboard_files`, `clear_clipboard`. `Job` (в `flit-platform`) — сторона потока операции над `OpCtl`: `update` копит прогресс и отправляет `OpProgress` не чаще раза в 33 мс (сразу — при смене стадии), `resolve` задаёт вопрос через `OpConflict`, `cancelled` читает флаг отмены; `Job::detached(policy)` работает без событий, для тестов и замеров. `ShellCom::file_op` сначала проверяет имена: `shell_addressable` отвергает имя, оканчивающееся точкой или пробелом, во всех путях операции, а новое имя не может быть пустым и оканчиваться точкой или пробелом. Затем `Copy`, `Move`, `MoveTo`, `Rename`, `Delete` и `Flatten` выполняет собственный движок (`engine.rs`); `Trash`, остаток, который движок вернул, и запасные пути новых элементов — `IFileOperation`; `Link`, `NewStream`, `Purge`, `EmptyBin`, `Restore`, `NewFolder` и `NewFile` идут напрямую (ниже).

**Движок.** `engine::run(op, job) -> Outcome { items, error, rest }`. Стадия `Preparing`: верхние элементы читаются `FindFirstFileExW` (атрибуты и тег точки повторной обработки через `map_attrs`), для копирования, переноса между томами и удаления деревья обходятся `NtFs::read_dir` и считаются элементы и байты (`Tally`); затем стадия `Running` с этими итогами. Обход в глубину тем же `NtFs::read_dir`: файл копирует `CopyFile2` с `COPY_FILE_FAIL_IF_EXISTS` и `pProgressRoutine` (на `COPYFILE2_CALLBACK_CHUNK_FINISHED` растут байты; после отмены ответ `COPYFILE2_PROGRESS_CANCEL`, и `CopyFile2` сам удаляет недокопированный файл), папку создаёт `CreateDirectoryExW` с исходной папкой как шаблоном (атрибуты, сжатие), перемещение — `MoveFileExW` без флагов, удаление — `DeleteFileW` и `RemoveDirectoryW` со снятием атрибутов «только чтение», «скрытый» и «системный» при отказе в доступе. Перемещение, получившее `ERROR_NOT_SAME_DEVICE`, продолжается как перенос между томами: копия, затем удаление источника; если источник удалить не удалось, удаляется копия, а элемент становится ошибкой. Папка переносится поэлементно, а в источнике удаляется, только когда ушло всё её содержимое. `MoveTo` создаёт недостающие родительские папки цели (`ERROR_PATH_NOT_FOUND`), поэтому отмена «Flatten folder» и слияния возвращает файлы на место. Папку нельзя скопировать или переместить в неё саму или в её подпапку. Дерево со ссылками на папки (точки соединения, символические ссылки) при копировании и переносе между томами целиком уходит `IFileOperation`; перемещение внутри тома переносит ссылку как есть, удаление удаляет саму ссылку, не заходя в неё. Копия в папку самого источника получает имя «x - Copy.ext», затем «x - Copy (2).ext».

**Конфликты.** Когда имя цели занято, движок спрашивает `Job::resolve` с метаданными обеих сторон. «Keep both» даёт свободное имя «x (2).ext» (`free_name`), «Skip» оставляет обе стороны нетронутыми. «Replace» для файла копирует во временный `имя.flit-partial` рядом с целью и ставит его на место `MoveFileExW` с `MOVEFILE_REPLACE_EXISTING` (перемещение внутри тома — сразу `MOVEFILE_REPLACE_EXISTING`), поэтому отмена или сбой посреди копирования оставляют старый файл; атрибут «только чтение» у цели снимается только после выбора «Replace». «Replace» для папки сливает: содержимое источника обрабатывается внутри существующей папки по тем же правилам, файлы цели с другими именами остаются, сама папка цели не удаляется никогда. «Replace» между файлом и папкой превращается в «Keep both». Отмена из диалога останавливает операцию. Занятое имя при переименовании (F2) не спрашивается: ответ — ошибка «An item named … already exists»; смена только регистра работает.

**Отчёт и сохранность.** В отчёт попадают пары для отката: новая папка копии — одной парой, слитая папка — парами её содержимого, папка, перенесённая не целиком, — парами того, что ушло. Отмена и сбой не трогают необработанные источники: обработанное остаётся на новом месте и есть в отчёте, поэтому Ctrl+Z его возвращает. Отказ в доступе на верхнем элементе (нужны права администратора) передаёт этот и все оставшиеся элементы `IFileOperation` как `Copy`, `MoveTo` или `Delete`, и запрос UAC показывает оболочка; переименование с отказом в доступе уходит в `IFileOperation::RenameItem`. Если подсчитанный объём копирования или переноса на другой том больше свободного места тома назначения (`GetDiskFreeSpaceExW`), операция сразу завершается ошибкой «There is not enough free space in …: the items need …, but only … is free», ничего не скопировав; нехватка места посреди операции её останавливает, прочие ошибки копятся: «N items failed. <первая>». Изменения сообщаются оболочке одним `SHChangeNotify(SHCNE_UPDATEDIR, SHCNF_FLUSHNOWAIT)` на каждую затронутую папку верхнего уровня, а не на каждый элемент; открытые папки Flit обновляет его собственное слежение.

**`IFileOperation`.** Работает в потоке операции для корзины, остатка движка и запасных путей новых элементов. `IFileOperationProgressSink` записывает результаты `PostCopyItem`, `PostMoveItem`, `PostRenameItem`, `PostNewItem` и `PostDeleteItem` (в отчёт — только элементы из запроса), `UpdateProgress` переводит прогресс в `Job::update`, а `Pre…` и `UpdateProgress` после отмены отвечают `ERROR_CANCELLED`, и оболочка прерывает операцию. Флаги: корзина — `FOF_ALLOWUNDO | FOFX_ADDUNDORECORD | FOFX_RECYCLEONDELETE | FOF_SILENT` (прогресс рисует панель Flit); новая папка и копия в папку самого источника — с `FOF_RENAMEONCOLLISION`; остальное — со стандартными диалогами, а если источники укладываются в бюджет (`QUIET_ENTRIES` = 500 элементов, `QUIET_BYTES` = 16 МиБ, обход не заходит в точки повторной обработки), с `FOF_SILENT`. `FOF_NOCONFIRMATION` и `FOF_NOERRORUI` не ставятся никогда: «слишком велик для корзины», запрос прав и ошибки оболочка показывает как обычно. Владелец её диалогов — окно Flit, если оно на переднем плане.

**Прямые операции.** Ярлыки (`Link`) создаются через `IShellLinkW` и `IPersistFile` с именем «x - Shortcut.lnk» и суффиксом « (k)», если имя занято. Новая папка — `CreateDirectoryW` и `SHCNE_MKDIR`, при занятом имени — `IFileOperation::NewItem` с `FOF_RENAMEONCOLLISION`. `Restore` переносит `$R…` на исходный путь `MoveFileExW` без флагов (перенос отказывает, если имя занято или папки нет), удаляет парный `$I…` из той же папки `$Recycle.Bin\<SID>` и сообщает оболочке переименование; остальные пары находятся перечислением корзины (`FOLDERID_RecycleBinFolder`) и восстанавливаются глаголом `undelete` — то же, что «Восстановить» в Проводнике.

**Расписание.** Маршрутизатор `flit-shell-ops` разрешает `Paste` и сам выполняет быстрые операции (`Rename`, `NewFolder`, `NewFile`, `NewStream`, `Link`, `Restore`); каждая остальная получает поток `flit-op-<id>` со своим `ShellCom`, так что операции идут одновременно и у каждой своя отмена. Перенос байтов — `Copy` и `Move`/`MoveTo` между томами — сначала занимает очередь тома назначения (`Gate`: набор занятых корней под мьютексом и условная переменная): две копии на один диск не делят его пополам, а идут друг за другом, вторая — в стадии `Queued`, и раз в 50 мс проверяет отмену. Перемещения внутри тома, пакетное переименование, корзина, удаление и «Flatten folder» очереди не ждут: это операции с метаданными, им параллельность не вредит. Счётчик идущих операций даёт `LocalProvider::wait_idle(limit)`.

**Замеры.** `bench_engine` (release, исходные данные в `%TEMP%` на C:, другой том — `target` на D:), до → после: папка из 50 файлов по 1 КБ — 138 → 21 мс; папка из 1000 файлов — 2148 → 402 мс; 1000 выделенных файлов — 2941 → 474 мс; файл 512 МБ — 187 → 118 мс (буферизованное копирование из кэша; `COPY_FILE_NO_BUFFERING` дал 204 мс и не используется); перенос папки из 50 файлов на другой том — 173 → 21 мс, из 1000 файлов — 3285 → 420 мс; перемещение папки внутри тома — 0,7 → 0,9 мс; пакетное переименование 1000 файлов — 448 → 292 мс. `bench_file_ops`: копирование файла 4 КБ — 0,5 мс, копия в ту же папку — 0,55 мс вместо 14, 20 файлов — 8,7 мс вместо 10, перенос файла на другой том — 0,8 мс, удаление одного файла в корзину — 12 мс, восстановление — 0,4 мс, перемещение внутри тома и переименование — 0,4 мс.

`NewFile` тоже идёт напрямую: `Empty` и `Data` — `File::create_new` (`CreateFileW` с `CREATE_NEW`) и запись байтов, `Copy` — `CopyFile2` с `COPY_FILE_FAIL_IF_EXISTS` и время изменения «сейчас», иначе новый документ показывал бы дату шаблона; затем `SHCNE_CREATE`. Если имя занято или нет прав, операция уходит в `IFileOperation::NewItem` с `FOF_RENAMEONCOLLISION` (шаблон передаётся по имени файла, данные `Data` в этом пути теряются, получается пустой файл). `NewStream` создаёт `путь:имя` тем же `File::create_new` и запасного пути через оболочку не имеет: оболочка потоков не знает, ошибка ОС приходит в строку состояния. Ярлык (`Link`) на несуществующую цель не создаётся. Замеры `bench_new_items`: пустой файл — 0,28 мс, файл из 22 байт — 0,32 мс, из шаблона 20 КБ — 0,6 мс, поток — 0,2 мс.

**Вставка.** `Paste { dest }` разрешается в маршрутизаторе `flit-shell-ops` (`resolve_paste` в `LocalProvider`), а не в UI-потоке: `FileOps::clipboard_files` читает `CF_HDROP` и `Preferred DropEffect`. Вырезанное превращается в `Move` (элементы, которые уже лежат в `dest`, пропускаются), скопированное — в `Copy`. После успешного перемещения буфер очищается, но только если его содержимое не менялось с момента чтения (сравнивается номер последовательности буфера). Отчёт приходит с уже разрешённой операцией, поэтому отмена знает, что было сделано на самом деле.

**Буфер обмена.** `Effect::SetClipboardFiles { paths, cut }` исполняется в UI-потоке как дешёвый вызов Win32: `CF_HDROP` (`DROPFILES` с широкими путями) и зарегистрированный формат `Preferred DropEffect` (`DROPEFFECT_MOVE` для вырезания, `DROPEFFECT_COPY | DROPEFFECT_LINK` для копирования). Если буфер держит другой процесс, любое открытие буфера (файлы и текст, запись и чтение) повторяется до 20 раз через 15 мс. Ctrl+Shift+C по-прежнему кладёт пути текстом.

**Результат и выделение.** `App::op_done` выводит ошибку в строку состояния вкладки-источника, перечитывает вкладку WSL или UNC (живых уведомлений там часто нет), записывает отчёт в журнал отмены и, если результаты лежат в папке, открытой во вкладке, запоминает их имена (`Reveal`). Каждый кадр `ops_frame` ищет эти имена в `DirView` (они появляются по уведомлениям слежения), выделяет найденные, ставит фокус на первое и прокручивает к нему; для новой папки сразу открывается переименование (открытый фильтр папки `new_folder` закрывает заранее, иначе папка была бы скрыта). Ожидание длится не дольше 10 с.

**Панель операций.** `ui/jobs.rs`. `start_op_for` создаёт `OpCtl` с `App::conflict_default` и для заметных операций (копирование, перемещение, `MoveTo`, вставка, корзина, удаление, «Flatten folder», восстановление, удаление из корзины, очистка) заводит `Job` с заголовком («Copying “a.txt” to “dst”», «Moving 3 items to the Recycle Bin», «Renaming 40 items»), папкой назначения и тем же `OpCtl`. `OpProgress` обновляет строку; раз в 250 мс считается скорость (байты или элементы в секунду) и кладётся отсчёт графика, до 60 отсчётов. `OpDone` переводит строку в `Done`, `Failed(текст)` или `Cancelled` (если `OpCtl` отменён). Кнопка операций стоит справа от адресной строки и видна, если поднят флаг `App::ops_button_always` (настройка появится на этапе 8), пока что-то идёт, пока панель открыта или пока ошибку не посмотрели (красная точка); во время работы на ней полоса общего прогресса. Щелчок открывает панель под кнопкой: заголовок «Operations» с кнопкой «Clear completed», строки новыми сверху (видно пять, колесо прокручивает), у каждой — заголовок, процент или итог, кнопка отмены, меню «⋯» («Open destination» открывает папку назначения в новой вкладке, затем «Cancel» или «Remove from the list»), график скорости, полоса прогресса и строка деталей («12 MB of 40 MB · 85 MB/s · 3 of 10 items», «Waiting for another operation on this drive», «Waiting for your answer», «Completed in 1.2 s», текст ошибки). Esc или щелчок вне панели закрывают её. Список хранит до 100 строк: при переполнении уходит самая старая завершённая. Список свой у каждого окна и не сохраняется между запусками.

**Диалог конфликта и подтверждение.** `OpConflict` встаёт в очередь `Jobs::asks`, первый вопрос показывается модальным диалогом поверх всего окна, в том числе поверх поиска: имя, папка, размеры и даты обеих сторон, для двух папок — пояснение, что «Replace» их сливает; кнопки «Replace», «Keep both» (выбрана), «Skip», «Cancel» и флажок «Do this for all remaining conflicts». Клавиши: R, K, S, A (флажок), Enter, Esc (отменить операцию), ←, →, Tab. Ответ уходит в `OpCtl::answer`, «Cancel» — в `OpCtl::cancel`; вопросы завершившейся операции из очереди убираются. Пока диалог открыт, остальной ввод окна не действует (`jobs_hit` отдаёт `Hit::Modal`, `jobs_key` забирает клавиши, символы и вставка отбрасываются); работают только кнопки заголовка окна и перетаскивание за заголовок, а закрытие окна отменяет операцию. Тот же диалог подтверждает удаление навсегда (`Delete`, `Purge`, `EmptyBin`): кнопки «Delete» (выбрана) и «Cancel», операция уходит провайдеру только после «Delete». Закрытие окна (`App::shutdown`) отменяет его операции, а при закрытии последнего окна `Handler` ждёт их остановки до 2 с (`wait_idle`), чтобы `CopyFile2` успел убрать недокопированный файл.

**Отмена.** `flit_core::undo::Journal` — стеки отмены и повтора одного окна, до 100 шагов. `inverse(&OpReport)` строит обратный шаг: копия, ярлык, новая папка, новый файл и восстановление → созданное в корзину; поток NTFS обратного шага не имеет; перемещение и «Flatten folder» → `MoveTo` по парам в обратную сторону (недостающие папки создаются заново); переименование → обратно; удаление в корзину → `Restore` по путям `$R…`; `Delete`, `Purge` и `EmptyBin` обратного шага не имеют и в журнал не попадают. Удалённое мимо корзины (в отчёте путь не изменился) вернуть нельзя: такие элементы пропускаются, а если других нет, шаг становится `Refuse` с сообщением. Операция, запущенная отменой, записывает свой отчёт в стек повтора, запущенная повтором — в стек отмены, новая операция очищает повтор. Журнал строится по фактическому отчёту, а не по запросу, поэтому имена, полученные при конфликте («Keep both»), учитываются. Заменённое («Replace») не восстанавливается: прежний файл перезаписан, а отмена копии или перемещения с заменой отправляет в корзину или уносит обратно новую версию, и на месте старой ничего не остаётся. Отменённая на середине операция отменяется по своему частичному отчёту.

**Переименование в списке.** `rename_focused` открывает `LineEdit` поверх ячейки имени: выделено имя без расширения (у папки — всё имя), ввод, вставка и IME идут в него. Enter и щелчок вне поля применяют, Esc отменяет. `validate_name` срезает пробелы по краям и точки и пробелы в конце, отвергает `<>:"/\|?*` и управляющие символы, зарезервированные имена (`CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`, включая `COM¹` и подобные, с любым расширением) и имена длиннее 255 единиц UTF-16; в папке WSL запрещён только `/`. Недопустимое имя оставляет редактор открытым с причиной в строке состояния. Если запись пропала из вида или пришло новое поколение листинга, редактор закрывается.

**Предупреждение о расширении.** `commit_rename` сравнивает расширения старого и нового имени (`changes_extension`, без учёта регистра; у папок расширения нет). Если флаг `App::warn_extension_change` (по умолчанию включён, настройка появится на этапе 8) поднят и расширение меняется или пропадает, редактор остаётся открытым, строка состояния предупреждает, а новое имя запоминается в `Rename::confirmed`; повторный Enter с тем же именем применяет его, другое имя предупреждает заново.

**Пакетное переименование.** F2 при нескольких выделенных элементах, когда фокус на одном из них, открывает редактор на элементе под фокусом, не сбрасывая выделения (`Rename::batch`). Введённое имя без расширения редактируемого элемента становится основой: `batch_names` даёт элементам в порядке строк имена «основа (k)» с их собственными расширениями, `k` растёт и пропускает имена, занятые невыделенными элементами (сравнение без учёта регистра). Всё уходит одной операцией `MoveTo` с выделением результата, поэтому отмена — один шаг. Замер `bench_new_items`: имена для 1000 элементов — 0,09 мс; переименование 100 файлов — 23 мс вместо 34, 1000 — около 275 мс вместо 450 (сам `MoveFileExW` на тестовой машине — 0,25 мс на файл; раньше оболочке сообщалось `SHChangeNotify` о каждом элементе, теперь один `SHCNE_UPDATEDIR` на папку).

**Переименование медленным щелчком.** `press_row` помечает нажатие `Press::slow`, если строка — единственная выделенная, щелчок пришёлся на колонку имени без модификаторов и окно получило фокус раньше, чем время двойного щелчка назад (иначе щелчок, активирующий окно, начинал бы переименование). При отпускании `ops_mouse_up` запоминает `Slow { вкладка, поколение, запись, момент }` и выпускает `Effect::Timer(double_click)`; обработчик вызывает `Window::set_timer`, а Windows-окно — `SetTimer` и по `WM_TIMER` снимает таймер (`KillTimer`) и отправляет `Event::Timer`. `ops_timer` начинает переименование, только если момент наступил (ранний таймер переставляется на остаток, допуск 16 мс), та же запись всё ещё единственная выделенная в том же поколении листинга. Любая клавиша, новое нажатие мыши (в том числе второй щелчок двойного) и потеря фокуса сбрасывают `Slow`. `App::double_click` берётся из `GetDoubleClickTime` при создании окна.

**Создание элементов.** `new_item_dialog` открывает палитру в режиме выбора (`Pick::NewItem`): «Folder», «Shortcut» и шаблоны из `Places::templates`. Шаблон — `NewTemplate { label, ext, stem, template }`; их собирает `places::templates` в потоке `flit-places` один раз за процесс, вторым ответом после первого списка мест, чтобы чтение реестра не задерживало боковую панель. Перечисляются подключи `HKEY_CLASSES_ROOT`, начинающиеся с точки; ключ `ShellNew` ищется в `.ext\ShellNew` и `.ext\<ProgID>\ShellNew`. Записи с `Handler` или `Command` пропускаются; `FileName` (абсолютный путь или имя в `%APPDATA%\Microsoft\Windows\Templates`, `%ProgramData%\Microsoft\Windows\Templates`, `%SystemRoot%\ShellNew`) даёт `Template::Copy`, `Data` (двоичное) — `Template::Data`, `NullFile` — `Template::Empty`. Подпись — `MenuText` через `SHLoadIndirectString` или `AssocQueryStringW(ASSOCSTR_FRIENDLYDOCNAME)`, основа имени — `ItemName` или «New <подпись>». Замер: около 90 мс на 6000 ключей `HKCR` (16 мс — само перечисление, остальное — открытие `ShellNew` у 1174 расширений). `create` выбирает свободное имя (`free_name`: занятые имена листинга с той же основой, без учёта регистра, суффикс « (k)» до расширения), закрывает фильтр и запускает `NewFolder` или `NewFile` с `Then::Rename`: элемент выделяется и переименовывается, как только слежение его покажет. «Shortcut» и «New alternate data stream» открывают тот же слой как поле ввода (`Pick::Shortcut(папка)`, `Pick::Stream(файл)`): цель ярлыка должна быть полным путём (диск, UNC или `\\?\`), кавычки по краям снимаются, получается `Link` с переименованием результата; имя потока проверяется `validate_name`, получается `NewStream`, и по завершении строка состояния показывает `файл:поток`.

**Новая папка с выделенным.** `new_folder_with_selection` запускает `NewFolder` с `Then::Fill(пути)`. Когда она создана, `op_done` сразу запускает `Move` выделенных путей в неё с `Then::Reveal(имя папки)`, а уже по завершении перемещения папка выделяется и открывается для переименования. В журнал попадают два шага.

**Вставка в папку, пути, вырезанное.** `paste_into_selection` отправляет `Paste { dest }` с единственной выделенной папкой. `copy_paths(quoted)` берёт только выделение, без него — текущую папку. При вырезании `App` запоминает `Cut { папка, имена, номер буфера }`; строки с этими именами в этой папке, как и скрытые элементы, рисуются с полупрозрачным значком (`Gfx::image_alpha`) и приглушённым именем. Окно подписано на `AddClipboardFormatListener`, `WM_CLIPBOARDUPDATE` превращается в `Event::ClipboardChanged(GetClipboardSequenceNumber())`: первое уведомление после вырезания — сама запись Flit, его номер запоминается, любой другой номер снимает приглушение. Содержимое буфера не читается и не опрашивается.

**Терминал и запуск.** `open_terminal(admin)` собирает выделенные папки (не больше `MAX_TERMINALS` = 5, о лишних говорит строка состояния) или текущую папку и отправляет `Launch::Terminal`; «This PC» и корзина отказывают. Бросок на строку `.exe`, `.com`, `.bat`, `.cmd` — `Target::Run`: строка подсвечивается, эффект — копирование, если источник его разрешает, бросок самой программы на себя запрещён, а `Drop` отправляет `Launch::With { program, args }`. Оба запроса идут в `flit-shell-open`, `via_unc` переписывает пути WSL. `shell::commands` строит командные строки чистой функцией: если есть псевдоним `%LOCALAPPDATA%\Microsoft\WindowsApps\wt.exe`, то один `wt.exe` с `new-tab -d <папка>` на каждую папку через ` ; ` (точка с запятой в пути экранируется `\;`), иначе по `cmd.exe /k pushd "<папка>"` на папку (`pushd` работает и для UNC, и в повышенном процессе, где рабочая папка не наследуется); папка WSL (`Location::from_local` узнаёт `\\wsl.localhost`) открывается как `wsl.exe -d <дистрибутив> --cd <путь>`. Аргументы программы — пути в кавычках по правилам `CommandLineToArgvW` (с удвоением обратных косых черт в конце), рабочая папка — папка программы. Запуск — `ShellExecuteExW`, для администратора с глаголом `runas`; отказ в запросе UAC (`ERROR_CANCELLED`) не считается ошибкой.

**Ярлыки на папки.** `Open` с путём, оканчивающимся на `.lnk`, сначала спрашивает `Shell::shortcut_folder`: `IShellLinkW` + `IPersistFile::Load` и `GetPath`, затем проверка, что цель — существующая папка. Тогда провайдер отвечает `ProviderEvent::Navigate`, и вкладка переходит в папку (если она всё ещё текущая); иначе файл открывает оболочка, как раньше. Замер: около 2 мс на ярлык, почти всё — `Load`.

**Контекстное меню и свойства.** Состав меню решает ядро (`crates/flit-core/src/ui/menu.rs`): `App::build_menu(on_items)` возвращает дерево `MenuItem` (`Command { label, keys, checked }`, `Submenu`, `Separator`) и запоминает в `App::menu` команды (`Cmd::Action(id)` из реестра `ACTIONS` или `Cmd::NewItem(k)` для пунктов «New») в порядке обхода в глубину. Текст сочетания — первое сочетание команды из реестра (`chord_text`), то же, что видно в палитре. Меню строки: «Open», для папок «Open in new tab» и «Open in new window» (`item.open_tab`, `item.open_window` → `dispatch` с `NewTab`/`NewWindow`), «Cut», «Copy», «Paste» в единственную выделенную папку, «Copy path», «Create shortcut» (`file.shortcut` → `FileOp::Link` в текущую папку с выделением результата), «Rename», «Delete», «Pin to sidebar»/«Unpin from sidebar», если выделены только папки (`item.pin` → `pin_selection`: открепляет, если все уже закреплены, иначе закрепляет недостающие), «New folder with selection», «New alternate data stream» для одного файла, «Open in terminal» для папок, «Properties»; в «This PC» пункты, требующие папки файловой системы, не появляются. Меню фона: подменю «Sort by» (четыре поля и «Descending», отмечен текущий порядок), «Refresh», подменю «New» (папка, ярлык, шаблоны «Создать»), «Paste», «Open in terminal», «Pin to sidebar» (`sidebar.pin`), «Copy path», «Properties». Флаг `App::menu_hidden` (идентификаторы команд, `file.new_item` прячет всё подменю «New») выкидывает пункты, лишние разделители схлопываются. `shell_menu` кладёт дерево в `ShellMenu { …, menu, inline }`, где `inline = App::shell_items_inline || Shift` (у Shift+F10 Shift не считается). `Effect::ShellMenu` и `Effect::Properties` не исполняются прямо в обработке эффекта: окно кладёт запрос в очередь своего потока и отправляет себе `WM_SHELL_UI`, а меню строится уже без заимствования обработчика, потому что модальный цикл меню прокачивает сообщения того же окна. Платформа (`context_menu.rs`) превращает дерево в `HMENU`: `AppendMenuW` с текстом «подпись\tсочетание» (Windows выравнивает сочетания колонкой), `MF_CHECKED` у отмеченных, идентификаторы с `FLIT_FIRST` = 0x8000 по порядку команд, а в конце — разделитель и пустое подменю «Show more options». Это 0,02 мс, оболочка не участвует, и `TrackPopupMenuEx(TPM_RETURNCMD)` показывает меню сразу. Выбор пункта Flit возвращается в ядро как `Event::MenuCommand(k)`, и `menu_command` запускает команду. Меню оболочки собирается, когда Windows присылает `WM_INITMENUPOPUP` для пустого подменю: `SHParseDisplayName` → `SHBindToParent` → `IShellFolder::GetUIObjectOf(IContextMenu)` для элементов или `CreateViewObject` для фона папки, затем `QueryContextMenu` прямо в это подменю с идентификаторами 1–0x7FFF, `CMF_CANRENAME` и `CMF_ASYNCVERBSTATE` (с Shift ещё `CMF_EXTENDEDVERBS`). `CMF_ASYNCVERBSTATE`, как у Проводника, разрешает обработчикам вычислять состояние глаголов позже: опрос меню файла занимает около 38 мс вместо 94. Если строить нечего, подменю получает серый пункт «No more options». При `inline` меню оболочки опрашивается до показа и ставится после пунктов Flit, глаголы, которые Flit уже показал (`open`, `cut`, `copy`, `paste`, `delete`, `rename`, `link`, `properties`), удаляются, а разделители в начале, в конце и подряд убираются. Замеры: от правого щелчка до видимого меню — 10–29 мс вместо 57–130 мс на строке и 41–54 мс на пустом месте; подменю «Show more options» — 45–105 мс. Через 0,5 с после создания первого окна поток `flit-shell-warm` один раз строит и опрашивает меню оболочки для файла (самого `flit.exe`), папки и фона папки и сразу освобождает их: библиотеки обработчиков загружаются в процесс заранее, и первое меню файла стоит 126 мс вместо 490, а меню фона папки — 30 мс вместо 233. `WM_INITMENUPOPUP` остальных подменю, `WM_DRAWITEM`, `WM_MEASUREITEM` и `WM_MENUCHAR` пересылаются в `IContextMenu3::HandleMenuMsg2` или `IContextMenu2::HandleMenuMsg`, поэтому «Отправить», «Открыть с помощью» и значки расширений работают. Глаголы `rename`, `copy`, `cut`, `paste`, `delete` и `newfolder` (`SHELL_VERBS`) Flit забирает себе через `Event::ShellVerb`: они выполняются его командами и попадают в журнал отмены. Остальное выполняет `InvokeCommand` с `CMINVOKECOMMANDINFOEX`. В лог (`FLIT_LOG`) пишется время построения меню и подменю оболочки. Свойства — `SHObjectProperties` для одного элемента и `SHMultiFileProperties` для нескольких.

**Перетаскивание.** Вместо `DragAcceptFiles` окно регистрирует `IDropTarget` (`RegisterDragDrop`; `OleInitialize` один раз на UI-поток) сразу после первого кадра и `ShowWindow`: регистрация стоит 5–9 мс, и до первого кадра её больше нет (старт до первого кадра — 22,8 мс вместо 25,8). Цель принимает только `CF_HDROP`, переводит координаты в клиентские и передаёт `DragEvent::Enter`, `Over`, `Leave` и `Drop` в `App::drag`, который возвращает эффект; `WindowHandler::drag` отвечает `DropReply { effect, caption }`, где подпись берётся из `App::drop_caption`; картинку перетаскивания рисует `IDropTargetHelper`. Куда бросают (`drop_target` → `Target` с местом подсветки `Spot`): строка папки — в эту папку (`Spot::Row`), строка файла, пустое место и полоса прокрутки — в текущую папку (`Spot::List`, рамка вокруг списка), вкладка — в её папку (`Spot::Tab`, на вкладку бросок не переключает), хлебная крошка — в её папку (`Spot::Crumb`), папка, диск или дистрибутив WSL боковой панели — в него (`Spot::Side`); «This PC» не принимает ничего. Элемент «Recycle Bin» боковой панели, вкладка с корзиной и любое место списка открытой корзины — в корзину (`Target::Trash`, эффект — перемещение, если источник его разрешает, и никакого, если среди путей есть лежащие в `$Recycle.Bin`; бросок становится `FileOp::Trash`). Заголовки колонок, строка состояния, пустое место боковой панели, поле фильтра и палитра — никуда, свободное место полосы вкладок, заголовок окна и адресная строка вне крошек — прежнее поведение (`Event::DroppedFiles`: открыть папку первого файла и выделить его). `App::drop_spot` говорит кадру, что подсветить, и строка списка, вкладка, крошка и элемент панели рисуются выделенными с обводкой цвета акцента.

**Подпись у курсора и раскрытие папок.** `drop_caption` даёт пару «шаблон, имя»: «Move to %1», «Copy to %1», «Create link in %1» по эффекту, «Move to %1» с «Recycle Bin» для корзины, «Open with %1» для программы; для прежнего поведения и запрещённого броска подписи нет. Цель хранит объект данных из `DragEnter` и пишет в него `DROPDESCRIPTION` (зарегистрированный формат `DropDescription`, `SetData` с передачей владения) только когда подпись или эффект изменились; тип картинки — эффект (`DROPIMAGE_MOVE`, `COPY`, `LINK`), `%1` оболочка заменяет именем папки и выделяет его. Перед `DragLeave` и после `Drop` описание сбрасывается в `DROPIMAGE_INVALID`, чтобы над чужим окном не осталась подпись Flit. Подпись видна у источников с картинкой оболочки (Проводник, сам Flit через `SHDoDragDrop`). Раскрытие папок: на каждом `DragEvent::Over` `spring_load` смотрит, что под курсором: строка папки (кроме корзины), другая вкладка или хлебная крошка, кроме последней. Пока это то же место, отсчёт идёт от первого `Over` над ним; через 1,3 с (`SPRING_DELAY`) строка и крошка открываются в текущей вкладке (`navigate`), вкладка становится текущей, и отсчёт начинается заново. OLE вызывает `DragOver` и без движения мыши, примерно раз в 60 мс, поэтому отдельный таймер не нужен. `Drop` раскрытие не запускает, бросок всегда идёт туда, куда указывает курсор. Эффект выбирает `choose_effect` по правилам Проводника: Alt или Ctrl+Shift — ярлык, Ctrl — копия, Shift — перемещение, без клавиш — перемещение в пределах тома (`same_volume`: тот же вид пути и тот же корень) и копия между томами, с учётом эффектов, разрешённых источником. Нельзя бросить папку в неё саму или в её подпапку и нельзя переместить элементы в ту папку, где они уже лежат. Бросок становится `FileOp::Copy`, `Move` или `Link`, то есть той же операцией с выделением результата и отменой. Перетаскивание из Flit начинается, когда мышь, нажатая на имени выделенной строки, сдвинулась на 4 пикселя: `Effect::StartDrag` через тот же отложенный `WM_SHELL_UI` вызывает `SHDoDragDrop` с объектом данных оболочки для выделенных путей (`GetUIObjectOf(IDataObject)`), поэтому приёмник получает все форматы Проводника. Щелчок по имени уже выделенной строки сужает выделение только при отпускании кнопки, иначе нельзя было бы перетащить несколько строк. Перемещение, выполненное приёмником, Flit видит через слежение за папкой. Повышенному процессу Windows (UIPI) не доставляет перетаскивание из обычных программ, и обойти это без ослабления защиты нельзя, поэтому, если `Platform::elevated` (`TokenElevation`), первое окно сразу пишет об этом в строку состояния.

**Первое перетаскивание.** Разбор первого перетаскивания свежего процесса (`bench_first_drag`, без модального цикла): `OleInitialize` — 2,6 мс, первый `CoCreateInstance(DragDropHelper)` — 8,2 мс, объект данных оболочки — 30 мс в первый раз и 2,6 мс потом, картинка перетаскивания `IDragSourceHelper::InitializeFromWindow` — 0,5–0,8 мс, `CF_HDROP` — 0,06 мс, первый `IDropTargetHelper::DragEnter` — 11,8 мс, потом — 0,006 мс, первое перемещение движком — 3,1 мс (2,4 мс из них — `ShellCom::new`), потом — 0,65 мс. В самом `flit.exe` (синтетические перетаскивания строки на папку: `.txt`, `.jpg`, `.mp4`, сразу после старта, на другой том через точку соединения, из Проводника во Flit и обратно) первое перетаскивание дороже следующих примерно на 10 мс: объект данных — 7–10 мс вместо 2,6–4, `DragEnter` помощника — 5–11 мс вместо 2,4–6; файл ложится на место через 12–31 мс после отпускания кнопки (в Проводник — около 90 мс), многосекундной задержки воспроизвести не удалось. Часть первого вызова уже снимает `flit-shell-warm`; прогрев объекта данных и картинки в фоне (1,4 мс) замерного выигрыша не дал и не добавлен. Если первое перетаскивание у пользователя заметно медленнее, вероятные причины — сторонние расширения оболочки (обработчики наложений, эскизов, `DragDropHandlers`, облачные провайдеры) в UI-потоке; для разбора в лог (`FLIT_LOG`) пишутся время создания объекта данных и модального цикла каждого перетаскивания из Flit, а вызов приёмника дольше 100 мс — предупреждением.

**Выделение рамкой.** Левая кнопка, нажатая на пустом месте списка или на колонках «Дата изменения», «Тип», «Размер» строки, взводит `Marquee` (`ui/marquee.rs`); имя строки по-прежнему начинает перетаскивание файлов. Начало рамки хранится в координатах содержимого (y плюс прокрутка), поэтому при прокрутке оно остаётся привязанным к своей строке. После сдвига на 4 пикселя включается `Drag::Marquee`, и каждое движение пересчитывает выделение заново: исходное выделение (непустое только с Ctrl) плюс строки под рамкой, а с Ctrl эти строки переключаются относительно исходного. Якорь — строка начала рамки, фокус — строка под курсором, поэтому Shift+щелчок после рамки продолжает диапазон. Пока курсор выше или ниже списка, `frame` прокручивает его со скоростью 12 выходов за край в секунду и продолжает анимацию до упора.

## Корзина

**Место.** `PathKind::RecycleBin`: `FsPath::recycle_bin()` хранит строку `shell:RecycleBinFolder`, показывается как «Recycle Bin», родителя не имеет, а `Location::to_windows()` для неё — `None`, поэтому всё, что требует папки оболочки (вставка, новая папка, пункты оболочки в меню фона, свойства), отказывает само; меню фона корзины — только пункты Flit («Sort by», «Group by», «Refresh»). `FsPath::parse` узнаёт и `shell:RecycleBinFolder`, и подпись «Recycle Bin», поэтому место сохраняется в `state.bin` и вводится в адресной строке. `open::resolve` переводит `shell:RecycleBinFolder`, `::{645FF040-5081-101B-9F08-00AA002F954E}` и `shell:::{…}` в это место до обращения к оболочке. Элемент боковой панели добавляется, если `Places::recycle_bin` (на Windows — всегда), команда палитры — `nav.recycle_bin`.

**Чтение.** `NtFs::read_dir` для `RecycleBin` вызывает `recycle::list(&recycle::roots())` (`crates/flit-platform-windows/src/recycle.rs`). Корни — `X:\$Recycle.Bin\<SID>` для каждой буквы несъёмного диска (`GetLogicalDrives`, `GetDriveTypeW`), SID — пользователь процесса (`instance::user_sid`); отсутствующий корень пропускается. Каждый корень сначала читается обычным `NtFs::read_dir` в черновой листинг: `$R<id>` даёт атрибуты (файл или папка), `$I<id>` — метаданные; элемент без второй половины не показывается. Файлы `$I…` открываются относительно дескриптора корня (`NtOpenFile` с `RootDirectory`, общий помощник `open_relative`) и читаются одним `ReadFile` в буфер потока; чтение идёт в пуле `rayon`, а на диске с seek penalty — последовательно. Формат `$I`: 8 байт версии, 8 байт размера, 8 байт FILETIME удаления, затем путь в UTF-16 — у версии 1 (Vista–8) в поле из 260 символов, у версии 2 (Windows 10+) после 4 байт длины в символах с завершающим нулём; другая версия, обрезанная запись или пустой путь отбрасываются. Запись листинга: имя — последний компонент исходного пути, размер — из `$I` (у папки это полный размер на момент удаления, ставится `SIZE_KNOWN`), время изменения и создания — время удаления, атрибуты — от `$R` без `HIDDEN` и `SYSTEM`. Замер `bench_recycle_bin_listing` на поддельной корзине: 1000 элементов — 6,3 мс, 10 000 — 61,5 мс (само чтение каталога корня — 0,4 и 4,2 мс; последовательное чтение `$I` давало 25 и 261 мс).

**Хвост записи.** `Entry` не меняется: путь `$R…` и исходная папка лежат в буфере `names` сразу за именем записи — `путь $R`, нулевой байт, `исходная папка`. `Listing::tail(i)` возвращает байты от конца имени до начала имени следующей записи, `flit_core::recycle::{push, recycled, origin, original}` пишут и читают хвост. Ключи сортировки, фильтр, `find` и изменения слежения видят только имя.

**Вид.** `App::columns()` в корзине берёт из `BIN_COLUMNS` («Name», «Original location», «Date deleted», «Size») те, что не скрыты в виде корзины; вид корзины — обычный вид папки со своим ключом, поэтому набор и ширины колонок, сортировка и группировка у неё свои. Группировка «Original location» идёт по исходной папке (`GroupField::Origin`), «Date deleted» — по времени удаления (`GroupField::Modified`). «Date deleted» сортирует по `SortField::Modified` (там время удаления), «Original location» — по новому `SortField::Origin`: байты исходной папки сравниваются, как расширения у «Type», без учёта регистра, с тем же быстрым префиксом из 8 байт. `Tab::load` сбрасывает сортировку `Origin` в обычной папке. Строка состояния корзины вместо «Folder sizes» показывает кнопки «Restore», «Restore all», «Empty Recycle Bin» (`Hit::Bin(k)`, `bin_button`); размеры подпапок в корзине не считаются. `Tab::entry_location` для записи корзины — исходный путь (его копирует Ctrl+Shift+C). Открытие записи (Enter, двойной щелчок) только пишет в строку состояния, что элемент в корзине. `item_paths` в корзине отказывает с «Items in the Recycle Bin can only be restored or deleted», поэтому копирование, вырезание, перетаскивание наружу, свойства и контекстное меню недоступны; переименование молча не начинается.

**Команды.** `restore_selection` и `restore_all` (только в открытой корзине) строят `FileOp::Restore` из пар «`$R…` → исходный путь» и идут прежним путём: прямой `MoveFileExW` с уборкой `$I…`, остаток — глагол `undelete` оболочки. `trash_selection` и `delete_selection` в корзине строят `FileOp::Purge` по выделению, вне корзины `delete_selection` — `FileOp::Delete`. `empty_bin` — `FileOp::EmptyBin` из любой папки. Все три сначала открывают диалог подтверждения Flit (`ask_confirm`), операция запускается только кнопкой «Delete».

**Выполнение.** `Delete` выполняет движок Flit (см. «Файловые операции»): дерево удаляется снизу вверх, атрибут «только чтение» снимается, ссылки на папки удаляются без захода внутрь, а отказ в доступе на верхнем элементе передаёт остаток `IFileOperation::DeleteItem` без флагов — без `FOF_NOCONFIRMATION` Windows тогда спрашивает ещё раз и запрашивает права. `Purge` и `EmptyBin` в потоке операции удаляют напрямую: `$R…` — `std::fs::remove_file` или `remove_dir_all` (ссылки не раскрываются, атрибут «только чтение» не мешает), потом парный `$I…`; путь, не имеющий вида `…\$Recycle.Bin\<SID>\$R…` (`info_file`), отвергается с ошибкой, так что вне корзины ничего не удаляется. `EmptyBin` удаляет в каждом корне все `$R…`, затем все `$I…` без пары, `desktop.ini` остаётся; если в корзине нет ни одного элемента, операция сразу возвращает «The Recycle Bin is already empty». После удаления вызывается `SHUpdateRecycleBinIcon`. Функции `list`, `purge`, `empty` и `count` получают корни аргументом, поэтому тесты гоняют их на поддельной структуре `$Recycle.Bin\S-1-…` во временной папке, а настоящую корзину не трогают.

**Обновление.** Корзина перечитывается целиком: слежение ставится на все корни и на любое уведомление отвечает `Rescan`; фокус сохраняется по имени, выделение сбрасывается.

## Единственный экземпляр

`main` до инициализации логов и до создания окна разбирает аргументы и вызывает `PipeInstance::acquire`. Именованный мьютекс `Local\flit-<SID>` определяет первичный процесс; первичный запускает поток, слушающий канал `\\.\pipe\flit-<SID>-<сеанс>` (`FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`). Канал создаётся с защищённым DACL `D:P(A;;GA;;;<SID>)`: открыть его может только владелец; если дескриптор безопасности не строится или первый экземпляр канала создать нельзя (имя заняли), слушатель пишет ошибку в лог и не запускается. Одновременно обслуживается не больше 4 клиентов (пятый получает `ERROR_PIPE_BUSY`), каждое чтение ограничено 2 с, а кадр — 256 КБ, так что молчащий или враждебный клиент не держит поток и память. Вторичный подключается к каналу с `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` (сервер не может выдать себя за клиента), повторяя попытки до 3 с, и проверяет, что сервер канала (`GetNamedPipeServerProcessId`) запущен тем же пользователем: иначе имя мог занять кто-то другой, и процесс работает самостоятельно. Только после проверки он разрешает первичному вывести окно на передний план (`AllowSetForegroundWindow`), отправляет `Hello` и `Request::Open`, дожидается `Hello` и `Reply::Accepted` и завершается. Если переслать не удалось, процесс работает самостоятельно. У процесса с повышенными правами к именам мьютекса и канала добавляется `-admin`: обычный и повышенный экземпляры живут раздельно, и команда не пересекает границу UAC. В первичном процессе команда попадает в канал, будит цикл сообщений, применяется к активному окну через `App::open`, и окно активируется.

**Гонка с завершением.** Слушатель получает не `Sender`, а `OpenSink = Arc<Mutex<Option<Sender<Open>>>>` и отправляет команду и `Accepted` под этим замком. Когда закрывается последнее окно, обработчик под тем же замком забирает `Sender` и вычерпывает канал. Если там что-то есть, он возвращает `Sender` и открывает новое окно (цикл сообщений не выходит по `WM_QUIT`, пока есть окна). Если нет, состояние сохраняется и процесс завершается, а клиент, не получивший `Accepted`, запускается сам. Принятая команда не теряется ни при каком порядке событий. В режиме `--metrics` проверка пропускается. Чтобы пересылающий процесс не грузил ненужное, `flit.exe` загружает `d3d11`, `dcomp`, `dwrite`, `dwmapi`, `imm32`, `ole32`, `oleaut32`, `shell32` и `combase` отложенно (`/DELAYLOAD` в `crates/flit/build.rs`). Время жизни пересылающего процесса — около 28,5 мс против 24,1 мс у пустого `where.exe` на той же машине, то есть собственная цена Flit около 4–5 мс сверх `CreateProcess`; от входа в `main` до выхода — меньше 1 мс. Метрика «старт → первый кадр» отсчитывается от входа в `main`, поэтому после перехода на отложенную загрузку она выросла с 22–24 до 28–29 мс: загрузка графических DLL переехала из загрузчика внутрь измеряемого интервала. Полное время от `CreateProcess` до первого кадра от этого расти не должно, но отдельно оно не измерялось.
Подробности — в [docs/design/external-open.md](docs/design/external-open.md).

## WSL

Папка WSL — `Location::Wsl { distro, path }`, её принимают формы `wsl://D/путь`, `\\wsl.localhost\D\...` и `\\wsl$\D\...`. Хлебные крошки: «This PC › D (WSL) › …», родитель корня дистрибутива — «This PC». Имя дистрибутива ограничено `[A-Za-z0-9._-]{1,64}` без `.` и `..` (`location::valid_distro`), иначе путь остаётся обычным UNC; `Location::canonicalize` в `App::dispatch` приводит его к написанию из реестра.

**Агент.** `flit-wsl-agent` — `[[bin]]` крейта `flit-platform-linux`, статический бинарник `x86_64-unknown-linux-musl`, слинкованный `rust-lld` с Windows. `crates/flit/build.rs` собирает его вложенным `cargo build --profile wsl-agent` в `<target>/wsl-agent` (или берёт из `FLIT_WSL_AGENT_X64`, `FLIT_WSL_AGENT_ARM64`) и встраивает в `flit.exe` как `AGENTS: AgentImages` с идентификатором `<версия>-<16 hex SHA-256>` (`flit_proto::build_id`, тот же файл через `#[path]`). Агент считает свой идентификатор от `/proc/self/exe`. `WslLauncher` выбирает образ по родной архитектуре (`IsWow64Process2`) и запускает `%SystemRoot%\System32\wsl.exe -d D --exec /bin/sh -c 'exec "${XDG_CACHE_HOME:-$HOME/.cache}/flit/agent-<id>"'` с `CREATE_NO_WINDOW` и сразу помещает процесс в общий Job object с `KILL_ON_JOB_CLOSE`; доставка — тот же `wsl.exe` со скриптом `cat > tmp; chmod 700; mv -f` и бинарником в stdin. Внутри агент (`agent::serve`) отвечает на `List` пачками `getdents64` + `statx` (сырой системный вызов: в musl нет обёртки, при `ENOSYS` — `fstatat`), на `Watch` — через общий `Inotify` с одним дескриптором на каталог и склейкой за 50 мс, на `DirSizes` — обходом без разыменования ссылок, на `Op::Trash` — корзиной freedesktop (`info/*.trashinfo` с `O_EXCL`, затем `rename`; домашняя корзина или `.Trash/$uid`, `.Trash-$uid` на других томах). Пути, не являющиеся абсолютными путями Unix, и недопустимые имена в `DirSizes` агент отвергает сам.

**Дистрибутивы.** `Platform::wsl_distros` читает подключи `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss` с `State = 1` и допустимым именем; `Platform::watch_wsl` на Windows запускает поток `flit-lxss-watch`, который по `RegNotifyChangeKeyValue` просит `flit-places` перечитать данные. `NtFs::volumes` добавляет после дисков строку на дистрибутив (`DIR | VOLUME`), так что «This PC» открывает `wsl://D/` через `Location::join`. Ни перечисление, ни «This PC» дистрибутив не запускают. Подробности — в [docs/design/wsl.md](docs/design/wsl.md).

## Протоколы (`flit-proto`)

**Транспорт.** Кадр — длина `u32` little-endian и полезная нагрузка postcard, не больше 16 МБ (`read_frame_limited` позволяет задать меньший предел, протокол единственного экземпляра использует 256 КБ); длина проверяется до выделения памяти. Первый кадр в обе стороны — `Hello { magic: "FLIT", protocol, version, build }`, где `protocol` — `Index`, `Provider` или `Instance`. `read_hello` ограничивает приветствие 256 байтами и любой мусор (например, текст ошибки `wsl.exe` в UTF-16) превращает в `NotFlit`; несовпадение версий даёт `VersionMismatch` с версией и сборкой собеседника. Ошибки: `Io`, `Decode`, `TooLarge`, `NotFlit`, `VersionMismatch`, `Invalid`.

**Протокол единственного экземпляра** (версия 1): `Request::Open(Open)` → `Reply::Accepted`.

**Протокол агента-провайдера** (версия 2, канал `WslProvider` ↔ `flit-wsl-agent` через stdio `wsl.exe`): запросы `List`, `Stat`, `Watch`, `DirSizes`, `Op`, `Cancel`, `Shutdown`; события `Entries { batch }`, `ListDone`, `Stat`, `Changes`, `Rescan`, `DirSize`, `OpDone { id, error: Option<String> }`. Пути в запросах — `FsPath`, проверяемый при десериализации. В `Hello.build` — идентификатор сборки агента; Flit принимает только свой.

**Протокол индекса** (`flit-search::proto`, версия 1): `Query { gen, text, sort }` → `QueryDone { gen, total }` и сразу первая страница `Rows` (64 строки); `GetRows { gen, from, to }` → `Rows { gen, from, entries, dirs }` (не больше 1024 строк, `dirs` — папки строк). Служба сама присылает `IndexStatus { volumes }`, когда меняется состояние томов, и повторный `QueryDone` того же поколения, когда изменился индекс; ошибка разбора запроса приходит как `Error { message }`. Канал — `\\.\pipe\flit-indexd`, подробности в разделе «Поиск».

**`EntryBatch`** — общий формат записей для всех протоколов: буфер имён и массив `WireEntry { name_len, meta }`. `entries(windows_names)` проверяет, что сумма длин (без переполнения) равна длине буфера и что имена не пустые, не `.` и `..` и не содержат `/` или NUL, а при `windows_names` ещё `\` и `:`, поэтому враждебный собеседник не может подсунуть путь вместо имени. Атрибуты вне `WIRE_ATTRS` (каталог, скрытый, системный, только чтение, ссылка) — внутренние биты вроде «удалён» или «размер известен» — отвергаются. `Event::validate(windows_names)` проверяет так же имена и метаданные в `Entries`, `Changes` и `Stat`; это обязанность того, кто примет события от удалённого агента. `append_to` дописывает пакет в `Listing`.

## Рендеринг

**Ядро строит, платформа рисует.** `App::frame(&mut Gfx<B>)` каждый кадр заново собирает `DrawList` — вектор экземпляров — только для видимой части интерфейса. Временные строки кадра (даты, размеры, типы) живут в арене `bumpalo`, которая сбрасывается каждый кадр. Платформенный `Renderer` умеет три вещи: изменить размер, загрузить прямоугольник в атлас и нарисовать `DrawList`.

**Один шейдер, один вызов отрисовки.** Экземпляр — 64 байта: прямоугольник, UV, прямоугольник отсечения (по `float4`), цвет RGBA8, радиус скругления, толщина рамки, вид (заливка, глиф, изображение). Всё рисуется одним `DrawInstanced(4, n)` полосой треугольников и одним шейдером `ui.hlsl`, который `build.rs` компилирует через `D3DCompile`, а результат встраивается через `include_bytes!`. Вершинный шейдер строит четырёхугольник по `SV_VertexID`; пиксельный отсекает по прямоугольнику экземпляра, рисует скруглённые прямоугольники и рамки через SDF со сглаживанием, глифы — по альфе атласа с кривой контраста, изображения — как RGBA с предумноженной альфой.

**Атлас.** Одна текстура RGBA8 2048×2048 для глифов и значков, упаковка полками с отступом 1 пиксель. Новые прямоугольники копятся в `Gfx::uploads` и загружаются `UpdateSubresource` перед отрисовкой. При переполнении атлас сбрасывается целиком вместе с местами значков: глифы растеризуются заново, значки загружаются из копий в памяти, а `App::frame` сразу строит кадр ещё раз, так что список примитивов со ссылками на старые места атласа на экран не попадает.

**Перерисовка только по изменению.** События и результаты рабочих потоков ставят флаг `dirty`, обработчик заказывает кадр, только если `App::needs_redraw()`. `App::frame` возвращает «анимация продолжается» (плавная прокрутка, непустая очередь изменений, сброс атласа, первые 300 мс загрузки), и тогда сразу заказывается следующий кадр. В остальное время цикл сообщений спит.

**Устройство.** Одно устройство D3D11 на процесс, общее для всех окон: `Renderer::device` создаёт устройство вместе с шейдерами и состояниями конвейера, `Renderer::new(device, window)` — swap chain и ресурсы окна. Устройства создаёт поток `flit-gpu` параллельно с остальным запуском: сначала программное WARP, затем аппаратное. Первый кадр рисуется на том, что готово раньше (UI-поток ждёт, только если не готово ни одно); когда приходит аппаратное устройство, окна, рисовавшие через WARP, пересоздают рендерер на нём, и программное устройство освобождается. Если аппаратное устройство создать не удалось, окна остаются на WARP.

**Swap chain и темп кадров.** Swap chain для композиции: `FLIP_DISCARD`, два буфера, `DXGI_SWAP_CHAIN_FLAG_FRAME_LATENCY_WAITABLE_OBJECT`, `SetMaximumFrameLatency(1)`; окно с `WS_EX_NOREDIRECTIONBITMAP`, swap chain выводится через визуал DirectComposition. Цикл сообщений для окон, ждущих кадра, вызывает `MsgWaitForMultipleObjectsEx` по их кадровым объектам ожидания вместе с вводом: ввод обрабатывается, пока ожидание не сработало, а кадр строится сразу после сигнала, поэтому отражает самый свежий ввод. Вывод — `Present(1, 0)` с вертикальной синхронизацией.

**Плавное изменение размера.** `WM_SIZE`, в том числе внутри модального цикла перетаскивания рамки, превращается в `Event::Resized`, после чего вызываются `ResizeBuffers` и синхронная перерисовка в том же сообщении: растянутых и пустых кадров нет. `WM_DPICHANGED` меняет масштаб, раскладка считается в физических пикселях.

Кадровый объект ожидания принадлежит рендереру (RAII-обёртка закрывает дескриптор); когда рендерер уничтожается, он убирает свой дескриптор из состояния окна, и цикл сообщений перерисовывает окно без ожидания, пока не появится новый. Контекст устройства привязан к потоку: рендереры создаются только в том потоке, где создан первый, и сами не `Send`.

**Потеря устройства.** Если любой вызов кадра (`Present`, `Map`, `GetBuffer`, `CreateRenderTargetView`, `CreateBuffer`, `ResizeBuffers`) вернул `DXGI_ERROR_DEVICE_REMOVED`, `DXGI_ERROR_DEVICE_RESET` или `DXGI_ERROR_DEVICE_HUNG` либо `GetDeviceRemovedReason` сообщает об ошибке, обработчик выбрасывает рендерер окна, для аппаратного устройства сразу создаёт новое (если не вышло, создаётся программное WARP, чтобы окно не осталось пустым) и заказывает кадр. Устройство пересоздаёт только первое окно, заметившее потерю: у окон есть номер поколения устройства, и остальные окна со старым номером просто перестраивают рендерер на уже новом устройстве; следующий кадр создаёт swap chain заново и сбрасывает атлас, так что глифы и значки загружаются в новую текстуру.

**Собственный заголовок.** Полоса вкладок занимает область заголовка. `WM_NCCALCSIZE` убирает стандартный заголовок (с поправкой на развёрнутое окно), `WM_NCHITTEST` спрашивает `App::hit_test` и отвечает `HTCAPTION`, `HTMINBUTTON`, `HTMAXBUTTON`, `HTCLOSE` или `HTTOP` для полосы изменения размера сверху. Благодаря этому система сама перемещает окно, разворачивает его двойным щелчком и показывает Snap Layouts над кнопкой «развернуть»; нажатия на кнопки заголовка приходят как неклиентские сообщения и переводятся в обычные события мыши для подсветки. Тёмный заголовок — `DWMWA_USE_IMMERSIVE_DARK_MODE`.

**Миниатюры.** Вторая текстура RGBA8 4096×4096 (64 МБ, `flit_core::thumbs::THUMB_ATLAS`) создаётся при первой миниатюре и подключена к шейдеру как `t1`; вид экземпляра 3 (`kind::THUMB`) берёт цвет из неё. `ThumbAtlas` в `Gfx` делит её на 64 страницы 512×512, у страницы класс размера ячеек — 64, 128, 256 или 512 пикселей; миниатюра ложится в ячейку наименьшего подходящего класса. У ячейки метка кадра последнего показа: место берётся из свободной ячейки своего класса, затем из нетронутой страницы, затем у давно не показанной ячейки своего класса, затем вся давно не показанная страница другого класса меняет класс; показанное в текущем кадре не вытесняется никогда. Новые миниатюры копятся в `ThumbAtlas::uploads` и загружаются `UpdateSubresource` в нужный прямоугольник перед отрисовкой; новый рендерер (смена устройства) очищает атлас, и миниатюры запрашиваются снова.

## Текст

Трейт `TextBackend` в `flit-core` — три синхронные операции: `shape` (строка и стиль → глифы с индексом шрифта, номером глифа, позицией и смещением кластера в байтах UTF-8, плюс ширина), `rasterize` (`GlyphKey`: шрифт, глиф, кегль в четвертях пикселя, субпиксельный сдвиг в четвертях пикселя → 8-битная маска покрытия) и `metrics` (подъём и спуск).

`DWriteText` на Windows:

- фабрика `IDWriteFactory2`; шрифт интерфейса — Segoe UI Variable Text, иначе Segoe UI; значки — Segoe Fluent Icons, иначе Segoe MDL2 Assets;
- раскладка через `IDWriteTextLayout` (подстановка шрифтов, двунаправленный текст, лигатуры, кластеры), которая «рисуется» в собственный `IDWriteTextRenderer`, собирающий прогоны глифов; шрифты интернируются в индексы, карта кластеров переводится в смещения UTF-8 для курсора и попадания мышью в адресной строке;
- растеризация через `IDWriteGlyphRunAnalysis` (`NATURAL_SYMMETRIC`, сглаживание в оттенках серого, текстура 1×1), четыре субпиксельные позиции по горизонтали; покрытие кладётся в атлас во все четыре канала.

`Gfx` кэширует разложенные строки (ключ — хеш строки и стиля, кэш очищается после 50 000 записей), глифы (`GlyphKey` → место в атласе или пусто для пробельных) и метрики шрифтов. Усечение с многоточием считается в ядре.

## Путь «ввод → кадр»

1. Оконная процедура переводит сообщение Win32 в `flit_core::input::Event`: клавиши — по коду виртуальной клавиши с модификаторами из `GetKeyState` (`VK_OEM_3`, клавиша слева от 1, — ``Key::Char('`')`` на любой раскладке), символы — из `WM_CHAR` с учётом суррогатных пар (символ отбрасывается, только если зажат ровно один из Ctrl и Alt, поэтому символы AltGr, то есть Ctrl+Alt, доходят до быстрого перехода и адресной строки, а сочетания Ctrl+A/C/X/V в адресной строке требуют Ctrl без Alt), мышь — в клиентских пикселях, неклиентские нажатия на кнопки заголовка — в обычные. Событие кладётся в очередь окна и тут же доставляется `Handler::event` → `App::on_event`.
2. `App` синхронно меняет состояние (выделение, фокус, цель прокрутки, текст адресной строки), ставит `dirty` и добавляет эффекты: запросы провайдеру, `Resort`, `Icon`, `TypeName`, буфер обмена, команды окна, заголовок, курсор, новое окно.
3. `Handler::flush` исполняет эффекты (отправка в канал или дешёвый вызов Win32) и, если нужно, заказывает кадр.
4. Цикл сообщений дожидается кадрового объекта ожидания и вызывает `Handler::redraw` → `App::frame`: забрать снимки, применить изменения в пределах 4 мс, сдвинуть прокрутку (экспоненциальное приближение к цели с постоянной 45 мс), разложить интерфейс, построить `DrawList`. Затем — загрузка новых прямоугольников атласа, отрисовка и `Present`.
5. Асинхронные результаты (снимки, события провайдера, значки, названия типов, сортировки) будят цикл через `WM_WAKE`; `Handler::woken` раскладывает их по окнам, и при необходимости заказывается кадр.

Значки: пока значка нет, рисуется глиф-заглушка и выпускается `Effect::Icon`. Ключ значка — расширение (общий значок типа), отдельный файл для `exe`, `ico`, `lnk`, `url`, `cur`, `ani`, папка или конкретный диск. Поток оболочки пропускает запрос, если строка ушла дальше чем на 32 строки от видимой области. Типовые значки и папки берутся из системного списка изображений (`SHGetFileInfoW` + `SHGetImageList`); его ленивую инициализацию `ShellCom::new` выполняет под общим замком, потому что при одновременном первом вызове из двух потоков `SHGetFileInfoW` возвращает 0 и значок типа навсегда остался бы заглушкой. Значки отдельных файлов и дисков — через `IShellItemImageFactory`. Название типа запрашивается один раз на расширение (`SHGetFileInfoW` с `SHGFI_TYPENAME`) и рассылается во все окна.

## Боковая панель

Код панели — `crates/flit-core/src/ui/sidebar.rs`, рабочий поток — `crates/flit/src/places.rs`, системная часть — `crates/flit-platform-windows/src/places.rs`. Всё, что добавлено для навигации, подключается к `App` через один модуль-концентратор `ui/nav.rs` (`App::nav: Nav` с панелью, палитрой, прямоугольниками фильтра и стеком закрытых вкладок): `layout`, `hit`, `key`, `char_input`, колесо, нажатия мыши и `frame` вызывают по одной функции оттуда.

Секции: Pinned, Folders, Drives, WSL. Пустые секции не показываются, кроме Pinned, у которой тогда подсказка «Ctrl+D pins the current folder». Элементы (`Item`: секция, подпись, глиф, `Location`, доля занятого места диска) пересобираются только при изменении данных (`Sidebar::rebuild`), прямоугольники строк — в `App::layout`; кадр рисует готовые строки, подписи проходят через общий кэш сформированного текста, так что в установившемся состоянии панель не добавляет к кадру формирования текста. Строки вне видимой части панели не рисуются. Список, заголовок колонок и поле фильтра сдвигаются вправо на ширину панели (`App::content_origin`); заголовок окна, панель инструментов и строка состояния остаются во всю ширину.

Данные — `Places { folders, drives, wsl, recycle_bin, templates }` за `Arc` (`templates` — шаблоны «Создать», см. «Файловые операции»), их собирает поток `flit-places` (`PlacesWorker`); `recycle_bin` (на Windows — всегда) добавляет в конец Folders элемент «Recycle Bin», на который можно бросать файлы (см. «Корзина»):

- известные папки — `Platform::known_folder("shell:Profile")`, `shell:Desktop`, `shell:Downloads`, `shell:Personal`, `shell:My Pictures`, `shell:My Music`, `shell:My Video`; если `shell:Profile` не разрешился, Home берётся из `Platform::home`;
- диски — новая функция трейта `Platform::drives` (`GetLogicalDrives`, `GetDriveTypeW`, `GetVolumeInformationW`, `GetDiskFreeSpaceExW`); подпись «Метка (C:)» или тип диска, если метки нет; у сетевых дисков том и место не запрашиваются, чтобы недоступный сервер не держал панель;
- дистрибутивы — новая функция `Platform::wsl_distros`: перечисление `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss\*` и значение `DistributionName`, только чтение; элемент открывает `wsl://<имя>/`.

Поток создаётся после первого кадра (`PlacesWorker::start_once` в конце `Handler::render`), чтобы не отнимать время у старта; до первого ответа панель показывает только закреплённые папки. Результат приходит через канал и `Wake`, `Handler::drain` раздаёт один `Arc<Places>` всем окнам. Подключение и извлечение устройства (`WM_DEVICECHANGE` с `DBT_DEVICEARRIVAL` или `DBT_DEVICEREMOVECOMPLETE`) превращается в `Event::DevicesChanged` → `Effect::RefreshPlaces` → новый запрос потоку; запросы, накопившиеся в очереди, схлопываются в один. На Linux `drives` и `wsl_distros` возвращают пустые списки.

Закреплённые папки общие для процесса: изменение выпускает `Effect::Pinned(список)`, `Handler` передаёт список остальным окнам (`App::set_pinned`) и запоминает в `Saved`. Ширина и видимость панели у каждого окна свои, в `state.bin` попадает состояние окна, закрытого последним, как и ширины колонок. Ширина хранится в логических пикселях в пределах 160–480 и на экране не превышает половины окна.

Подсвечен элемент, чья `Location` совпадает с текущей папкой вкладки. Щелчок открывает элемент через общую `dispatch` с `OpenTarget::CurrentTab`, средняя кнопка и Ctrl+щелчок — с `OpenTarget::NewTab`. Перетаскивание закреплённой папки начинается после сдвига на 5 пикселей (`Drag::PinMove`), линия показывает место вставки, отпускание переставляет и выпускает `Effect::Pinned`. Разделитель — `Drag::Splitter`. Фокус клавиатуры на панели — `Focus::Sidebar` со своим курсором; F6 переключает фокус между панелью и списком. Файлы, брошенные на закреплённую или известную папку, диск или дистрибутив WSL, копируются или перемещаются в него, на «Recycle Bin» — уходят в корзину; элемент подсвечивается, пока над ним курсор (`Spot::Side`, см. «Файловые операции»). Закрепить и открепить выделенные папки можно и из контекстного меню (`item.pin`).

## Фильтр в папке

`NameFilter` (`crates/flit-core/src/filter.rs`) хранит образец в нижнем регистре, признак шаблона, вектор `matched` по стабильным индексам листинга и готовый список видимых строк `rows` — подпоследовательность `snap.order`. `DirView::rows()` с фильтром отдаёт `rows` фильтра, без него — `snap.order`, поэтому отрисовка, прокрутка, быстрый переход, диапазонное выделение и подсчёт строк работают с отфильтрованным порядком без изменений. `DirView::is_visible` учитывает `matched`, а `prune` после каждой перефильтрации убирает скрытые строки из выделения, фокуса и якоря: Delete, Enter и Ctrl+Shift+C действуют только на видимое.

Без `*` и `?` образец ищется как подстрока имени без учёта регистра; с ними образец сопоставляется со всем именем (`*` — любая последовательность, `?` — один символ). Для ASCII-имён и ASCII-образцов сравнение идёт по байтам без выделения памяти; остальные имена переводятся в нижний регистр в один переиспользуемый буфер.

Перефильтрация (`DirView::refilter`) вызывается везде, где меняется `order`: очередной снимок той же загрузки (`replace`), изменения слежения (`apply_all`), результат фоновой пересортировки (`merge_order`), размер подпапки. Имя по индексу не меняется (новые и переименованные элементы получают новый индекс), поэтому совпадения считаются только для новых индексов, а `rows` перестраивается одним проходом по `order`. Если новый образец без шаблонов содержит предыдущий (пользователь дописал символ), проверяются только прежние совпадения. На 100 000 записей любое нажатие укладывается в единицы миллисекунд (бенчмарки `filter_100k_*`, тест `filters_100k_entries_instantly`), поэтому фильтр работает синхронно в UI-потоке.

Текст фильтра хранится во вкладке (`Tab::filter: Option<Field>`), у каждой вкладки свой. `Tab::load` в другую папку сбрасывает фильтр, а новый `DirView` после перезагрузки той же папки (F5, переполнение буфера слежения) получает прежний текст. Поле фильтра — полоса над заголовком колонок; `Focus::Filter` отдаёт полю клавиши редактирования, Enter и стрелки переводят фокус в список, Esc очищает и закрывает. Строка состояния при активном фильтре — «N of M items», пустой результат — «No items match the filter.».

## Палитра команд и реестр действий

Реестр — статический срез `ACTIONS` в `crates/flit-core/src/ui/actions.rs`: `Action { id, title, keys: &[Chord], run: fn(&mut App, Instant) }`. Новая команда — одна строка в срезе, например:

```
Action::new("tab.new", "New tab", &[ctrl(Key::Char('T'))], |a, now| a.new_tab_here(now)),
```

Сочетания клавиш и палитра читают один и тот же реестр: `App::key` после обработки адресной строки, палитры, фильтра и панели вызывает `run_bound`, который ищет точное совпадение клавиши и модификаторов. В `App::key` остались только переключение вкладок по номеру, Ctrl+Space, клавиши «Назад»/«Вперёд» и перемещение фокуса по списку: у них либо диапазон клавиш, либо зависимость от модификаторов, которую одна строка реестра не выражает. Тест проверяет, что сочетания в реестре не повторяются и что клавиши файловых операций и поиска (Ctrl+C/X/V, Ctrl+Shift+V, F2, Ctrl+Shift+N, Ctrl+Shift+I, Ctrl+Alt+C, Ctrl+\`, Ctrl+Shift+\`, Ctrl+Z/Y, Alt+Enter, Ctrl+E, Ctrl+Shift+F) закреплены за своими командами, и что каждая команда выполняется без окна. `App::run_action(id)` запускает команду по идентификатору.

Палитра (`ui/palette.rs`) — модальный слой поверх окна: пока она открыта, все клавиши идут ей. Слой обобщён режимом `Pick`: `Commands` (реестр), `NewItem` (выбор нового элемента, Ctrl+Shift+I) и поля ввода `Shortcut`, `Stream` и `FolderIcon`, у которых нет списка, а Enter передаёт текст `submit_pick`; заголовки и подписи справа (сочетания или расширения) хранятся в самой палитре. Подходящие команды пересчитываются на каждое нажатие (98 названий): подстрока даёт 2001–4000 очков (выше — ближе к началу, ещё +1000 — с начала слова), нечёткое совпадение — не больше 1999, причём каждая буква запроса должна начинать слово названия или идти сразу за предыдущей совпавшей. При равенстве очков сохраняется порядок реестра. Текст сочетаний (`keys_text`) вычисляется один раз при открытии. Щелчок мимо палитры закрывает её, колесо прокручивает список.

## Поиск

Поиск по именам всех файлов устроен как у Everything: индекс живёт в памяти процесса-владельца (служба `flit-indexd` или запасной индекс внутри `flit.exe`), запрос — это параллельный проход по одному блобу имён, а интерфейс получает только видимые строки.

### Индекс (`flit-search::index`)

`VolumeIndex` — один том в виде структуры массивов. На запись: `ids` (FRN на NTFS, `FileId` при обходе), `parent_ids`, `parents` (индекс родителя или `NONE`), исходные имена в общем буфере `names` (`name_off`, `name_len`), имена в нижнем регистре в блобе `lower`, где каждое имя завершается `\0` (`lower_off`, `lower_len`), `sizes`, `modified` (FILETIME UTC), `attrs` (каталог, скрытый, системный, только чтение, ссылка и внутренние биты «удалён» и «корень»). Таблица сегментов `seg_start`/`seg_entry` сопоставляет позицию в блобе записи. Пути не хранятся: `path_into` собирает путь по цепочке родителей (не глубже 1024) только для строк, которые показываются, и для условий `path:`. Четыре заранее отсортированных порядка `perms` (имя, путь, размер, дата изменения) и обратные к ним `ranks` дают сортировку результатов без сортировки во время запроса.

Изменения (`IndexSink::upsert`/`remove`) копятся и применяются в `commit`. Новое или переименованное имя дописывается в конец блоба, старый сегмент становится мёртвым. Запись, чей родитель ещё не пришёл, ждёт его как «сирота» и подключается при следующем `commit`; удаление каталога каскадно удаляет его поддерево; повторное появление записи с тем же идентификатором в той же пачке её воскрешает. Порядки имени, размера и даты поддерживаются слиянием отсортированных изменённых записей с прежним порядком, порядок пути перестраивается обходом в глубину по детям, отсортированным по имени. Когда мёртвых байтов больше четверти блоба и больше 1 МБ, блоб уплотняется, а `epoch` увеличивается.

### Движок запросов (`flit-search::query`, `flit-search::engine`)

`query::parse` превращает текст в `Query` — список условий, объединённых по «И»: подстрока, шаблон с `*`/`?` или регулярное выражение по имени или пути, `ext:`, `size:` и `dm:` (полуоткрытые интервалы; даты считаются по местному времени со смещением UTC клиента), отрицание `!`, кавычки для буквального текста. Ведущим выбирается самый длинный положительный литерал по имени: `memchr::memmem::Finder` ищет его прямо в блобе `lower`, блоб делится на куски не меньше 4096 сегментов и обрабатывается пулом `rayon`, совпадение переводится в запись двоичным поиском по таблице сегментов, остальные условия проверяются только у кандидатов. Без ведущего литерала записи просматриваются тем же параллельным проходом. Отмена — замыкание, которое в начале каждого куска сравнивает поколение запроса с последним пришедшим.

Если совпадений не больше 65 536, они сортируются по `ranks` нужного порядка. Если больше, совпадения отмечаются в битовой карте, а строки выдаются ленивым проходом по готовому порядку, так что первые строки готовы сразу. Результаты нескольких томов сливаются по требованию (k-путевое слияние в `ResultSet::ensure`). Пустой запрос сразу отдаёт готовый порядок: 25 мкс на 10 млн записей. Замеры на синтетических данных — в README («Бенчмарки»): на 1 млн записей нажатие обходится в 0,3–2 мс, на 10 млн — в 3–20 мс; дороже всего `path:` (12 и 160 мс) и регулярные выражения (5 и 50 мс), потому что им нужен путь или полное сравнение для каждой записи.

### Источники индекса (`IndexSource`)

**`MftIndex`** (`flit-platform-windows/src/mft.rs`). Для NTFS-тома при правах администратора открывается `\\.\C:`. Сначала `FSCTL_QUERY_USN_JOURNAL` даёт контрольную точку (идентификатор журнала и `NextUsn` до начала чтения), затем читаются записи `$MFT`: `FSCTL_GET_NTFS_VOLUME_DATA` даёт геометрию, запись 0 — список экстентов `$DATA` самой `$MFT`, экстенты читаются последовательно кусками по 4 МБ в буфер, выровненный по 4096 байт. У каждой записи проверяется и снимается защита секторов (update sequence), из `$STANDARD_INFORMATION` берётся время изменения, из безымянного `$DATA` — размер (длина резидентного значения или `DataSize` первого экстента), из `$REPARSE_POINT` — тег точки повторной обработки; размер из записей-расширений переносится в базовую запись. Затем `FSCTL_ENUM_USN_DATA` перечисляет все записи (`USN_RECORD_V2` и `V3`) с именем, родителем и атрибутами, и размер с датой подставляются по номеру записи с проверкой порядкового номера. Метафайлы (записи 0–15) и всё под `$Extend` не индексируются. Изменения раз в 500 мс читаются `FSCTL_READ_USN_JOURNAL` с контрольной точки и схлопываются по FRN до последнего состояния: удаление — `remove`; старое имя переименования без нового в той же пачке — ничего (новое придёт следующим); остальное — `upsert` со свежими размером, датой и атрибутами через `OpenFileById` и `GetFileInformationByHandle`. Другой идентификатор журнала, точка раньше `FirstUsn` или `LowestValidUsn`, `ERROR_JOURNAL_ENTRY_DELETED`, `ERROR_JOURNAL_NOT_ACTIVE` или `ERROR_JOURNAL_DELETE_IN_PROGRESS` означают пересканирование. Если том не NTFS, прав нет, журнал выключен или `$MFT` не читается, том индексируется через `WalkIndex`.

**`WalkIndex`** (`walk_index.rs`). Идентификатор записи — `FileId` из `FileIdBothDirectoryInformation` (на NTFS это FRN). Обход — 8 потоков `std::thread::scope` с общей очередью папок. До начала обхода на корень ставится рекурсивный `ReadDirectoryChangesExW` с `FILE_NOTIFY_EXTENDED_INFORMATION` (идентификаторы записи и родителя, размер, время, атрибуты), поэтому изменения во время обхода не теряются. Пары переименования сводятся в одно перемещение, у появившейся папки обходится поддерево, переполнение буфера или нулевой идентификатор означают пересканирование. Продолжить с контрольной точки другого процесса `WalkIndex` не может и просит пересканирование.

### Драйвер индекса и снимки

`flit_platform::start_indexer(source, shared, snapshots)` запускает поток `flit-indexer`. Первый проход тома пишет прямо в общий индекс, сбрасывая накопленное не чаще чем раз в max(250 мс, 4 × цена последнего сброса), так что искать можно с первых секунд. Повторный проход тома, в котором уже есть данные, строит отдельный `VolumeIndex` и подменяет им старый в конце, поэтому поиск во время пересканирования продолжает работать. Ошибка источника ставит тому `VolumeState::Error` и повтор через 30 с. Состояние томов (`IndexStatus`) публикуется в `SharedIndex`.

Снимок (`flit-search::snapshot`) пишется после каждого завершённого прохода и не чаще раза в 5 минут, если индекс менялся: заголовок (`FLITIDX\0`, версия, контрольная точка, идентификатор тома, корень, разделитель), затем записи (идентификатор, родитель, размер, время, атрибуты, имя) и FNV-1a 64 всего содержимого; запись идёт во временный файл с переименованием поверх, имя файла — хеш идентификатора тома. При старте драйвер загружает снимок, сразу отдаёт его поиску (том в состоянии `Ready`) и продолжает с контрольной точки через `changes`; если источник отказывается (`Ok(None)`), том пересканируется в фоне. Снимок, контрольная точка которого сохранена вместе с данными, согласован сам с собой, поэтому при остановке службы ничего дописывать не нужно: всё, что случилось после снимка, догоняется по журналу USN.

Формат собственный, а не rkyv + memmap2: в файле только первичные поля, а блоб в нижнем регистре, таблица сегментов и порядки строятся при загрузке (около 0,3 с на миллион записей). Файл не зависит от раскладки структур в памяти, переживает их изменения без миграций, проверяется целиком до использования и не добавляет зависимостей; отображение без копирования сэкономило бы эти доли секунды, но привязало бы файл к раскладке `VolumeIndex`.

### Сессия и протокол

Каждое подключение обслуживает `Session` (`flit-search::session`) над общим `SharedIndex` (`RwLock<Engine>`). `Query` разбирается с часами и смещением UTC, выполняется, и в ответ сразу идут `QueryDone { gen, total }` и первая страница `Rows` из 64 строк, так что первый экран приходит за один обмен. `GetRows` возвращает до 1024 строк из того же набора результатов; запросы чужого поколения игнорируются. Набор результатов живёт в сессии, клиент держит только видимые строки. Раз в 250 мс сессия шлёт `IndexStatus`, если состояние томов изменилось, и не чаще раза в секунду перевыполняет текущий запрос, если индекс изменился, отправляя повторный `QueryDone` того же поколения и первую страницу; клиент воспринимает его как обновление. Ошибка разбора (неверная дата или регулярное выражение) приходит как `Error` перед `QueryDone { total: 0 }`.

### Служба и безопасность канала

`flit-indexd` слушает `\\.\pipe\flit-indexd` (overlapped-ввод-вывод, чтобы чтение и запись шли из разных потоков одновременно). Канал создаётся с `FILE_FLAG_FIRST_PIPE_INSTANCE` (если имя уже занято, служба не запускается) и `PIPE_REJECT_REMOTE_CLIENTS`. DACL: в консольном режиме `D:P(A;;GA;;;<SID>)`, под SYSTEM — `D:P(A;;GA;;;SY)(A;;0x12008b;;;IU)`: интерактивные пользователи могут читать и писать, но не создавать свои экземпляры канала с тем же именем. Сервер проверяет SID процесса клиента (`GetNamedPipeClientProcessId`): в консольном режиме пускается только тот же пользователь. Клиент подключается с `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` (служба не может действовать от его имени) и проверяет, что сервер канала (`GetNamedPipeServerProcessId`) работает под SYSTEM или под тем же пользователем.

Ограничения: не больше 16 клиентов одновременно (следующий ждёт свободного места), `Hello` — в течение 2 с, запрос — не больше 64 КБ; между запросами клиент может молчать сколько угодно, но начатый кадр должен прийти целиком за 2 с. От клиента принимаются только `Query` и `GetRows`, всё остальное, мусор и несовпадение версии разрывают соединение. На клиента два потока: `flit-indexd-client` читает запросы, `flit-indexd-session` выполняет их и пишет ответы.

Без `--console` `main` вызывает `Service::run`: `StartServiceCtrlDispatcherW`, в `ServiceMain` — `RegisterServiceCtrlHandlerExW`, `SERVICE_RUNNING` и тело службы. `SERVICE_CONTROL_STOP` и `SHUTDOWN` переводят службу в `STOP_PENDING`, затем `STOPPED` и завершают процесс. Запуск не из диспетчера (`ERROR_FAILED_SERVICE_CONTROLLER_CONNECT`) даёт понятную ошибку с подсказкой про `--console`.

### Фильтрация по правам

Запись видна клиенту, если он может просматривать содержимое её родительской папки (`FILE_LIST_DIRECTORY`); права на папки выше не важны, потому что проверка обхода в Windows по умолчанию отключена (`SeChangeNotifyPrivilege`). В движке это трейт `Visibility { can_list(volume, dir) }`, который проверяется у каждого совпадения во время параллельного прохода; при фильтре пустой запрос тоже идёт через проход, а не через готовый порядок, чтобы `total` был точным. `Duplex::access` у `PipeConn` в процессе под SYSTEM после `Hello` вызывает `ImpersonateNamedPipeClient`, берёт токен потока (`OpenThreadToken` с `TOKEN_QUERY`) и сразу возвращается `RevertToSelf` (если вернуться не удалось, процесс аварийно завершается). Токена уровня identification достаточно для `AccessCheck`. `TokenAccess` читает дескриптор папки (`GetFileSecurityW`: владелец, группа, DACL) от имени службы и проверяет `FILE_LIST_DIRECTORY` с отображением прав файлов; нечитаемый дескриптор означает «не видно». Ответы кэшируются по паре «том, идентификатор папки» на 5 минут. В консольном режиме фильтра нет: клиент — тот же пользователь.

Не сделано: группировка по идентификатору безопасности. В `$STANDARD_INFORMATION` у каждой записи есть `security_id`, а различных дескрипторов на томе обычно сотни или тысячи; проверка по ним вместо папок сделала бы первый широкий запрос почти бесплатным, а изменения прав пришли бы из журнала USN (`USN_REASON_SECURITY_CHANGE`). Сейчас первый пустой запрос клиента на томе с сотнями тысяч папок тратит на проверки секунды, а смена прав учитывается не позже чем через 5 минут.

### Клиент в `flit.exe`

`App` выдаёт `Effect::Search(SearchRequest)`, обработчик окна передаёт его `SearchClient` в поток `flit-search`. Для каждого окна с открытым поиском поток держит связь: удалённую (своё подключение к службе и поток `flit-search-read`, который читает ответы, просыпаясь раз в 500 мс, и рвёт связь, если начатый кадр не пришёл за 10 с) или локальную (`Session` над индексом в процессе, который наполняет `start_indexer` с `P::FallbackIndex` — `WalkIndex` по всем несъёмным дискам — и снимками в `%LOCALAPPDATA%\Flit\search`). Подключиться к службе поток пробует один раз за процесс; при потере связи окно переходит на локальный индекс и повторяет последний запрос. Ответы службы проверяются до передачи в интерфейс (`EntryBatch::entries(true)`, число папок равно числу строк, нет внутренних битов атрибутов). Поколение последнего запроса окна лежит в `AtomicU64`, поэтому устаревшие ответы отбрасываются ещё в потоке клиента. События уходят в `App::on_search_event` через `Wake`.

### Интерфейс

`SearchView` (`ui/search.rs`) — режим вкладки поверх обычного вида: открывается командой реестра `search.open` (Ctrl+E, Ctrl+Shift+F) или `App::open_search`. Каждая правка запроса — новое поколение и `SearchRequest::Query`. `QueryDone.total` задаёт высоту виртуального списка (прокрутка в `f64`); при построении кадра запрашиваются только недостающие страницы по 64 строки вокруг видимой части, а загруженные строки дальше 2048 от неё забываются, когда их больше 4096. Щелчок по заголовку меняет `SearchSort` и отправляет новый запрос: сортирует служба по готовым порядкам. «Group by folder» (`search.group_folder`, флажок в меню правого щелчка) переключает сортировку на папку и рисует папку только в первой строке каждой серии с линией над ней; щелчок по другой колонке группировку снимает. Enter открывает файл через провайдера или переходит в папку, Ctrl+Enter переходит в папку результата и выделяет его. Строка состояния показывает число результатов, время от запроса до `QueryDone`, источник индекса (запасной — цветом ошибки) и состояние томов.

## Сохранение состояния

Файл `%LOCALAPPDATA%\Flit\state.bin` — четыре записи postcard подряд:

```
Head { version: u32, path: Location, sort: SortField, descending: bool, show_hidden: bool,
       col_w: [f32; 3], placement: Option<(x, y, width, height, maximized)> }
NavState { pinned: Vec<Location>, sidebar_w: f32, sidebar: bool }
ViewRecord { view: FolderView, prefs: ViewPrefs, folders: Vec<(u64, FolderView)> }
LayoutRecord { view: (LayoutMode, Sizes), defaults: (LayoutMode, Sizes), folders: Vec<(LayoutMode, Sizes)>,
               thumbnails: bool, thumb_cache_mb: u32 }
```

`LayoutRecord` (этап 5.2) — раскладка и размеры вида активной вкладки, вида по умолчанию и каждого вида папки в том же порядке, что `ViewRecord::folders`, и два флага миниатюр. В `ViewRecord` раскладка всегда записывается как «Подробно»: прежние сборки знают только её, а новые берут настоящую из `LayoutRecord`; без `LayoutRecord` (файл прежней сборки) все виды открываются в «Подробно» с размерами по умолчанию.

`Head` побайтно совпадает с записью этапа 1 (`Saved { version, Persisted { path, ViewSpec { field, descending, show_hidden }, col_w }, placement }`): `col_w` — ширины «Дата изменения», «Тип», «Размер». Пишется она из вида активной вкладки, а сортировка по дате создания, которой этап 1 не знает, записывается в неё как сортировка по имени. `NavState` — хвост навигации этапа 3. `ViewRecord` — вид активной вкладки целиком, настройки вида окна и виды папок в порядке от давно открывавшихся к недавним (так при чтении восстанавливаются метки LRU).

`Saved::decode` читает `Head` через `postcard::take_from_bytes`, затем `NavState`, затем `ViewRecord`; пустой или нечитаемый хвост даёт значения по умолчанию для этой и следующих записей (ничего не закреплено, ширина панели 220, панель видна; виды папок пусты, настройки по умолчанию, вид — из `Head`). Поэтому номер версии остался 2: файлы этапов 1–4 читаются без потерь, а прежние сборки читают новый файл, потому что `postcard::from_bytes` не проверяет лишние байты в конце. Файл другой версии, отсутствующий или с нечитаемым `Head` заменяется значениями по умолчанию (домашняя папка, сортировка по имени, стандартные ширины). При загрузке ширина колонки вне 40–600 пикселей или не число сбрасывается к стандартной (в виде активной вкладки, в виде по умолчанию и в каждом виде папки), маска скрытых колонок не может скрыть имя, видов папок остаётся не больше 4096 последних, положение окна с неположительным размером отбрасывается, ширина боковой панели вне 160–480 сбрасывается к 220, повторы среди закреплённых папок убираются; `Location` проверяется при десериализации.

Снимок состояния (`App::persisted`) берётся, когда окно закрывается командой закрытия: путь и вид активной вкладки, показ скрытых, `ViewPrefs` этого окна и общее хранилище видов папок, а также положение окна и навигация. Записывается файл при уничтожении последнего окна: сначала `state.<pid>.tmp` (у каждого процесса свой, так что обычный и повышенный экземпляры не пишут в один файл), затем переименование поверх `state.bin`. Следующее поле можно добавить так же — ещё одной записью в конце, без смены версии; при несовместимом изменении увеличивается номер версии, миграций нет — старый файл просто игнорируется.
## Стратегия тестирования

- Тесты лежат отдельно от кода, в папке `test/` каждого крейта, и повторяют структуру `src/` (`src/ui/edit.rs` → `test/ui/edit.rs`). Обмен с настоящим буфером обмена (`clipboard::tests::files_written_to_the_clipboard_read_back_with_their_effect`) тоже игнорируется: он затирает всё содержимое буфера пользователя, кроме текста, и падает, когда буфер между записью и чтением перехватывает другая программа; запускать его вручную с `--ignored --exact`. Построение контекстного меню до показа (только меню оболочки, как раньше; меню Flit с пустым подменю; меню Flit с пунктами оболочки) сравнивает игнорируемый `context_menu::tests::bench_menu_prepare`.
- Производительность: бенчмарки `flit-core` и `flit-search` и сквозной сценарий `--metrics` на данных `flit-gen` (`scripts/metrics.ps1` → [docs/metrics.md](docs/metrics.md)).
- CI: Windows (release-сборка, тесты, clippy), Linux (`cargo check --workspace`, тесты ОС-независимых крейтов и `flit-platform-linux`), проверка правила зависимостей.

## Отклонения от ТЗ

1. **`TextBackend` находится в `flit-core`** (а `flit-platform` переэкспортирует его как `Text`): раскладке нужны синхронные измерения текста, а ядро не может зависеть от платформы.
2. **`Hello` вынесен из сообщений отдельных протоколов в общее рукопожатие транспорта `flit-proto` с магическим числом**: одно рукопожатие на все протоколы, и не-Flit собеседник распознаётся ещё до разбора сообщений.
3. **`Rows` протокола поиска несут `from` и используют общий `EntryBatch` плюс параллельный массив `dirs`**: ответ самоописателен для окна виртуального списка, а формат записей и его проверка одни для всех протоколов.
4. **Добавлен `OpenTarget::Default`**: отправитель не знает настроек получателя, поэтому куда открывать решает принимающий экземпляр по своей настройке.
5. **Обобщённый `LocalProvider` живёт в `flit-platform`, а не в `flit-platform-windows`**: это код без ОС поверх трейтов `Fs`, `Watcher`, `Shell`, он тестируется на любой системе, а `flit-platform-windows` даёт только реализации трейтов.
6. **Сортировка по колонке «Тип» идёт по расширению, а не по локализованному названию типа**: названия приходят от оболочки асинхронно, а расширение известно сразу и даёт детерминированный порядок.
7. **Естественная сортировка не зависит от локали** (ё после я, не-ASCII символы после букв) и не повторяет всех тонкостей `StrCmpLogicalW` с дефисами и апострофами: ключ вычисляется один раз на имя и сравнивается как байты, что быстро и одинаково на любой машине.
8. **Сглаживание текста в оттенках серого вместо ClearType**: одноканальная маска в общем атласе не зависит от цвета фона и порядка субпикселей монитора и работает с субпиксельным позиционированием.
9. **Смещение UTC читается один раз при запуске** (при создании окна), а не для каждой даты: форматирование дат в кадре обходится без системных вызовов; смена часового пояса или перевод часов учитываются после перезапуска.
10. **Названия типов получаются асинхронно, до ответа показывается заглушка «EXT File»**: запрос к оболочке может блокироваться, а UI-поток ждать не должен.
11. **Атлас глифов при переполнении сбрасывается целиком**: простейшая предсказуемая стратегия без учёта давности использования; при 2048² переполнение редко, а цена — один кадр перерастеризации.
12. **Пул потоков чтения фиксированного размера (4 потока)**: чтение папок упирается в ввод-вывод, четырёх параллельных загрузок хватает для вкладок и окон, автоподбора пока нет.
13. **Edition 2021**: чтобы `gen` оставался обычным идентификатором (в edition 2024 это зарезервированное слово).
14. **Канал единственного экземпляра — «сырой» именованный канал Win32 (`std::fs::File` поверх дескриптора) вместо крейта `interprocess`**: меньше зависимостей, протокол тот же.
15. **Неизвестные расположения оболочки без пути в файловой системе (Панель управления и т. п.) показываются как ошибка, а не передаются `explorer.exe`**: когда Flit назначен файловым менеджером по умолчанию, это грозит бесконечным циклом обработчиков. Корзина — исключение с этапа 3: она открывается собственным местом Flit (см. «Корзина»).
16. **Без агента WSL работает через `\\wsl.localhost`**: символы, запрещённые в Windows, видны как символы частной области Unicode. С этапа 4 это запасной путь, когда агента нет в сборке или он не запустился (см. «WSL»).
17. **Платформа Linux — заглушки**: этап 1 нацелен на Windows, а заглушки держат workspace собираемым на Linux и проверяют, что ядро не зависит от Windows.
18. **Кэш листинга для холодного старта пока не реализован**: отложен; первые строки и так приходят потоково.
19. **Слежение использует только `ReadDirectoryChangesExW`**: расширенные уведомления сразу несут метаданные; сетевые шары и файловые системы без расширенной информации живых обновлений не получают.
20. **Первый кадр рисуется на программном устройстве WARP, затем окно переходит на аппаратное**: `D3D11CreateDevice` для аппаратного адаптера занимает на тестовой машине около 160 мс, а WARP готов за единицы миллисекунд; параллельное создание обоих упирается в блокировку загрузчика, поэтому `flit-gpu` создаёт их последовательно.
21. **«Ввод → кадр ≤ 1 кадр» проверяется как максимум не больше 1,5 периода обновления**: ввод приходит в случайный момент внутри периода, и даже идеальный конвейер с `SetMaximumFrameLatency(1)` показывает его в ближайшем кадре, то есть через время от 0 до 1 периода плюс выдержка композитора; полуторный запас отличает «следующий кадр» от «через кадр».
22. **Имена, оканчивающиеся точкой или пробелом, нельзя открыть или удалить в корзину**: оболочка Windows не умеет адресовать их без нормализации; листинг и навигация работают, операции оболочки отказывают с ошибкой.
23. **Короткие имена 8.3 в уведомлениях распознаются по форме** (`~` и цифры в конце основы не длиннее 8 символов, расширение не длиннее 3), а не по любому `~`: иначе файлы блокировки Office `~$x.docx` вызывали бы полное перечитывание папки при каждом удалении.
24. **Фильтр в папке открывается по Ctrl+F**, как в ТЗ навигации, а не по Ctrl+Shift+F: Ctrl+Shift+F остаётся за поиском, Ctrl+E — тоже.
25. **Диски на боковой панели берутся не из листинга «This PC»**: у того листинга нет ни меток томов, ни свободного места, поэтому `flit-places` опрашивает диски сам (`Platform::drives`), а сетевые диски — без запроса тома и места.
26. **Командные ветки удалены из `App::key` и перенесены в реестр `ACTIONS`**: сочетания и палитра читают один источник. Сравнение модификаторов стало точным: раньше Shift у большинства сочетаний не учитывался (Shift+Delete отправлял в корзину, Ctrl+Shift+W закрывал вкладку), теперь такие сочетания свободны, а Ctrl+Shift+T возвращает закрытую вкладку.
27. **Ширина и видимость боковой панели — свои у каждого окна**, сохраняется состояние окна, закрытого последним; закреплённые папки общие для всех окон и синхронизируются сразу.
28. **Известные папки перечитываются вместе с дисками при подключении или извлечении устройства**, отдельного слежения за ними нет. Список дистрибутивов WSL с этапа 4 перечитывается и по уведомлению реестра (`flit-lxss-watch`).
29. **Домашняя страница не сделана**: ей нужен новый вид `Location` и правки маршрутизации, адресной строки и провайдеров; команды «Go to the home folder» и «Go to This PC» есть в палитре.
30. **Файловые операции адресуют файлы путями Windows и идут через `ProviderId::Local`**: папки WSL — через `\\wsl.localhost`, имена не в UTF-8 в таких операциях недоступны. Исключение с этапа 4 — удаление в корзину в папке WSL: оно идёт агенту с путями Linux (отклонение 200).
31. **Flit кладёт в буфер обмена только `CF_HDROP` и `Preferred DropEffect`, без `Shell IDList Array`, и принимает при вставке и броске только `CF_HDROP`**: этого достаточно для обмена с Проводником и большинством приложений; виртуальные файлы (`CFSTR_FILEDESCRIPTOR`: вложения почты, содержимое архивов) не принимаются, а уведомление «Paste Succeeded» источнику не отправляется. При перетаскивании из Flit используется полный объект данных оболочки.
32. **Меню оболочки, окно свойств и объект данных для перетаскивания создаются в UI-потоке**: `IContextMenu` привязан к окну-владельцу и его модальному циклу, поэтому расширения оболочки выполняются синхронно; это единственное место, где UI-поток ждёт сторонний код, и только по явному действию пользователя. Меню оболочки строится только при раскрытии «Show more options» (или до показа, если пункты оболочки стоят в общем меню), собственные пункты Flit оболочку не трогают.
33. **Восстановление из корзины — прямым переносом `$R…` на исходный путь с удалением `$I…`**, если исходное имя свободно и папка существует; иначе — глаголом `undelete` найденных в корзине элементов, как «Восстановить» в Проводнике: он сам создаёт пропавшую папку и спрашивает о конфликте имён. Значок корзины на рабочем столе Flit явно не обновляет (`SHUpdateRecycleBinIcon` не вызывается). После глагола `undelete` служебный `$I…` может остаться в `$Recycle.Bin`, корзина его не показывает.
34. **Каждая долгая операция идёт в своём потоке `flit-op-N`, а перенос байтов ждёт очереди тома назначения**: копии на один диск идут друг за другом (вторая показана как «Queued»), а не делят его, операции с метаданными (перемещение внутри тома, корзина, удаление, «Flatten folder») идут сразу; короткие операции выполняет сам маршрутизатор `flit-shell-ops`, поэтому они могут ждать разрешения вставки, но не долгого копирования. Очередь — по корню пути назначения, а не по физическому диску: два раздела одного диска не ждут друг друга, а чтение с того же диска, что и запись, не учитывается.
35. **Сообщения операций выводятся в строку состояния через ошибку вкладки** и держатся до следующей загрузки папки; итоги заметных операций (успех, ошибка с текстом, отмена) остаются ещё и в панели операций, а всплывающих уведомлений нет.
36. **Журнал отмены знает только операции Flit**: пункты меню оболочки, кроме `SHELL_VERBS`, и операции в других программах в него не попадают (пункты Flit в контекстном меню — обычные команды и попадают), а удалённое мимо корзины вернуть нельзя.
37. **Бросок на свободное место полосы вкладок, заголовок окна или адресную строку вне хлебных крошек сохраняет поведение этапа 1** (открыть папку первого файла и выделить его), а бросок на список, вкладку, крошку или элемент боковой панели копирует или перемещает в их папку.
38. **Копирование, перемещение, переименование, удаление навсегда и «Flatten folder» выполняет собственный движок Flit (`CopyFile2`, `MoveFileExW`, `CreateDirectoryExW`, `DeleteFileW`, `RemoveDirectoryW`), а не `IFileOperation`, без ограничения размера**: обработчики копирования оболочки (`ICopyHook`) не вызываются, записи в журнал отмены Проводника не добавляются (отменяет Ctrl+Z во Flit), изменения сообщаются оболочке одним `SHCNE_UPDATEDIR` на папку. `IFileOperation` остаётся для корзины, деревьев со ссылками на папки, элементов, которым нужны права администратора (остаток операции с первого такого элемента), и запасных путей новых элементов; в этих случаях могут появиться диалоги Windows. Перенос между томами сначала копирует, затем удаляет источник; если удалить нельзя, копия удаляется, а элемент становится ошибкой.
39. **Рамка выделения начинается только с пустого места и с колонок даты, типа и размера**: в Проводнике её можно начать и с пустой части колонки имени правее текста, во Flit вся колонка имени отдана перетаскиванию файлов.
40. **Поиск открывается Ctrl+E и Ctrl+Shift+F, а не Ctrl+F**: Ctrl+F занят фильтром в папке.
41. **MFT читается двумя способами**: имена, родители и атрибуты — `FSCTL_ENUM_USN_DATA`, размеры и даты — прямым чтением записей `$MFT`, потому что перечисление их не отдаёт. Если у самой `$MFT` есть `$ATTRIBUTE_LIST`, читаются только экстенты из записи 0, и записи за ними остаются без размера и даты до первого изменения.
42. **Без доступа к MFT служба переходит на обход папок, а журнал USN сама не создаёт**: не NTFS, нет прав администратора, журнал выключен или `$MFT` не читается — том индексируется `WalkIndex`; создание журнала изменило бы том.
43. **Снимок индекса — собственный формат с перестройкой производных структур при загрузке, а не rkyv + memmap2**: файл не зависит от раскладки `VolumeIndex` в памяти и проверяется целиком, цена — около 0,3 с на миллион записей при старте.
44. **Изменения индекса доходят до клиента повторным `QueryDone` того же поколения (не чаще раза в секунду)**, а не отдельным сообщением: протокол не меняется, клиент перечитывает видимые страницы.
45. **Первая страница результатов приходит вместе с `QueryDone` без `GetRows`**: первый экран за один обмен.
46. **Фильтр прав проверяет только родительскую папку записи и кэширует ответ на 5 минут**; группировки по идентификатору безопасности нет, поэтому первый широкий запрос на большом томе стоит секунды. В консольном режиме фильтра нет.
47. **У жёсткой ссылки в индексе одно имя**: то, которое вернуло перечисление MFT или обход.
48. **Установщика службы нет**: регистрация — вручную через `sc.exe`, команды описаны в README; Flit службу не регистрирует.
49. **Запасной индекс в `flit.exe` обходит все несъёмные диски**, а не только открытые папки, и хранит снимок в `%LOCALAPPDATA%\Flit\search`.
50. **Корзина всегда, а остальные операции оболочки в пределах бюджета (500 элементов, 16 МиБ) идут с `FOF_SILENT`, без окна прогресса Windows**: прогресс корзины показывает панель Flit по `UpdateProgress` (в элементах, без байтов и скорости в байтах), а отменяет её кнопка панели; Проводник показал бы окно, если операция затянулась. Диалоги конфликтов, «слишком велик для корзины» и ошибок остаются. Точки повторной обработки при подсчёте бюджета не раскрываются, поэтому папка со связью на большое дерево может копироваться без окна прогресса.
51. **Корзина обновляется только полным перечитыванием**: имена в ней не уникальны (два удалённых `report.txt`), а уведомления приходят об именах `$R…` и `$I…`, поэтому изменения нельзя применить по имени. При обновлении фокус сохраняется по имени, выделение сбрасывается.
52. **Удаление навсегда в корзине и её очистка выполняются напрямую (удаление `$R…` и `$I…`) с подтверждением в диалоге Flit, а не через `SHEmptyRecycleBinW` или `IFileOperation`**: так обходится перечисление корзины оболочкой, путь согласован с прямым восстановлением и проверяется на поддельной корзине во временной папке, что для `SHEmptyRecycleBinW` невозможно — она всегда работает с настоящей корзиной. Цена: нет окна прогресса для огромной корзины и системного звука очистки; значок на рабочем столе обновляет `SHUpdateRecycleBinIcon`.
53. **Данные записи корзины (путь `$R…` и исходная папка) хранятся «хвостом» за именем в общем буфере `names`**, а не в отдельной структуре или новых полях `Entry`: запись остаётся 40-байтной, листинг корзины — обычный `Listing`, который сортируется, фильтруется и передаётся без особых случаев.
54. **Колонки корзины делят ширины с колонками обычной папки по позиции** («Original location» — с «Date modified», «Date deleted» — с «Type»): свой набор колонок у места есть, а свои ширины появятся вместе с настройкой колонок. Снято на этапе 5.1: ширины хранятся по виду колонки в `Columns`, и у корзины свой вид папки (см. «Вид папки»).
55. **Корзина показывает только элементы текущего пользователя на несъёмных дисках с буквой**: тома без буквы и съёмные диски не читаются. Корень, которого не было при загрузке (на диске ещё ничего не удаляли), начинает отслеживаться со следующей загрузки, например после F5.
56. **Скрытые и системные элементы в корзине видны всегда**: пользователь ищет удалённое, а переключатель скрытых файлов относится к обычным папкам.
57. **Любое удаление навсегда (Shift+Delete, Delete в корзине, очистка корзины) подтверждает модальный диалог Flit, а удаление в корзину не подтверждается**: режимы подтверждения удаления настраиваются на этапе 8. Если остаток Shift+Delete уходит оболочке за правами администратора, Windows спрашивает ещё раз.
58. **Шаблоны «Создать» с `Handler` или `Command` пропускаются** (библиотеки, контакты, мастер ярлыка): их выполняют COM-объекты и программы оболочки. Ярлык Flit создаёт сам, цель вводится в поле палитры вместо мастера Windows.
59. **Шаблоны читаются один раз за процесс, вторым ответом потока `flit-places`**: перечисление `HKEY_CLASSES_ROOT` стоит около 90 мс, а набор шаблонов меняется только при установке программ; новые шаблоны появятся после перезапуска. До ответа выбор нового элемента предлагает папку и ярлык.
60. **Основа имени нового файла без `ItemName` — «New <тип>»**, где «New» по-английски, как у «New folder», а тип — локализованное название из оболочки: на русской Windows получается «New Документ Microsoft Word.docx». Проводник берёт шаблон имени из своих ресурсов; подписи интерфейса Flit пока английские.
61. **«New folder with the selected items» — две операции и два шага отмены** (папка, затем перемещение), а не одна: журнал хранит отчёты отдельных операций, и каждый шаг остаётся обычной обратимой операцией с выделением результата.
62. **Созданный поток NTFS не отменяется и не имеет запасного пути через оболочку**: поток не уходит в корзину, а удалять данные мимо корзины журнал не умеет; оболочка потоков не знает.
63. **Предупреждение о смене расширения — строка состояния и повторный Enter, а не модальный диалог**: UI-поток не блокируется, редактор остаётся открытым для исправления; флаг `warn_extension_change` пока без интерфейса.
64. **Пакетное переименование нумерует все элементы «Имя (1)», «Имя (2)»… в порядке строк и пропускает номера, занятые невыделенными элементами**, а не останавливается на конфликте; одна операция `MoveTo`, одна отмена.
65. **Приглушение вырезанного — только для вырезанного в этом окне Flit**: вырезанное в Проводнике или в другом окне не приглушается, потому что для этого пришлось бы читать буфер при каждом изменении. Конец вырезания определяется по номеру последовательности буфера в `WM_CLIPBOARDUPDATE`, без опроса содержимого.
66. **Бросок на программу принимается только для `.exe`, `.com`, `.bat`, `.cmd`**: Проводник ещё спрашивает обработчики броска (`DropHandler`) у других типов, а это COM в UI-потоке при каждом движении мыши.
67. **Терминал — Windows Terminal, если есть псевдоним `wt.exe`, иначе `cmd.exe`** (его консоль сама откроется в терминале по умолчанию, если он назначен); профиль Windows Terminal не выбирается, PowerShell без Windows Terminal не запускается, папка WSL открывается `wsl.exe --cd` в своём дистрибутиве.
68. **Ctrl+Shift+C и новый Ctrl+Alt+C копируют только выделенное, а без выделения — путь текущей папки**; элемент под фокусом без выделения больше не копируется.
69. **Ярлык разбирается без `IShellLink::Resolve`**: `GetPath` и проверка, что цель — существующая папка, дают то же, что `Resolve` с `SLR_NO_UI | SLR_NOSEARCH | SLR_NOTRACK`, но никогда не переписывают `.lnk`; ярлык с пропавшей целью уходит оболочке с её диалогом.
70. **Повышенный Flit только сообщает о блокировке перетаскивания один раз при запуске**: UIPI не пропускает OLE-перетаскивание из процессов ниже уровнем, `ChangeWindowMessageFilterEx` этого не меняет, а других обходов без ослабления защиты нет.
71. **Слайд-шоу обоев и экрана блокировки из выделенных картинок не сделано, пункта «Set as lock screen background» тоже нет**: экрану блокировки нужен WinRT (`LockScreen`, `StorageFile`) с асинхронным API и новыми возможностями крейта `windows`, у неупакованного приложения вызов может быть отклонён, а проверить результат без изменения системных настроек пользователя нельзя; одна картинка на обои ставится из меню оболочки («Show more options»).
72. **Медленный второй щелчок начинает переименование с любого места колонки имени**, а не только с текста имени, и не раньше времени двойного щелчка после получения окном фокуса.
73. **Диалог конфликта — «Replace», «Keep both», «Skip», «Cancel» и флажок «для всех остальных», без выбора по каждому файлу и сравнения содержимого**: Проводник ещё предлагает отметить нужные версии в списке. «Keep both» даёт имя «x (2).ext», как при вставке в Проводнике, а не открывает поле для нового имени. Действие по умолчанию задаёт флаг `App::conflict_default` (тогда диалог не появляется), интерфейс настройки — этап 8.
74. **«Replace» для папки сливает её с существующей, а между файлом и папкой работает как «Keep both»**: папка цели и её файлы с другими именами никогда не удаляются, так что потерять можно только то, что пользователь явно выбрал заменить.
75. **Заменённое не возвращается отменой**: файл перезаписывается (через временный `.flit-partial`, поэтому до конца копирования старая версия цела), а журнал отмены хранит только пары «откуда → куда»; отмена копии с заменой отправляет в корзину новую версию.
76. **Конфликт имени при переименовании и пакетном переименовании не спрашивается**: F2 в занятое имя даёт ошибку в строке состояния, а пакетное переименование само обходит занятые номера; диалог конфликта — только для копирования, перемещения и «Flatten folder».
77. **Копия в ту же папку называется «x - Copy.ext» по-английски**, а не так, как её назвала бы локализованная оболочка: имя выбирает движок Flit, как и «New folder».
78. **Отмена не откатывает уже сделанное**: недокопированный файл удаляется (`CopyFile2`), необработанные источники остаются на месте, а перенесённое до отмены остаётся перенесённым и есть в отчёте, поэтому его возвращает Ctrl+Z. Паузы нет.
79. **Закрытие окна отменяет его операции, а при закрытии последнего окна Flit ждёт их остановки не больше 2 с**: окна прогресса, живущего отдельно от окна Flit, нет; список операций — свой у каждого окна и не сохраняется.
80. **Скорость и график считаются по байтам, а у операций без байтов (перемещение внутри тома, корзина, удаление) — по элементам**; прогресс отправляется не чаще 30 раз в секунду, отсчёт графика — раз в 250 мс, на графике последние 60 отсчётов.
81. **«Flatten folder» — команда палитры для выделенных папок, без пункта меню и без включения в настройках**: файлы из всех подпапок переносятся в выделенную папку, опустевшие подпапки удаляются, ссылки на папки переносятся как есть, без захода внутрь; совпадения имён решает диалог конфликта, отмена — одним шагом через журнал. Переключатель «показывать в меню» и пометка опасной команды — этап 8.
82. **Кнопка операций стоит справа от адресной строки и прячется, когда операций нет**, если не поднят флаг `App::ops_button_always` (интерфейс настройки — этап 8); непросмотренная ошибка держит кнопку видимой с красной точкой.
83. **Вместо диалога «Элементы слишком велики для этого диска» — ошибка до начала копирования**: свободное место тома назначения сравнивается с подсчитанным объёмом без учёта заменяемых файлов, поэтому копия с заменой на почти полный диск может быть отклонена; файл больше 4 ГБ на FAT32 даёт ошибку этого файла, остальные копируются.
84. **Большие файлы копируются с буферизацией (`CopyFile2` без `COPY_FILE_NO_BUFFERING`)**: на тестовой машине файл 512 МБ копировался за 118 мс с буферизацией и за 204 мс без неё; цена — копия вытесняет из кэша другие данные.
85. **Пункты оболочки лежат в подменю «Show more options», которое наполняется при раскрытии, а не открывают отдельное классическое меню, как в Windows 11**: подменю не требует закрывать меню Flit и строить второе окно, а цена опроса оболочки (45–105 мс) платится только при наведении на него. Shift при правом щелчке и флаг `App::shell_items_inline` ставят пункты оболочки прямо в меню, как классическое меню Проводника; интерфейса у флага нет до этапа 8.
86. **Набор пунктов меню Flit фиксирован, а отдельные пункты скрываются только флагом ядра `App::menu_hidden` по идентификаторам команд**: переключателей в интерфейсе нет до этапа 8; пункты «New» не имеют своих идентификаторов и скрываются вместе через `file.new_item`.
87. **В общем меню повторы убираются по глаголу оболочки** (`open`, `cut`, `copy`, `paste`, `delete`, `rename`, `link`, `properties`): пункт расширения, который не сообщает глагол, но делает то же, останется; в подменю «Show more options» меню оболочки остаётся целиком.
88. **У пунктов Flit нет значков и пункта по умолчанию, выделенного жирным, подписи английские**: меню — обычное `HMENU` с текстом и сочетанием через `\t`, без отрисовки владельцем; в «Sort by» нет группировки и вида раскладки (этап 5). На этапе 5.1 группировка появилась отдельным подменю «Group by», вида раскладки в меню нет до этапа 5.2.
89. **Раскрытие папки при перетаскивании — фиксированные 1,3 с, без настройки, и только для строки папки, другой вкладки и хлебной крошки**: элементы боковой панели не раскрываются (на них можно бросить), строка или крошка открывается в текущей вкладке, а вкладка просто становится текущей; отсчёт идёт по вызовам `DragOver`, без своего таймера.
90. **Подпись у курсора передаётся через `DROPDESCRIPTION` в объекте данных, поэтому видна только у источников с картинкой перетаскивания оболочки** (Проводник, Flit); остальные показывают обычный курсор. Подписи английские («Move to %1», «Copy to %1», «Create link in %1», «Open with %1»), при прежнем поведении броска (открыть папку файла) подписи нет.
91. **Бросок на вкладку не переключает на неё**, а файлы уходят в её папку; переключает только задержка курсора над вкладкой. Броски на вторую панель — этап 6.
92. **Первое перетаскивание не прогревается**: прогрев объекта данных и картинки перетаскивания в фоне (1,4 мс) замерного выигрыша не дал; вместо этого регистрация приёмника перенесена за первый кадр, а время каждого перетаскивания пишется в лог для разбора медленных случаев у пользователей.
93. **Группировка по типу идёт по расширению без учёта регистра, а не по названию типа**: ключ считается в потоке сортировки из листинга, а названия типов приходят от оболочки позже и асинхронно. Расширения с одинаковым названием типа (`.jpg` и `.jpeg`) дают две группы с одной подписью; все папки — одна группа.
94. **Группы по имени — по первой букве, как в Files**: цифры — «0-9», знаки и пустые имена — «#», каждая буква — своя группа (`Ä` отдельно от `A`); диапазонов «A - H» Проводника нет.
95. **Группы по дате — абсолютные («2024», «March 2024», «2024-03-15», «Unknown date»), без относительных «Today», «Last week»**; месяцы по-английски. Местный день считается по смещению UTC, взятому при создании окна, поэтому запись около полуночи из другого периода летнего времени может попасть в соседний день, а смена часового пояса применяется в новом окне. Смещение записывается в `ViewSpec` только при группировке по дате, чтобы оно не вызывало лишних пересортировок.
96. **Щелчок по заголовку группы сворачивает и разворачивает её, а не выделяет её элементы**; фокус клавиатуры на заголовок не встаёт, свернуть группу с клавиатуры нельзя. Свёрнутые группы помнит только `DirView` загрузки: переход в другую папку и F5 открывают все группы, а смена поля группировки даёт новые идентификаторы.
97. **Группировка результатов поиска по папке — без заголовков, числа элементов и сворачивания**: результаты приходят страницами от службы, и клиент не знает границ групп за пределами загруженных строк. Группировка сортирует результаты по папке на стороне службы и помечает начало каждой серии: папка написана только в первой строке, над ней линия.
98. **«Size all columns to fit» меряет заголовок и видимые строки, а не все 100 000**, и не трогает «Имя»: колонка имени всегда занимает остаток ширины. Ширины ограничены 40–600 пикселями при 100 %.
99. **Скрытие расширений скрывает расширения всех файлов, а не только известных типов**: проверка «известности» требует реестра на каждое расширение. У имени, которое целиком расширение (`.gitignore`), и у папок ничего не скрывается; переименование показывает полное имя.
100. **Скрытая строка состояния возвращается, пока у вкладки есть ошибка**, иначе ошибку было бы негде прочитать; кнопки «Folder sizes» и корзины уходят вместе со строкой, их команды остаются в палитре.
101. **Автоматический подсчёт размеров папок — только для текущей вкладки, когда её папка дочитана**: фоновые вкладки не считаются, пока их папку не перечитают при активной вкладке.
102. **Меню фона корзины — меню Flit без пунктов оболочки: «Sort by», «Group by», «Refresh»**; меню элементов корзины по-прежнему не показывается (см. «Корзина», «Вид»).
103. **Вид папки запоминается только после явной смены вида в ней** (сортировка, группировка, колонки, ширина); до этого папка открывается видом по умолчанию и следует за его изменениями. Ключ — 64-битный хеш пути: переименованная или перемещённая папка теряет свой вид, а сами пути в `state.bin` не хранятся.
104. **Хранилище видов одно на процесс, а `ViewPrefs` — у каждого окна свои**: в `state.bin` попадают настройки окна, закрытого последним командой закрытия, а новое окно начинает с сохранённых при последнем закрытии или запуске. Хранилище держит до 4096 папок и при переполнении сразу сокращается до 3072 недавних, а не вытесняет по одной.
105. **Вид раскладки (`LayoutMode`) хранится в виде папки, но раскладка пока одна — «Подробно»**; остальные — этап 5.2. Группировки по тегам нет до этапа 7, группировка по состоянию синхронизации облака вне рамок. На этапе 5.2 появились все шесть раскладок (см. «Раскладки»).
106. **Выделение наведением заменяет выделение одной строкой через фиксированные 0,6 с**, не срабатывает с Ctrl и Shift, при нажатой кнопке, во время перетаскивания и переименования; задержка не настраивается. Флажки выделения стоят слева в колонке имени, флажка «выделить всё» в заголовке нет. Оба режима выключены по умолчанию и переключаются из палитры; страница настроек — этап 8.
107. **Автопрокрутка средней кнопкой — только по вертикали, с курсором «вверх-вниз»** (`IDC_SIZENS`): своего курсора автопрокрутки у Windows нет. Средняя кнопка по строке папки не открывает её в новой вкладке, а включает автопрокрутку.
108. **Новые флаги вида (`ViewPrefs`: `same_for_all`, `defaults`, `auto_fit`, `show_dotfiles`, `show_system`, `show_extensions`, `auto_sizes`, `status_bar`, `split_count`, `checkboxes`, `hover_select`) переключаются командами палитры и сохраняются в `state.bin`, страницы настроек нет до этапа 8**; вид по умолчанию задаётся только копированием вида текущей папки.
109. **«Size all columns to fit» — Ctrl+плюс (клавиша «=+» и «+» цифровой клавиатуры), как Ctrl+Num+ в Проводнике**: в Files Ctrl+плюс и Ctrl+Num+ увеличивают размер элементов; когда на этапе 5.2 появятся размеры элементов, сочетания придётся развести. На этапе 5.2 разведены: см. п. 110.
110. **Ctrl+плюс и Ctrl+минус меняют размер элементов, а «Size all columns to fit» осталась только на Ctrl+«+» цифровой клавиатуры (`Key::NumPlus`, `VK_ADD`)**, как в Проводнике; в Files Ctrl+Num+ тоже увеличивает элементы.
111. **Порядок Ctrl+Shift+1…6 — «Подробно», «Список», «Карточки», «Колонки», «Сетка», «Адаптивная»**, как в списке раскладок настроек Files; в описании горячих клавиш Files «Сетка» стоит перед «Колонками».
112. **Колонки-родители в раскладке «Колонки» не следят за изменениями и не группируются**: их листинг — снимок `ProviderRequest::List` с вкладкой 0 (или листинг, оставленный при уходе вглубь), слежение у вкладки одно и стоит на текущей папке. Колонок-родителей не больше четырёх, их ширина — ступень размера «Колонок», папки, вид которых не меняли, в «Колонках» наследуют раскладку текущей папки.
113. **Адаптивная раскладка выбирается при появлении первой порции листинга и до конца загрузки не меняется; решение по полному листингу запоминается для следующего открытия папки** (до 4096 папок в памяти окна, при переполнении память очищается, в `state.bin` не пишется): так вид не прыгает, пока папка дочитывается, а папка, в которую добавили картинки, меняет вид со второго открытия после изменения. `desktop.ini` читается только у папок с адаптивной раскладкой, из него берётся одна `[ViewState] FolderType`; `Mode` и `Vid` Проводника не используются.
114. **Имя в «Сетке» — одна строка с многоточием, в «Карточках» — имя, тип и размер без даты**; подписи не переносятся на вторую строку, как в Files.
115. **Миниатюры — только в «Сетке» и «Карточках» и только у файлов с расширениями картинок, видео и документов с обработчиком миниатюр**; папки показывают значок, а не коллаж содержимого, в корзине миниатюр нет. Миниатюра не увеличивается больше своего размера, класс размера в атласе — 64, 128, 256 или 512 пикселей.
116. **Собственный дисковый кэш миниатюр вместо одного кэша Windows**: несжатый RGBA в сегментах `%LOCALAPPDATA%\Flit\thumbs\NNNNNNNN.thumbs`, ключ — хеш пути, даты изменения, размера и класса. Чтение своей записи — 0,03–0,08 мс против 2,5–2,9 мс у `IShellItemImageFactory` с кэшем Windows (раздел «Бенчмарки» README); цена — до `thumb_cache_mb` места на диске. Вытесняется сегмент целиком, самый старый, а не каждая миниатюра по давности показа; изменённый файл получает новый ключ, старая запись лежит до вытеснения своего сегмента.
117. **Свой значок папки ищется только у папок с атрибутом «только чтение» или «системный»**, как это делает Проводник; значок перечитывается после команды Flit или при смене даты и атрибутов папки, а правка `desktop.ini` другой программой без них видна после перезапуска. Команда «Change the folder icon» не отменяется Ctrl+Z, вернуть обычный значок из Flit нельзя.
200. **Корзина в папке WSL — корзина Linux, и Ctrl+Z её не отменяет**: агент кладёт файлы в корзину freedesktop внутри дистрибутива, но не сообщает, куда, поэтому `OpReport` приходит без элементов и журнал отмены пуст. Вернуть файл можно средствами Linux (`gio trash --restore`, файловый менеджер с WSLg).
201. **Агенту уходят только листинг, наблюдение, размеры папок и корзина**: копирование, перемещение, переименование, новая папка и удаление навсегда внутри дистрибутива выполняет движок Windows через `\\wsl.localhost` (раздел 9 `docs/design/wsl.md` не сделан), поэтому они медленнее, теряют права Linux и не работают с именами не в UTF-8. На прочие `FileOp` агент отвечает ошибкой.
202. **После тайм-аута `Hello`, неудачной доставки или трёх разрывов за 5 минут дистрибутив до перезапуска Flit работает через `\\wsl.localhost`**: команды «Повторить» нет.
203. **Вкладка WSL, восстановленная при запуске Flit, запускает дистрибутив**: восстановление считается действием пользователя. Само наблюдение без листинга агента не запускает.
204. **Дистрибутивы в «This PC» — строки-папки с атрибутом `VOLUME`, без собственного значка и без объёма**; как и диски, они появляются в «This PC» при следующем открытии или F5, а не сразу после установки.
205. **`wsl.exe` попадает в Job object сразу после запуска, а не созданным приостановленным**: `std::process::Command` не умеет `CREATE_SUSPENDED`. Если Flit упадёт в эти микросекунды, агент всё равно выйдет по EOF на stdin, а неудачное присоединение пишется в лог.
206. **Агент вычисляет свой идентификатор сборки при старте, хешируя `/proc/self/exe`**: бинарник не может содержать хеш самого себя. Время входит в измеренные 45 мс тёплого запуска.
207. **Наблюдение агента сообщает состояние, а не события**: после склейки за 50 мс существующее имя приходит как `Added` с метаданными, исчезнувшее — как `Removed`, `Modified` агент не шлёт, переименование — пара `Removed` и `Added`. Изменения видны не раньше чем через 50 мс.
208. **В `flit.exe` встраивается только агент x64**: цель `aarch64-unknown-linux-musl` на машине сборки не установлена, поэтому сборка ARM64 получает агента только через `FLIT_WSL_AGENT_ARM64`, иначе работает через `\\wsl.localhost`. Выбор архитектуры по `IsWow64Process2` уже есть.
209. **Старые файлы `agent-<id>` в `~/.cache/flit` не удаляются**: каждая сборка Flit кладёт свой (около 650 КБ), чтобы одновременно работающие версии не мешали друг другу.
210. **Признак «дистрибутив запущен» не показывается**: `wsl.exe --list --running` не вызывается, чтобы не трогать службу WSL без действия пользователя.
211. **Дистрибутивы с именем вне `[A-Za-z0-9._-]{1,64}` не поддерживаются**: Flit их не показывает, а путь `\\wsl$\<имя>` остаётся обычным UNC-путём.
212. **Запрос `Stat` агент понимает, но UI его не шлёт**: путь из адресной строки проверяется листингом, как и для локальных папок.
