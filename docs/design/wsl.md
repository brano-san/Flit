# WSL во Flit

Статус: стадия 1 (канонические пути и упрощённый режим через `\\wsl.localhost`) реализована, агент `flit-wsl-agent` пока только спроектирован.

Пометки: **[код Flit]** — так работает текущий код; **[реестр]** — наблюдалось read-only на машине разработки (Windows 11 25H2, 26200.9711, один дистрибутив Ubuntu-22.04, WSL2); **[гипотеза]** — не проверялось. В этой сессии `wsl.exe` не запускался и к `\\wsl.localhost` никто не обращался: и то и другое запускает дистрибутив.

## 1. Цель

Каталоги дистрибутивов WSL — полноправные расположения Flit:

- листинг со скоростью Linux-нативного кода;
- точные имена Linux (любые байты, кроме `/` и NUL);
- живые обновления через inotify;
- корзина по спецификации freedesktop;
- остановленные дистрибутивы не будятся без действия пользователя.

## 2. Модель пути

### 2.1 Формы

| Форма | Пример | Где используется |
|---|---|---|
| `wsl://<distro>/<путь Linux>` (канон) | `wsl://Ubuntu-22.04/home/u/src` | `Location::to_bytes`, сохранённое состояние, протоколы, адресная строка, `Location::display` |
| `\\wsl.localhost\<distro>\…` | `\\wsl.localhost\Ubuntu-22.04\home\u\src` | `to_windows()`: всё, что идёт в Win32 и Shell (ShellExecute, `IFileOperation`, NtFs в упрощённом режиме) |
| `\\wsl$\<distro>\…` | `\\wsl$\Ubuntu-22.04\etc` | только на входе (старая форма) |
| `\\?\UNC\wsl.localhost\…` | — | на входе; NtFs открывает каталоги verbatim-путями (`to_wide(true)`) |

### 2.2 Правила разбора [код Flit, `location.rs`]

- Схема `wsl://` без учёта регистра. Имя дистрибутива — до первого `/`, непустой UTF-8 без `\`. Без пути подставляется `/`. `wsl:///etc` отвергается.
- Путь — `FsPath` вида `Unix`: `.` и пустые сегменты выбрасываются, `..` схлопывается лексически и выше `/` не поднимается.
- `from_local`: хосты `wsl.localhost` и `wsl$` (без учёта регистра, включая verbatim `\\?\UNC\…`) дают `Location::Wsl`, любой другой UNC остаётся `Location::Local`.
- `to_windows()` всегда выдаёт `\\wsl.localhost\`.
- Родитель корня дистрибутива — «Этот компьютер». Крошки: `This PC › Ubuntu (WSL) › home › u`.
- `Location::provider()` возвращает `ProviderId::Wsl(distro)`.

### 2.3 Экранирование имён в представлении Windows

| Байт в имени Linux | Символ в имени Windows |
|---|---|
| 0x01–0x1F | U+F001–U+F01F |
| `"` `*` `:` `<` `>` `?` `\` `\|` | U+F000 + код (`:` → U+F03A) |
| всё остальное | без изменений (UTF-8 → UTF-16) |

Обратно (`from_local`) U+F001–U+F07F декодируются только для перечисленных байтов. Схема совпадает с той, которой WSL обозначает такие имена; на живом `\\wsl.localhost` не проверялась [гипотеза]. Сейчас её покрывает модельный тест `linux_names_with_windows_forbidden_chars`.

### 2.4 Что не представимо в Windows

| Случай | Канон | Представление Windows | Последствие |
|---|---|---|---|
| невалидный UTF-8 (`bad\xFF`) | без потерь: сырые байты в `wsl://…` | `to_windows()` = `None` | показывается с U+FFFD; в упрощённом режиме недоступно; агент работает |
| имя с настоящим символом U+F03A | без потерь | совпадает с экранированным `:` | `from_local` превращает его в `:`, это уже другой файл (коллизия упрощённого режима) |
| имя оканчивается точкой или пробелом | без потерь | Win32 срезает их при нормализации не-verbatim путей | NtFs листает verbatim-путём и видит верно, но ShellExecute и `SHCreateItemFromParsingName` (`to_wide(false)`) адресуют другой файл, поэтому `ShellCom::open` и `ShellCom::trash` такие пути отвергают с ошибкой (исправлено; раньше «Удалить» для `build.` удалило бы `build`) |
| зарезервированные имена (`con`, `nul.txt`) | без потерь | ? | [гипотеза] проверить трактовку в UNC-путях |
| NUL | в именах Linux не бывает; `FsPath` его отвергает (исправлено) | Win32 обрезает путь | §11 |

## 3. Провайдеры

Как устроено [код Flit]:

- `flit_platform::Provider { fn submit(&self, req: ProviderRequest) }` асинхронный. Ответы приходят через канал `ProviderEvent`, листинги — через `SnapshotSlot`.
- `ProviderId::{Local, Wsl(distro)}` получается из `Location::provider()`.
- `App` выпускает `Effect::Provider { provider, req }` по `Location` вкладки. Отдельного поля «провайдер» у `Tab` нет, он выводится из `Location`, поэтому переход `C:\` → `wsl://…` в той же вкладке сам меняет провайдера.
- `Handler::submit` (`crates/flit/src/app.rs`) — единственная развилка: `Local` → `LocalProvider`, `Wsl(d)` → тот же `LocalProvider` через `via_unc(d, req)`.
- События возвращаются по `TabId` + `gen` (`window_of_tab`, `TAB_STRIDE`).

План:

- `Handler` получает `wsl: HashMap<String, WslProvider>`. Провайдер создаётся лениво при первом запросе к дистрибутиву, развилка остаётся с двумя ветвями.
- `WslProvider: Provider` прячет агента и сам откатывается на `via_unc` + `LocalProvider`, когда агент недоступен.
- Linux-сборка Flit использует тот же код `flit-platform-linux` напрямую как `LocalProvider`. Агент — это тот же код, только за каналом.

## 4. Стадия 1: упрощённый режим

`via_unc` переписывает все пути запроса в `\\wsl.localhost\<distro>\…` и отдаёт запрос `LocalProvider` (NtFs, DirWatcher, ShellCom).

| Ограничение | Причина |
|---|---|
| Имена с запрещёнными в Windows символами показываются символами U+F0xx; канонический путь вкладки содержит U+F0xx вместо исходных символов | имена приходят из представления Windows. Обратное преобразование через `to_windows()` работает, но «Копировать путь» выдаёт не настоящее имя Linux |
| Нет живых обновлений | [гипотеза] `ReadDirectoryChangesW` на 9P-редиректоре не работает; DirWatcher при неудаче молча остаётся без наблюдения, обновление только по F5 |
| Скорость | каждый листинг идёт по 9P поверх Hyper-V socket; не измерялось. Медленный или только стартующий дистрибутив занимает воркеры общего пула `LocalProvider` (`FS_THREADS` = 4) и задерживает локальные листинги |
| Первое обращение будит дистрибутив | [гипотеза] холодный старт ВМ WSL2 занимает секунды |
| Точечные файлы не скрываются | [гипотеза] 9P не ставит `FILE_ATTRIBUTE_HIDDEN` |
| Абсолютные символические ссылки Linux | [гипотеза] из Windows не разрешаются |
| Невалидный UTF-8, имена с точкой или пробелом на конце, коллизия U+F0xx | §2.4 |
| Регистр | `App.case` по умолчанию `Insensitive`, а в Linux `A` и `a` — разные файлы (§12) |

Найдено при подготовке документа:

1. **Исправлено.** Раньше `via_unc` при `to_windows() == None` (невалидный UTF-8) отдавал запрос `LocalProvider` с исходным Unix-путём, и Win32 читал `/tmp/x` как `C:\tmp\x`. Теперь `via_unc` возвращает `Option`: `List` сразу получает снимок с ошибкой `Unavailable`, `Watch` снимает слежение, `DirSizes`, `Op::Trash` и `Open` отбрасываются (тест `unmappable_wsl_paths_never_reach_win32`).
2. **Исправлено.** `ShellCom::trash` и `ShellCom::open` отказываются от путей, где есть имя на точку или пробел. Это касается и локальных путей NTFS, не только WSL.
3. **Исправлено.** NUL в `FsPath` (§11).
4. Желательно: прогонять имена из листинга через обратное экранирование до `Location::join`. Тогда канонический путь будет содержать настоящие имена Linux, а сохранённые в упрощённом режиме вкладки останутся верными и для агента.

## 5. Агент `flit-wsl-agent`

### 5.1 Сборка и встраивание

- `[[bin]]` в `flit-platform-linux`, без нового крейта: `LinuxFs`, `Inotify`, корзина из `FreedesktopShell` и `flit-proto`. GUI-заглушки в граф вызовов не попадают.
- Цели `x86_64-unknown-linux-musl` и `aarch64-unknown-linux-musl`; бинарник статический, `panic = "abort"`, без отладочных символов. Архитектура выбирается по родной архитектуре Windows (`IsWow64Process2`), потому что дистрибутив совпадает с ней.
- Без зависимостей на C (`mimalloc` есть только у бинарника `flit`), чтобы линковать `rust-lld` прямо с Windows [гипотеза]. Если не выйдет — собирать внутри WSL.
- Сборочный скрипт `crates/flit` берёт пути из `FLIT_WSL_AGENT_X64` и `FLIT_WSL_AGENT_ARM64` и встраивает файлы через `include_bytes!`. Нет файла — остаётся только упрощённый режим.
- Идентификатор агента: `<версия>-<первые 16 hex SHA-256 бинарника>`, вычисляется при сборке.

### 5.2 Доставка и запуск

Агент лежит в `${XDG_CACHE_HOME:-$HOME/.cache}/flit/agent-<id>`, каталог с правами 0700.

Тёплый путь — один запуск процесса:

```text
%SystemRoot%\System32\wsl.exe -d <distro> --exec /bin/sh -c 'exec "${XDG_CACHE_HOME:-$HOME/.cache}/flit/agent-<id>"'
```

`--exec` обходит login shell пользователя, `$HOME` раскрывает `sh`, а `exec` отдаёт агенту stdio напрямую. Абсолютный путь к `wsl.exe` защищает от подмены через `PATH` и текущий каталог.

Если `Hello` не пришёл (файла нет: `sh` пишет ошибку в stderr и выходит с кодом 127, stdout пуст, значит EOF), выполняется доставка с бинарником в stdin, затем ещё одна попытка тёплого пути:

```text
wsl.exe -d <distro> --exec /bin/sh -c 'set -e; d="${XDG_CACHE_HOME:-$HOME/.cache}/flit"; mkdir -p "$d"; chmod 700 "$d"; t="$d/agent-<id>.$$"; cat > "$t"; chmod 700 "$t"; mv -f "$t" "$d/agent-<id>"'
```

Не через `\\wsl.localhost`: так не нужно знать `$HOME`, нет 9P и не остаётся полузаписанных файлов (атомарный `mv`).

`wsl.exe` запускается в Job object с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`. Если `flit.exe` упадёт, `wsl.exe` завершится, агент получит EOF на stdin и выйдет, и дистрибутив сможет остановиться по простою.

### 5.3 Транспорт и Hello

- stdin и stdout `wsl.exe`, кадры `u32` LE + postcard (`flit-proto/src/transport.rs`), `MAX_FRAME` = 16 МиБ. stderr агента пишется в лог Flit.
- Обе стороны сразу шлют `Hello` (`transport::handshake`): `{ magic: "FLIT", protocol: Provider, version: provider::VERSION (= 1), build }`.
- Мусор вместо `Hello` (сообщение `wsl.exe` в UTF-16, предупреждения) даёт `NotFlit`; это покрыто тестом `handshake_errors_are_specific`.
- `NotFlit` или `VersionMismatch` → одна повторная доставка, иначе упрощённый режим для этого дистрибутива.
- `build` сейчас равен `CARGO_PKG_VERSION`, и две разработческие сборки одной версии неотличимы. В `build` нужно включить идентификатор из §5.1, а `VERSION` повышать при любом изменении сообщений: postcard не самоописываемый.
- Двоичная прозрачность stdio `wsl.exe` (без преобразования CRLF) — [гипотеза]; это первый тест.

### 5.4 Сообщения (`crates/flit-proto/src/provider.rs`)

| Запрос UI (`ProviderRequest`) | Агенту (`Request`) | От агента (`Event`) | В UI |
|---|---|---|---|
| `List { tab, gen, path, view, case, out, cancel }` | `List { id, path }` | `Entries { id, batch }`…, `ListDone { id, error }` | `EntryBatch::append_to` → `Listing`; `DirSnapshot` в `out` каждые 16 мс и в конце, как в `local::list`; сортировка на стороне Windows |
| `Watch { tab, gen, Some(path) }` | `Watch { id, path }` | `Changes { id, changes }`, `Rescan { id }` | `ProviderEvent::Changes` / `Rescan { tab, gen }` |
| `Watch { tab, gen, None }` | `Cancel { id наблюдения }` | — | — |
| `DirSizes { tab, gen, dir, items, cancel }` | `DirSizes { id, dir, items }` | `DirSize { id, idx, size }` | `ProviderEvent::DirSize` |
| `Op { id, op: Trash(paths) }` | `Op { id, op }` | `OpDone { id, error }` | `ProviderEvent::OpDone` |
| `Open { path }` | — | — | ShellExecute для `to_windows()` (§8) |
| — | `Stat { id, path }` | `Stat { id, result }` | проверка пути из адресной строки и из `Open` до создания вкладки |
| простой или выход | `Shutdown` | — | — |

Отмена. `WslProvider` проверяет `GenToken` на каждом входящем `Entries` и `DirSize`. Если запрос устарел, агенту уходит один `Cancel { id }`, дальнейшие события с этим `id` отбрасываются. Агент проверяет набор отменённых `id` между пачками `getdents64` и между каталогами в `DirSizes`.

Потоковая выдача: пачка `Entries` раз в ~16 мс или по 4096 записей, что наступит раньше (порог открыт).

### 5.5 Метаданные

| Поле `Meta` | Источник в Linux |
|---|---|
| `size` | `st_size` |
| `modified` | mtime из `statx` → такты FILETIME: (секунды + 11 644 473 600) × 10⁷ + наносекунды / 100 (как ожидает `fmt::datetime`) |
| `created` | btime при `STATX_BTIME`, иначе 0 |
| `DIR` | `S_ISDIR`; для ссылки — по цели, вместе с `LINK` |
| `LINK` | `S_ISLNK` |
| `HIDDEN` | имя начинается с `.` |
| `READONLY` | `mode & 0o222 == 0` |

WSL1: `statx` может вернуть `ENOSYS`, тогда используется `fstatat`.

### 5.6 Наблюдение (inotify)

- Маска: `IN_CREATE`, `IN_DELETE`, `IN_MOVED_FROM`, `IN_MOVED_TO`, `IN_MODIFY`, `IN_ATTRIB`, `IN_CLOSE_WRITE`, `IN_DELETE_SELF`, `IN_MOVE_SELF`, `IN_ONLYDIR`.
- События склеиваются за 50 мс в `Changes`; для `Added` и `Modified` метаданные берутся через `fstatat`.
- `IN_Q_OVERFLOW`, `IN_DELETE_SELF`, `IN_MOVE_SELF`, `IN_IGNORED` → `Rescan`.
- `ENOSPC` (исчерпан `max_user_watches`) → наблюдения нет, запись в лог.
- Изменения, сделанные Windows в `/mnt/c` (DrvFs), inotify не видит. Такие пути лучше открывать как локальные (§12).

### 5.7 Корзина (freedesktop Trash 1.0)

- Файл на устройстве домашней корзины идёт в `$XDG_DATA_HOME/Trash` (по умолчанию `~/.local/share/Trash`). Иначе — в `$topdir/.Trash/$uid`, если `.Trash` — каталог со sticky bit и не ссылка, иначе в `$topdir/.Trash-$uid` (создаётся с правами 0700).
- Сначала `info/<имя>.trashinfo` создаётся с `O_CREAT | O_EXCL` (при конфликте `<имя>.2`, `<имя>.3`, …). Содержимое: `[Trash Info]`, `Path=` (percent-encoded; абсолютный путь для домашней корзины, относительно `$topdir` для остальных), `DeletionDate=YYYY-MM-DDThh:mm:ss` по местному времени. Затем `rename(2)` в `files/<имя>`. Если `rename` не удался, `.trashinfo` удаляется и возвращается ошибка.
- Копирования между устройствами нет: при `EXDEV` приходит `OpDone` с ошибкой, а UI может предложить удаление без корзины.
- Кэш `directorysizes` не ведётся.

### 5.8 Размеры каталогов

Итеративный обход через `openat` + `getdents64`, `fstatat(AT_SYMLINK_NOFOLLOW)`, ссылки не разыменовываются, суммируется `st_size`, отмена проверяется на каждом каталоге. Семантика та же, что у `tree_size` в `local.rs`.

## 6. Обнаружение дистрибутивов

Источник — `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss`. В корне `DefaultDistribution` (GUID), в подключах `{GUID}`:

| Значение | Смысл | На этой машине [реестр] |
|---|---|---|
| `DistributionName` | имя для `-d` и для `wsl://` | `Ubuntu-22.04` |
| `Version` | 1 = WSL1, 2 = WSL2 | 2 |
| `State` | 1 = установлен; другие значения (установка, удаление, конвертация) пропускаются | 1 |
| `BasePath` | каталог дистрибутива | `D:\WSL\Ubuntu-22.04` |
| `DefaultUid` | пользователь по умолчанию | 1000 |
| `Flags` | interop, `PATH`, монтирование дисков, WSL2 | `0xF` |
| `VhdFileName` | диск WSL2 | `ext4.vhdx` |
| `Flavor`, `OsVersion` | подпись | `ubuntu`, `22.04` |

- Чтение реестра дистрибутивы не будит. Список обновляется по `RegNotifyChangeKeyValue` на `Lxss` в фоновом потоке.
- «Этот компьютер» показывает дистрибутивы из реестра как `Ubuntu-22.04 (WSL)` → `wsl://Ubuntu-22.04/`. Сейчас `volumes()` перечисляет только буквы дисков.
- Без действия пользователя — никаких обращений к `\\wsl.localhost\<distro>` и запусков `wsl.exe -d`: и то и другое запускает дистрибутив [поведение WSL, здесь не проверялось]. Открыть такую строку значит согласиться на запуск; в строке состояния — «Запуск Ubuntu-22.04…».
- WSL1: файлы под `BasePath\rootfs` никогда не трогать напрямую, только через `\\wsl.localhost` или агента.
- Имя дистрибутива в `Location` приводится к написанию из реестра (сравнение без учёта регистра). Сейчас `\\wsl$\ubuntu-22.04` даёт отдельный дистрибутив `ubuntu-22.04` и отдельного провайдера.

Как узнать, что дистрибутив запущен:

- если агент этого дистрибутива в состоянии «Готов», он запущен, и лишние процессы не нужны;
- иначе `wsl.exe --list --running --quiet` с `WSL_UTF8=1` в окружении (без него вывод в UTF-16LE). Дистрибутивы эта команда не запускает, но может запустить службу WSL. Вызывается вне UI-потока, только когда «Этот компьютер» на экране, результат кэшируется на 5 с. Время не измерялось.

## 7. Жизненный цикл агента

| Состояние | Что происходит | Переходы |
|---|---|---|
| Нет агента | исходное | первый запрос к `wsl://<d>`, вызванный действием пользователя → Запуск |
| Запуск | тёплый путь (§5.2) | `Hello` принят → Готов; `NotFlit` или EOF → Доставка (один раз); нет `Hello` за 15 с (холодный старт ВМ) → Упрощённый |
| Доставка | запись бинарника | успех → Запуск; ошибка → Упрощённый |
| Готов | обслуживание запросов | 5 мин без вкладок и наблюдений → Остановка; EOF или ошибка ввода-вывода → Упал |
| Остановка | `Shutdown`, закрыть stdin, ждать 1 с, затем `TerminateProcess` для `wsl.exe` | → Нет агента |
| Упал | ожидающие запросы завершаются ошибкой, вкладки помечаются устаревшими | следующий запрос от действия пользователя (навигация, F5) → Запуск; 3 падения за 5 мин → Упрощённый |
| Упрощённый | `via_unc` + `LocalProvider` | до перезапуска Flit или ручного «Повторить» |

Автоматического перезапуска после падения нет. Пользователь мог сам остановить дистрибутив (`wsl --terminate`, `wsl --shutdown`), а восстановление наблюдений разбудило бы его снова. Наблюдения возвращаются только после перезапуска, который вызвал пользователь.

Агент живёт, пока открыт stdin: EOF — выход. Работающий агент держит дистрибутив запущенным, поэтому остановка по простою важна для памяти и батареи.

## 8. Открытие файлов

| Действие | Механизм | Ограничения |
|---|---|---|
| Enter, двойной щелчок | ShellExecuteEx для `to_windows()`; приложение Windows по ассоциации читает файл через 9P | непредставимое имя → ошибка «имя не представимо в Windows»; имя с точкой или пробелом на конце → отказ |
| «Открыть в Linux» (стадия 2) | агент запускает `xdg-open` с сырыми байтами пути (новый `Request::Open { id, path }`); GUI Linux показывается через WSLg | через `wsl.exe` с путём в argv нельзя: argv у `wsl.exe` UTF-16, невалидный UTF-8 не передать |
| «Терминал здесь» | `wsl.exe -d <distro> --cd <путь Linux>` | только пути в UTF-8 |
| Исполняемый файл Linux | ShellExecute его не запустит | только «Открыть в Linux» или терминал |

## 9. Копирование и перемещение

Сейчас в `FileOp` есть только `Trash`: копирования во Flit нет вообще, ни локально, ни для WSL. План:

| Направление | Механизм | Почему |
|---|---|---|
| Windows ↔ WSL | движок копирования Windows (`IFileOperation` или `CopyFileEx`) по `\\wsl.localhost\…` | прогресс, конфликты и отмена как у локальных операций; скорость 9P |
| внутри одного дистрибутива | агент: `rename(2)`, иначе `copy_file_range`; новые варианты `FileOp` (`Copy`, `Move`, `Rename`, `Mkdir`, `Delete`), общие для `LocalProvider` и агента | намного быстрее 9P; сохраняются права, владелец и ссылки, которые 9P теряет [гипотеза] |
| между дистрибутивами | через Windows (9P на обоих концах) | редкий случай |
| имена, непредставимые в Windows | только агентом; на стороне Windows — ошибка с именем файла | 9P такие имена не адресует |

## 10. Поиск

- Служба индекса и агент делят тип `EntryBatch` (`flit-proto/src/listing.rs`; в `flit-search/src/proto.rs` — `Message::Rows { entries: EntryBatch, dirs }`).
- Рекомендация: индекс дистрибутива ведёт сам агент внутри дистрибутива (`WalkIndex` из `flit-platform-linux` + inotify) и отвечает по протоколу `flit-search` (`Query`, `GetRows`, `Rows`, `IndexStatus`). Это второй процесс агента с `Hello { protocol: Index }`, запущенный тем же способом. Поиск Flit объединяет ответы `flit-indexd` (тома Windows) и агентов, добавляя к `dirs` префикс `wsl://<distro>`.
- Почему не стримить обход в `flit-indexd`: при каждом старте дистрибутива через канал шли бы миллионы записей, служба индекса будила бы дистрибутивы, а изменения всё равно видны только изнутри (inotify).
- Участвуют только запущенные дистрибутивы; поиск их не будит.
- `\\wsl.localhost` не является томом NTFS и в MFT-индекс не попадает; `ext4.vhdx` индексируется как обычный файл.

## 11. Безопасность

Граница доверия — канал агента. Дистрибутив может быть скомпрометирован, а имена файлов Linux всегда приходят из внешних источников (архивы, git). Всё, что прислал агент, проверяется:

- кадры не больше 16 МиБ, `Hello` не больше 256 байт, иначе разрыв;
- `EntryBatch::entries()` отвергает пустые имена, `.`, `..`, имена с `/` или NUL и несовпадение длин, включая переполнение суммы;
- `FsPath` при декодировании отвергает относительные пути, а `..` схлопывается лексически и за корень не выходит;
- **дыра**: имена в `Event::Changes` (`DirChange.name`) сейчас не проверяются; нужна та же проверка, что в `EntryBatch`;
- `FsPath::parse_exact` отвергает NUL (исправлено, `external-open.md`, §7.4).

Остальное:

- Агент тоже проверяет вход: путь должен быть вида `PathKind::Unix`, имена в `DirSizes.items` проверяются по тем же правилам, а NUL не пройдёт через `CString`.
- Имена Linux с `\` и `:` законны и передаются как есть. Путь Windows никогда не собирается склейкой строк, только как `Location::Wsl.join(name).to_windows()`.
- Имя дистрибутива берётся из реестра. При разборе `wsl://` и `\\wsl$` его нужно ограничить набором `[A-Za-z0-9._-]` длиной до 64 символов и запретить `.` и `..`. Сейчас допустим любой UTF-8 без `\`, и он подставляется в `\\wsl.localhost\<distro>`.
- Канал — stdio дочернего процесса: ни TCP, ни Unix-сокетов, ни сокетов в файловой системе, другой процесс к агенту не подключится.
- Агент работает от пользователя дистрибутива по умолчанию, без повышения прав. Доступа к Windows у него не больше, чем у любого процесса Linux с interop.
- Файл агента в `~/.cache/flit` (0700) может подменить только тот, кто уже владеет учётной записью Linux; новых прав это не даёт. Подмену выявит `Hello` (идентификатор сборки), а данные всё равно проходят проверки выше.
- `wsl.exe` и `explorer.exe` запускаются по абсолютному пути из `%SystemRoot%`.

## 12. Открытые вопросы

1. Экранирование U+F000, поведение 9P с именами, оканчивающимися точкой или пробелом, и зарезервированными именами. Проверить на живом `\\wsl.localhost\Ubuntu-22.04`; проба создаёт файлы в дистрибутиве и запускает его, поэтому нужно одобрение.
2. Работает ли `ReadDirectoryChangesW` на `\\wsl.localhost`. Если да, упрощённый режим получит обновления.
3. Windows 10: `\\wsl.localhost` есть только у WSL из Store, у старого встроенного WSL — только `\\wsl$`, и `to_windows()` должен уметь откатываться. Не проверялось.
4. Чувствительность к регистру для WSL-вкладок (`CaseMode::Sensitive` по провайдеру): сортировка, поиск по набору, выделение по имени.
5. `wsl://<d>/mnt/c/…`: открывать как `C:\…` (быстрее, есть `ReadDirectoryChangesW`) или оставлять в WSL.
6. Время запуска `wsl.exe` для запущенного и остановленного дистрибутива и скорость листинга 9P против агента не измерялись.
7. Уборка старых `agent-*` в `~/.cache/flit`, когда одновременно работают несколько версий Flit.
8. Размер пачки `Entries`, тайм-ауты `Hello` и `Stat`, срок простоя (5 мин).
9. Индекс внутри дистрибутива: хранить ли его на диске (`~/.cache/flit/index-*`), лимит памяти.
10. Видимая отрисовка управляющих и bidi-символов в именах Linux.
