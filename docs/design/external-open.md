# Внешние открытия: Flit как файловый менеджер по умолчанию

Статус: проект. Стадия 1 (разбор аргументов, единственный экземпляр, маршрутизация во вкладки) реализована; регистрация обработчика, перехват выделения через `SHOpenFolderAndSelectItems` и Linux не реализованы.

Пометки в тексте:

- **[код Files]** подтверждено исходниками [files-community/Files](https://github.com/files-community/Files);
- **[реестр]** наблюдалось read-only (`reg query`) на машине разработки;
- **[код Flit]** так работает текущий код;
- **[гипотеза]** не проверялось, требует пробы из §10.

## 1. Цель

Любое внешнее «открыть папку» или «показать файл в папке» превращается в новую вкладку в уже запущенном Flit (в последнем активном окне), с выделением, если оно было запрошено. Регистрация без UAC, полностью обратимая, не ломает другие файловые менеджеры.

Не цели: системный перехват `explorer.exe` (IFEO), замена рабочего стола и панели задач, диалоги открытия и сохранения.

### 3.1 Навигация внутри окон Explorer

Лаунчер Files, если его родитель — процесс оболочки и уже открыто окно Explorer, показывающее родителя цели (или Панель управления `{26EE0668-…}`), вызывает в этом окне `IShellBrowser::BrowseObject` и выходит [код Files]. Отсюда следует, что после замены `Folder\shell\open` двойной щелчок внутри окна Explorer запускает обработчик, а не навигацию на месте. Без такой же логики во Flit перестанет работать навигация по Панели управления и по окнам Explorer, открытым через `explorer.exe`.

План для Flit: проверку делает первичный экземпляр (у него COM уже прогрет), а пересылающий процесс только сообщает, что его родитель — оболочка (`GetShellWindow` → PID против PID родителя, без COM). Для этого в `Open` нужен признак происхождения, то есть протокол v2. Если первичного нет, проверку делает новый процесс до создания окна.

## 4. Поток стадии 1 [код Flit]

1. `main` (`crates/flit/src/main.rs`): `args_os` → WTF-8 (`name::push_utf16`, одиночные суррогаты сохраняются) → `open::parse_args(args, cwd)` → `Open`.
2. `PipeInstance::acquire(&open)` вызывается **до** логирования, D3D, DirectWrite и COM. Результат `Forwarded` → выход; `Primary` → `listen()`; `Standalone` → обычное окно без приёма пересылок.
3. Первичный: поток `flit-instance` принимает соединения, `serve` кладёт `Open` в канал, будит UI и отвечает `Accepted`.
4. `Handler::drain` собирает очередь, `apply_opens` применяет её только в активном окне: пустой `Open` → домашняя папка, затем `App::open`, затем `window.activate()`.
5. `App::open` → `open::routes` (разрешение путей) → ошибки в строку состояния → `App::dispatch(routes, target)`, единственная точка маршрутизации: `Default` → `App.open_target` (по умолчанию `NewTab`), `NewTab`, `CurrentTab` (первый маршрут в текущей вкладке, остальные новыми вкладками), `NewWindow` → `Effect::NewWindow`.

## 5. Единственный экземпляр

### 5.1 Имена

| Объект | Имя | Комментарий |
|---|---|---|
| mutex | `Local\flit-<SID>` | `Local\` — пространство имён сеанса; первичный держит handle до выхода процесса |
| канал | `\\.\pipe\flit-<SID>-<session>` | имена каналов общие для всей машины, поэтому номер сеанса входит в имя |

`SID` — строковый SID из `TokenUser`, `session` — `ProcessIdToSessionId`.

### 5.2 Алгоритм

1. `CreateMutexW`. Mutex создан заново → `Primary`; канал создаётся позже в `listen()`, первый экземпляр с `FILE_FLAG_FIRST_PIPE_INSTANCE`, все с `PIPE_REJECT_REMOTE_CLIENTS`, по потоку на соединение.
2. Mutex уже был → закрыть handle → `connect`: повтор до 3 с (5 мс сна при отсутствии канала, `WaitNamedPipeW` 200 мс при `ERROR_PIPE_BUSY`).
3. `GetNamedPipeServerProcessId` → `AllowSetForegroundWindow(pid)`.
4. Одна запись: `Hello` + `Request::Open`. Затем чтение `Hello` и `Reply::Accepted` → `Forwarded`, выход.
5. Любая ошибка → `Standalone(err)`: своё окно без приёма пересылок.

### 5.3 Безопасность

Есть: отказ удалённым клиентам; обнаружение захвата имени при старте первичного (`FIRST_PIPE_INSTANCE` не даст создать канал, ошибка в лог); проверка `Hello` (magic, протокол, версия); лимиты кадра 16 МиБ и `Hello` 256 байт; `FsPath` при декодировании отвергает относительные пути.

Надо доделать:

| Проблема | Решение |
|---|---|
| DACL канала по умолчанию даёт Everyone чтение | явный DACL `D:P(A;;GA;;;<SID>)(A;;GA;;;SY)` |
| пространство каналов глобальное: другой пользователь может заранее создать `\\.\pipe\flit-<наш SID>-<session>` и получать наши пути | клиент проверяет сервер: `GetNamedPipeServerProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → SID владельца токена равен нашему, иначе `Standalone`. Сейчас `AllowSetForegroundWindow` вызывается до какой-либо проверки |
| повышенный и обычный процессы одного пользователя делят имена; канал повышенного первичного, вероятно, закрыт на запись для обычного клиента → каждый обычный запуск уходит в `Standalone` | суффикс `-admin` в обоих именах при `TokenElevation` |
| `Open` из канала — недоверенные данные | тот же `resolve`, что и для командной строки, плюс запрет NUL (§7.4) |

### 5.4 Бюджет времени пересылающего процесса: < 20 мс от `CreateProcess` до выхода

| Этап | Сейчас | Мера |
|---|---|---|
| Загрузчик | `flit.exe` статически импортирует `d3d11`, `dcomp`, `dwrite`, `dwmapi`, `gdi32`, `imm32`, `ole32`, `oleaut32`, `combase`, `shell32`, `user32`, `advapi32` и CRT (`objdump -p target\release\deps\flit.exe`). Все они отображаются до `main` и в пересылающем процессе: ранняя развилка в `main.rs` экономит инициализацию D3D, DirectWrite и COM, но не загрузку DLL | `/DELAYLOAD` для `d3d11`, `dcomp`, `dwrite`, `dwmapi`, `imm32`, `ole32`, `oleaut32`, `shell32` + `delayimp.lib` в сборочном скрипте `crates/flit`; замер до и после |
| `main` до выхода | аргументы, cwd, SID, mutex, один обмен по каналу; без COM, окон и тяжёлых аллокаций | 0,4 мс (`FLIT_TIMING`) |

**Сделано.** `/DELAYLOAD` для `d3d11`, `dcomp`, `dwrite`, `dwmapi`, `imm32`, `ole32`, `oleaut32`, `shell32`, `combase` (`crates/flit/build.rs`). Замер на машине из `docs/metrics.md`, медиана 15 запусков, время жизни процесса `ExitTime − StartTime`: пересылающий `flit.exe` — 31,8 мс до и 28,5 мс после; пустой `where.exe /?` — 24,1 мс. Сам `CreateProcess` с проверкой Defender съедает больше бюджета в 20 мс ещё до первой инструкции, а собственная цена Flit теперь около 4–5 мс. Цель «< 20 мс от `CreateProcess`» на этой машине недостижима ни для какого exe; честная цель — «≤ 5 мс сверх пустого процесса».
| Сторона первичного | `Accepted` уходит сразу после постановки в очередь, работа UI во время пересылающего процесса не входит | — |
| Худший случай | 3 с: первичный стартует, а канала ещё нет, или завис до `listen` | — |

Ничего из этого не измерялось. Метод: при запущенном первичном 20 раз `Measure-Command { Start-Process -Wait $flit 'C:\Windows' }` минус то же для пустого exe; либо события ETW начала и конца процесса.

### 5.5 Права на передний план

Процесс, запущенный оболочкой в ответ на ввод пользователя, имеет право вывести окно на передний план. Он передаёт это право первичному через `AllowSetForegroundWindow(pid сервера)` до отправки, а первичный в `apply_opens` вызывает `window.activate()` (`SW_RESTORE` для свёрнутого окна + `SetForegroundWindow`). Без `AttachThreadInput` и трюка с TOPMOST, которыми пользуется Files (`BringToForegroundEx`). Если право истекло (пользователь успел щёлкнуть в другое место), Windows мигает кнопкой на панели задач, это приемлемо.

### 5.6 Несовпадение версий

Сервер всегда отвечает своим `Hello`, даже при несовпадении, и закрывает соединение без `Accepted`. Клиент получает `VersionMismatch { ours, theirs, build }` → `Standalone`: отдельное окно без пересылки. Сообщение сейчас уходит в stderr, у GUI-процесса его не видно; его надо показывать в строке состояния. `instance::VERSION` повышается при любом изменении `Open`, `Request` или `Reply`, потому что postcard не самоописываемый. После обновления, пока работает старый первичный, новые запуски открывают отдельные окна.

### 5.7 Первичный стартует или завершается

| Ситуация | Сейчас | Нужно |
|---|---|---|
| Первичный стартует: mutex есть, канала ещё нет | клиент опрашивает каждые 5 мс до 3 с; канал появляется после `Ws::new` и `LocalProvider::new`, до первого окна и D3D | `Open`, пришедший до создания первого окна, применяется только на первом `woken` после него; вызывать `apply_opens` из `created` |
| UI первичного завис | поток канала жив → `Accepted` → вкладка появится, когда UI оживёт | — |
| Первичный упал | ядро освобождает mutex, следующий запуск становится первичным | — |
| Первичный завершается, `Handler` уже уничтожен | `send` не проходит → нет `Accepted` → EOF → `Standalone` без приёма пересылок | при EOF после корректного `Hello` повторять `acquire` (до 10 раз по 50 мс), чтобы стать первичным |
| Последнее окно закрыто, `Handler` ещё жив | `Open` принят и потерян | в `destroyed` последнего окна разобрать очередь; если она не пуста, открыть окно вместо выхода |
| Несколько клиентов одновременно | `PIPE_UNLIMITED_INSTANCES`, поток на соединение | — |

## 6. Протокол Instance

Кадр: длина `u32` LE + полезная нагрузка postcard (`flit-proto/src/transport.rs`). Одно соединение = один запрос.

```text
клиент → сервер:  [len][Hello{magic:"FLIT", protocol:Instance, version:1, build}] [len][Request::Open(Open)]   одной записью
сервер → клиент:  [len][Hello]  [len][Reply::Accepted]
```

| Поле `Open` | Тип | Смысл |
|---|---|---|
| `paths` | `Vec<Vec<u8>>` | что открыть: сырые байты WTF-8 как в argv, без разрешения |
| `select` | `Vec<Vec<u8>>` | что показать выделенным в родительской папке |
| `target` | `OpenTarget` | `Default`, `NewTab`, `NewWindow`, `CurrentTab` |
| `cwd` | `Option<Vec<u8>>` | текущий каталог отправителя |

Разрешает пути получатель: относительные — от `cwd`, `shell:` и `::{…}` — через `known_folder`, `file:///` — percent-decoding, `\\wsl$` и `\\wsl.localhost` → `Location::Wsl`. Так пересылающий процесс не трогает shell32 и COM, а ошибки разрешения видны в UI. `Accepted` означает «поставлено в очередь», а не «показано».

## 7. Грамматика аргументов `flit.exe`

### 7.1 Что принимается [код Flit, `open::parse_args` и `open::resolve`]

| Аргумент | Результат |
|---|---|
| `<путь>` (абсолютный, относительный от cwd, в кавычках или без) | папка в новой вкладке |
| `/select,<путь>` | вкладка в родителе, `<путь>` выделен. Всё после первой запятой — путь, запятые внутри сохраняются |
| `/root,<путь>` | как `<путь>`, семантика корня игнорируется |
| `/e,` `/separate,` `/n,` | префиксы, допускается цепочка в одном аргументе (`/n,/e,/select,X`); `/n` → `NewWindow` |
| `/idlist,…` | игнорируется до конца аргумента (PIDL в разделяемой памяти Flit прочитать не может) |
| `shell:<имя>`, `::{CLSID}` | «Этот компьютер» → корень; иначе файловый путь известной папки; иначе ошибка `Cannot open … in Flit` |
| `file:///C:/a%20b/`, `file:///home/u` | путь после percent-decoding |
| `wsl://<distro>/<путь>`, `\\wsl$\…`, `\\wsl.localhost\…` | `Location::Wsl` (см. `wsl.md`) |
| `--new-tab`, `--new-window`, `--current-tab` | цель открытия; последний флаг побеждает |
| `--metrics <файл>` | режим замера, без единственного экземпляра |
| прочие `--…` | игнорируются (место для будущих `--register-default` и `--unregister-default`) |

### 7.2 Примеры

```text
flit C:\Windows                               → вкладка C:\Windows
flit /select,"C:\Program Files\x\app.exe"     → вкладка C:\Program Files\x, выделен app.exe
flit /n,/e,/select,C:\x\y.txt                 → новое окно, C:\x, выделен y.txt
flit /e, C:\Users                             → вкладка C:\Users
flit shell:Downloads ::{20D04FE0-3AEA-1069-A2D8-08002B30309D}   → две вкладки: Загрузки и Этот компьютер
flit src\lib                                  → вкладка <cwd>\src\lib
flit "D:\"                                    → argv = D:" (правило \" в CommandLineToArgvW); кавычка срезается → D:\
flit --current-tab \\wsl$\Ubuntu-22.04\home   → текущая вкладка wsl://Ubuntu-22.04/home
```

### 7.3 Расхождения с explorer.exe

| Случай | explorer.exe | Flit | Что делать |
|---|---|---|---|
| Разбор | [гипотеза] режет сырую командную строку по запятым | argv по правилам MSVC, потом запятые внутри аргумента | при первом токене на `/` разбирать `GetCommandLineW` по правилам Explorer |
| `/select, C:\a.txt` (пробел после запятой) | выделяет `C:\a.txt` | **исправлено**: следующий аргумент после пустого `/select,` (или `/root,`) считается его значением | — |
| `/select,C:\a b\c.txt` без кавычек | работает | два аргумента: выделение `C:\a`, папка `b\c.txt` | решается сырым разбором |
| Несколько `/select` в одной папке | одно выделение | отдельная вкладка на каждый элемент (`Route.select` одиночный) | `Route.select: Vec`, слияние по папке; нужно и для `SHOpenFolderAndSelectItems` с несколькими элементами |
| Linux: путь `/e` или `/n` | — | съедается как ключ | на Linux грамматику Explorer не применять |

### 7.4 Проверка входа

`FsPath::parse_exact` принимает байт NUL, а Win32 обрезает строку по NUL. Путь `C:\Docs\<NUL>x` покажет содержимое `C:\Docs`, а «Удалить» элемента `a.txt` в этой вкладке передаст в корзину `C:\Docs\<NUL>x\a.txt`, то есть **всю папку** `C:\Docs`. Источники: `Open` через канал и `file:///C:/Docs/%00x` (`percent_decode` даёт 0x00). **Исправлено**: `FsPath::parse_exact` отвергает любой байт NUL. Через него проходят все формы, включая декодированный `file:///`, поэтому отдельная проверка в `percent_decode` не нужна (тесты `verbatim_and_unc` и `resolution`).

## 8. Регистрация обработчика по умолчанию

### 8.1 Что пишется

Всё в `HKCU\Software\Classes`. Команда — `REG_SZ` `"<абсолютный путь flit.exe>" "%1"`, не `REG_EXPAND_SZ`.

| Ключ | Значение | Данные |
|---|---|---|
| `Folder\shell\open\command` | `(Default)`; `DelegateExecute` | команда; `""` |
| `Folder\shell\explore\command` | `(Default)`; `DelegateExecute` | команда; `""` |
| `Directory\shell` | `(Default)` | `open` |
| `Directory\shell\open\command` | `(Default)`; `DelegateExecute` | команда; `""` |
| `Drive\shell` | `(Default)` | `open` |
| `Drive\shell\open\command` | `(Default)`; `DelegateExecute` | команда; `""` |
| `CLSID\{52205fd8-5dfb-447d-801a-d0b52f2e83e1}\shell\opennewwindow\command` | `(Default)`; `DelegateExecute` | `"<flit.exe>"` без `%1`; `""` |

После записи `SHChangeNotify(SHCNE_ASSOCCHANGED, SHCNF_IDLIST, null, null)`. Пишет сам Flit через `RegSetValueExW`, без regedit, PowerShell и UAC.

`DelegateExecute` задаётся пустой строкой, а не удаляется: в объединённом представлении HKCR значение `{11dbb47c-…}` (COM-обработчик Explorer) из HKLM иначе остаётся видимым. Files и FilePilot делают так же [код Files, реестр]; точная семантика слияния по значениям — [гипотеза].

`Directory` и `Drive` нужны потому, что verb по умолчанию для файловых папок берётся из `Directory`. В HKLM там `none`, и тогда срабатывает `Folder\shell\open`, но любой менеджер, записавший HKCU `Directory\shell` = `open`, перебивает `Folder`. Именно так регистрируется FilePilot [реестр]; регистрация только `Folder`, как у Files, ему бы проиграла.

### 8.2 Резервная копия

- `HKCU\Software\Flit\Backup\<тот же относительный путь>`: для каждого изменяемого значения — копия с тем же именем, типом и данными.
- Значение `Absent` (`REG_MULTI_SZ`) в том же ключе копии: имена значений, которых до регистрации не было.
- В корне `Backup`: `CreatedKeys` (`REG_MULTI_SZ`, ключи, созданные Flit) и `Command` (`REG_SZ`, точная записанная команда).
- Копия пишется один раз и **до** любых изменений. Повторная регистрация существующую копию не перезаписывает.

### 8.3 Точный откат

1. Для каждого значения из копии: если текущие данные всё ещё равны записанным Flit — восстановить исходные (или удалить, если значение в `Absent`); если их уже переписал другой менеджер — не трогать.
2. Удалить ключи из `CreatedKeys`, начиная с самых глубоких, и только если они пусты.
3. Удалить `HKCU\Software\Flit\Backup`, вызвать `SHChangeNotify`.
4. Никогда не удалять ключи, которые создал не Flit. Для сравнения: `UnsetFilesAsDefault.reg` удаляет весь HKCU `CLSID\{52205fd8-…}` и значение по умолчанию `Directory\shell`, а `Folder` восстанавливает зашитыми значениями без копии [код Files]. На этой машине это снесло бы Win+E и обработку папок FilePilot.

### 8.4 Интерфейс

Переключатель в настройках и `flit --register-default` / `--unregister-default` (обрабатываются в `main` до `acquire`; второй нужен деинсталлятору). Признак «Flit по умолчанию»: HKCR `Folder\shell\open\command` и `Directory\shell\open\command` содержат путь текущего `flit.exe`.

### 8.5 Отличия от Files

| | Files | Flit |
|---|---|---|
| Права | `regedit /s` с `runas`, UAC в обе стороны | HKCU из процесса, без UAC |
| Покрытие | `Folder` + Win+E | `Folder`, `Directory`, `Drive` + Win+E |
| Откат | зашитые значения по умолчанию | точная копия; чужие более поздние регистрации не трогаются |
| Передача в приложение | протокол `files-dev:?cmd=<hex>`, `WaitForInputIdle` 5 с, `Sleep` 2 с | именованный канал, один обмен |
| Длинные пути | `WCHAR openDirectory[MAX_PATH]`, обрезка свыше 260 символов | без ограничения |
| `/select` из командной строки | не поддерживается | поддерживается |
| Передний план | `AttachThreadInput` + TOPMOST | `AllowSetForegroundWindow` от пересылающего процесса |

### 8.6 Риски

- `flit.exe` перемещён или удалён при активной регистрации: любое открытие папки падает с «не найдено приложение». Отдельного лаунчера с самовосстановлением, как у Files, нет. Деинсталлятор обязан вызывать `--unregister-default`; ручное восстановление нужно описать. При старте Flit может предлагать исправить регистрацию, указывающую на другой путь.
- Виртуальные папки и навигация внутри окон Explorer (§3, §3.1): без запасного пути в Explorer переключатель включать нельзя.

## 9. Что осталось

### 9.1 До включения переключателя

1. Запасной путь для `UnknownShellLocation`: запуск `%SystemRoot%\explorer.exe <аргумент>` (абсолютный путь). Отсутствие цикла подтвердить пробой (§10, п. 6).
2. Проверка сервера и DACL канала (§5.3). Запрет NUL (§7.4) сделан.
3. `::{52205fd8-…}` в `THIS_PC`. Исправление `/select, <путь>` сделано.
4. Навигация внутри окон Explorer (§3.1).

### 9.2 Выделение для `SHOpenFolderAndSelectItems`

Фиктивное окно оболочки, как у Files, но в первичном экземпляре на отдельном STA-потоке: на каждый `Open` от обработчика регистрировать ожидающее окно для папки на ≤ 10 с, `SelectItem` превращать в `Route { select }`. Тогда пересылающий процесс остаётся в бюджете и сразу выходит. Вариант Files (окно в самом лаунчере) требует COM и цикла сообщений и держит процесс живым от 0,5 до 10 с.

Отдельный вопрос — постоянно регистрировать настоящие вкладки в `IShellWindows`. Тогда `SHOpenFolderAndSelectItems` выделял бы элемент в уже открытой вкладке, но побочные эффекты для других инструментов, перечисляющих окна оболочки, неизвестны.

### 9.3 Прочее

Переиспользование открытой вкладки с той же папкой (Files переключается на неё, выделение теряет); `Route.select: Vec`.

## 10. Процедура живой пробы (только с одобрения пользователя)

Меняет HKCU-обработчики папок, дисков и Win+E, в том числе временно перебивает обработчики других файловых менеджеров. Полностью обратима: экспорт до изменений, удаление и импорт после.

Предусловия: стабильная сборка `flit.exe` по постоянному пути; Explorer и другие файловые менеджеры закрыты; есть точка восстановления или хотя бы экспорт из шага 1.

Шаг 1. Снимок и экспорт:

```powershell
$flit = 'D:\Flit\target\release\flit.exe'
$bak = "$env:LOCALAPPDATA\Flit\probe-$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory -Force $bak | Out-Null
$keys = @(
  'HKCU\Software\Classes\Folder\shell\open',
  'HKCU\Software\Classes\Folder\shell\explore',
  'HKCU\Software\Classes\Directory\shell',
  'HKCU\Software\Classes\Drive\shell',
  'HKCU\Software\Classes\CLSID\{52205fd8-5dfb-447d-801a-d0b52f2e83e1}'
)
for ($i = 0; $i -lt $keys.Count; $i++) {
  reg.exe export $keys[$i] "$bak\$i.reg" /y
  reg.exe query $keys[$i] /s >> "$bak\before.txt"
}
```

Если ключа не было, `reg export` завершится ошибкой и файла не будет: при восстановлении такой ключ только удаляется.

Шаг 2. Прописать Flit:

```powershell
$cmd = '"' + $flit + '" "%1"'
$sets = [ordered]@{
  'Folder\shell\open\command' = $cmd
  'Folder\shell\explore\command' = $cmd
  'Directory\shell\open\command' = $cmd
  'Drive\shell\open\command' = $cmd
  'CLSID\{52205fd8-5dfb-447d-801a-d0b52f2e83e1}\shell\opennewwindow\command' = '"' + $flit + '"'
}
foreach ($k in $sets.Keys) {
  $p = "HKCU:\Software\Classes\$k"
  if (-not (Test-Path -LiteralPath $p)) { New-Item -Path $p -Force | Out-Null }
  Set-ItemProperty -LiteralPath $p -Name '(default)' -Value $sets[$k]
  Set-ItemProperty -LiteralPath $p -Name 'DelegateExecute' -Value ''
}
Set-ItemProperty -LiteralPath 'HKCU:\Software\Classes\Directory\shell' -Name '(default)' -Value 'open'
Set-ItemProperty -LiteralPath 'HKCU:\Software\Classes\Drive\shell' -Name '(default)' -Value 'open'
```

`New-Item -Force` вызывается только для отсутствующих ключей: на существующем ключе реестра он стирает его содержимое.

Шаг 3. Матрица (каждый пункт — при запущенном и при незапущенном Flit; записывать, что открылось и с каким аргументом):

| # | Действие | Ожидание при перехвате |
|---|---|---|
| 1 | двойной щелчок по папке на рабочем столе | вкладка Flit |
| 2 | двойной щелчок по диску в «Этот компьютер» (окно Explorer открыто до шага 2 через `explorer.exe`) | вкладка Flit |
| 3 | двойной щелчок по папке внутри существующего окна Explorer | вкладка Flit вместо навигации на месте (подтверждает §3.1) |
| 4 | Win+E | вкладка Flit; что пришло в argv |
| 5 | Win+R: `C:\Windows`; `shell:Downloads`; `shell:RecycleBinFolder`; `::{20D04FE0-3AEA-1069-A2D8-08002B30309D}` | вкладки; для Корзины — текущая ошибка Flit |
| 6 | cmd: `explorer.exe C:\Windows`; `explorer.exe /select,C:\Windows\notepad.exe`; `explorer.exe /e,C:\`; `explorer.exe` | гипотеза: Explorer, не Flit |
| 7 | cmd: `start "" C:\Windows`; `start "" "file:///C:/Windows/"` | вкладка Flit |
| 8 | Edge: загрузки → «Показать в папке»; VS Code: Reveal in File Explorer | вкладка с папкой, без выделения |
| 9 | Корзина на рабочем столе; Панель управления → переход в категорию | что именно ломается |
| 10 | контекстное меню папки | нет ли двух пунктов «Открыть»; кто обрабатывает «Открыть в новом окне» |
| 11 | Блокнот → Открыть → вход в папку | навигация остаётся в диалоге |
| 12 | ярлык `.lnk` на папку; «Главная»; библиотеки; `\\wsl.localhost\Ubuntu-22.04` в Win+R (запустит дистрибутив) | записать аргумент и результат |

Шаг 4. Восстановление и проверка:

```powershell
for ($i = 0; $i -lt $keys.Count; $i++) {
  reg.exe delete $keys[$i] /f
  if (Test-Path "$bak\$i.reg") { reg.exe import "$bak\$i.reg" }
  reg.exe query $keys[$i] /s >> "$bak\after.txt"
}
Compare-Object (Get-Content "$bak\before.txt") (Get-Content "$bak\after.txt")
```

Пустой вывод `Compare-Object` означает точное восстановление. Папку `$bak` сохранить. Если оболочка продолжает вести себя по-старому, нужен выход из системы.

## 11. Linux

| Задача | Решение |
|---|---|
| Единственный экземпляр | Unix-сокет `$XDG_RUNTIME_DIR/flit/instance` (каталог 0700), тот же `Hello` + `Open` из `flit-proto` (пути Linux и так байты); вместо mutex — `flock` на `$XDG_RUNTIME_DIR/flit/instance.lock`; проверка `SO_PEERCRED` (uid). Сейчас `DbusInstance` — заглушка, всегда `Primary` |
| Интеграция с приложениями | первичный экспортирует `org.freedesktop.FileManager1` на сессионной шине, объект `/org/freedesktop/FileManager1`: `ShowFolders(as uris, s startup_id)` → `Open { paths }`; `ShowItems(as uris, s startup_id)` → `Open { select }`; `ShowItemProperties` → родитель + выделение. URI `file://` разбираются тем же `resolve` (percent-decoding в байты). `startup_id` → токен XDG activation или `_NET_STARTUP_ID` для фокуса, аналог `AllowSetForegroundWindow` |
| Владение именем шины | без `REPLACE_EXISTING`, если имя занято другим менеджером и Flit не выбран основным; файл активации `~/.local/share/dbus-1/services/org.freedesktop.FileManager1.service` (`Exec=flit --dbus`) пишется только при выборе Flit основным, с копией и откатом как в §8 |
| Ассоциация каталогов | `~/.local/share/applications/flit.desktop` (`Exec=flit %U`, `MimeType=inode/directory;`); `xdg-mime default flit.desktop inode/directory` (пишет `~/.config/mimeapps.list`); прежнее `xdg-mime query default inode/directory` сохраняется для отката |
| Кто чем пользуется | браузеры и Electron «Показать в папке» → `FileManager1.ShowItems` (запасной путь — `xdg-open` родителя); `xdg-open <каталог>` → ассоциация `inode/directory` |

## 12. Отклонения и открытые вопросы

1. `explorer.exe <аргументы>` при прямом вызове, по всей видимости, не перехватывается никак, кроме IFEO (отвергнут). Скрипты и программы, запускающие `explorer.exe /select,…`, продолжат открывать Explorer.
2. Windows 10 не проверялся; живая проба на Windows 11 не проводилась (§10).
3. `/n` сейчас означает новое окно, как в Explorer. Многие вызывающие передают `/n` по привычке, что противоречит цели «всегда вкладка». Варианты: игнорировать `/n` или вынести в настройку.
4. Регистрировать ли `Folder\shell\opennewwindow` и `opennewtab` (пункты контекстного меню).
5. Где жить фиктивному окну оболочки: в первичном (рекомендация) или в пересылающем процессе; постоянная регистрация вкладок в `IShellWindows`.
6. Переход на протокол Instance v2: признак происхождения из оболочки (§3.1) и, возможно, `Route.select: Vec`. Сделать до первого публичного выпуска, пока v1 не закреплён.
7. Что передаёт `%1` для Win+E и виртуальных папок (Главная, Библиотеки, OneDrive): выяснить пробой.
8. `file://host/share` не поддержан; по ассоциации `%U` на Linux приходят URI, их разбор общий.
9. Загрузка DLL в пересылающем процессе измерена (§5.4): после `/DELAYLOAD` — 28,5 мс против 24,1 мс у пустого процесса. Отдельный маленький exe-пересыльщик сэкономил бы оставшиеся 4–5 мс ценой усложнения регистрации и обновления; пока не нужен.
10. Повышенные экземпляры: суффикс `-admin` или запрет пересылки между уровнями целостности.
11. Сообщения `Standalone` и `VersionMismatch` сейчас уходят только в stderr GUI-процесса.
