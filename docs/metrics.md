## Capture mode

The script sets `FLIT_HIDDEN=1`: the window is created at -32000,-32000 with `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` and shown with `SW_SHOWNOACTIVATE`, so it never appears on screen, in the taskbar or in Alt+Tab, and never takes focus. It is still a normal DWM-composed flip-model swapchain presenting with sync interval 1, so frame period, vsync pacing, dropped frames and input-to-frame latency are measured on the same present path as a visible window (`refresh_from_display` stays true and the frame interval p50 matches the display period).

A truly windowless mode (no `ShowWindow`, an offscreen render target or a composition-free present) was rejected: without DWM composition there is no vsync, so frame intervals and dropped frames become meaningless and only CPU frame time would remain. What the hidden window cannot show: occlusion of a visible window by others, multi-monitor placement, and the cost of DWM composing a window that is actually on screen; those still need a manual run without `FLIT_HIDDEN`.
